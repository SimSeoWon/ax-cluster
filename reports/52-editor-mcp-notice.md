# 52 — 「에디터에 붙었나」를 세션이 스스로 안다 (`#374`)

**2026-09-06** · 신규 훅 1 · 테스트 35건 · `.33`·NS 라이브 · 커밋 `abe87a5`·`dc1f7ed`·`72960b8`

---

## 1. 결론부터

어제 `.33` 세션은 **한참 작업한 뒤에야** *"세션 시작할 때부터 unreal-mcp 연결이 실패한
상태였다"* 를 알았다. 이제 세션 시작에 한 줄이 뜬다:

    [에디터 MCP] 꺼짐 — 에디터가 안 떠 있다 (127.0.0.1:8000). 소스·빌드·로그 작업은 영향 없다.
                 애셋·BP·입력 매핑을 건드려야 하면 사람에게 에디터 기동을 요청하고
                 (임의로 켜지 않는다), 켜진 뒤 `/mcp reconnect unreal-mcp` 로 이 세션에 붙인다.

## 2. 🔴 함정 — 「포트 열림」이 「이 세션이 붙었다」가 아니다

MCP 는 **세션 시작에 한 번만** 붙고 자동 재시도가 없다. 그래서 **세션보다 늦게 켠 에디터에는
못 붙는다** — 어제가 정확히 그 경우였고, `netstat` 으로는 `LISTENING` 이라 멀쩡해 보였다.

이슈 원안은 「에디터 프로세스 기동 시각 vs 세션 시작 시각」 비교였다. 실제로 만들다 보니
**그 시각을 추정할 필요가 없었다** — 이 훅은 세션 시작에 **직접 돌기 때문에** 그때 재서
적어 두면 된다. 프로세스 시각 비교는 스냅샷이 없을 때만 쓰는 폴백으로 남겼다.

    off        포트 닫힘                          에디터가 안 떠 있다
    ok         지금 살아 있고 세션 시작에도 살아 있었다    붙었을 것이다
    stale      🔴 지금 살아 있는데 세션 시작엔 아니었다    이 세션은 못 붙었다 — `/mcp reconnect`
    gone       세션 시작엔 살아 있었는데 지금 닫혔다      도구는 목록에 남고 호출만 실패한다
    not_mcp    포트는 열렸는데 MCP 응답이 아니다         남이 그 포트를 잡고 있다
    unknown    열렸지만 세션 시작 기록이 없다           단정하지 않는다

## 4. 막지 않는다 · 켜 주지 않는다

에디터가 필요 없는 작업이 대부분이다(2026-09-05 실증 3라운드 전부). 고지만 하고, **기동은
사람의 결정**이다 — 원격 기동은 세션 0 경계로 기술적으로도 막혀 있고 `win-main-33.md` 가
*"원격 절차를 설계하지 마라"* 라고 적어 둔 자리다. 요청이 애셋·BP·입력 매핑을 건드릴 때
**요청자 세션이** 판정해 사람에게 **에디터 기동을** 요청하고, 켜지면 `/mcp reconnect` 로 붙는다
(`ax-request` SKILL §0.06 · §7) — 훅은 문장에서 애셋 여부를 가르지 않는다.

## 6. 측정이 잡은 것 둘 (둘 다 내가 만든 것)

**⑴ handshake 가 본문을 기다리다 오탐을 만들었다.** streamable-http 응답이 `text/event-stream`
이면 `read()` 가 서버가 끊을 때까지 블록한다 → 타임아웃 → `not_mcp`. **본문을 안 읽고**
상태줄과 Content-Type 으로 판정하도록 고쳤다.

**⑵ 테스트가 배달 표면에 `__pycache__` 를 만들었다.** `bundle.workshop_files` 가 `hooks/` 를
rglob 로 쓸어 담으므로 그대로 두면 `.pyc` 가 **요청자 기계로 배달된다**(`test_client_bundle` 이
그 바이트를 읽다 `UnicodeDecodeError` 로 죽어서 드러났다). 테스트와 훅 양쪽에
`sys.dont_write_bytecode = True` — 사람의 `.claude/hooks/` 도 더럽히지 않는다(배달 뒤 실측: 없음).

[주의] 소켓 테스트가 **5회 중 2회** 흔들렸다 — `accept()` 에 블록된 스레드가 있으면 `close()`
가 실제로 닫지 않는다. 6회 반복으로 확인하기 전에는 「통과」로 보였다.

## 7. 🔴 처방이 틀렸다 — 사용자가 잡았다 (같은 날 수정)

*"그럼 코드 변경해서 재빌드 할때 연결 끊어질꺼 아니야"* — 맞다. C++ 을 고치면 **에디터를 닫고
빌드하고 다시 켠다.** 즉 이 연결은 예외가 아니라 **하루에도 여러 번** 끊긴다. 그런데 내가 쓴
고지 문구는 그때마다 **「세션을 다시 열어 달라」**고만 말했다 — 맥락을 통째로 버리는 처방이다.

재보니 `claude` 에 재연결 명령이 있다 (2.1.263 바이너리 문자열 실측):

    /mcp reconnect <서버>  ·  /mcp reconnect all
    "..." isn't a recognized /mcp action. Try reconnect, enable, or disable.

문구를 바꿨다 — **`/mcp reconnect unreal-mcp` 가 먼저**이고 세션 재시작은 그것이 안 될 때의
차선이다. `gone`(에디터가 꺼졌다)에는 *"다시 켠 뒤에는 재연결이 필요하다 — 에디터만 켜면 붙지
않는다"* 를 넣었다. 리빌드 흐름의 정본은 이제 이것이다:

    에디터 종료 → 빌드 → 에디터 기동 → /mcp reconnect unreal-mcp

[주의] **원전 런북 §12-5 의 마지막 줄(*"세션 재시작"*)을 그대로 베낀 것이 출처다.** 원전이
쓰인 시점의 `claude` 에는 그 명령이 없었을 수 있는데, 나는 **지금 도구에 무엇이 있는지 재지
않고** 문장을 옮겼다. 원전은 「무엇을 해야 하나」의 정본이지 「지금 도구가 무엇을 할 수 있나」의
정본이 아니다.

## 8. 사용자가 선을 그었다 — 정상은 조용히, 요청은 사람에게

*"사람이 어차피 명시적으로 에디터 편집 작업을 시작할 때 체크하면 되는거 아니야?"* — 맞다.
실제 게이트는 요청 시점이다. 다만 세션 시작 고지를 아예 없애면 **「지금이 에디터 작업인가」를
내가 판정하는 자리**가 되살아난다(`~/CLAUDE.md` 「판단의 틈」이 지목한 그 형태). 그래서
**선을 옮겼다** (사용자 결정): `붙음`이면 **침묵**하고, 위험한 넷만 말한다.
[주의] 조용해도 스냅샷은 남긴다 — 뒤 턴의 판정 근거가 그것이다.

그리고 처방의 주어를 고쳤다 (사용자 지시: *"사람은 자리에 앉아있는거니까 대신 요청하면 될듯해.
에디터를 켜달라거나 / MCP를 다시 시작해달라거나"*). 🔴 **슬래시 명령은 세션이 칠 수 없다** —
`/mcp reconnect` 는 사람이 친다. 내가 SKILL 에 *"켜지면 제가 `/mcp reconnect` 로 붙이면
됩니다"* 라고 쓴 것은 **할 수 없는 일을 약속한 것**이었다. 문구를 전부 「사람에게 요청한다」로
바꿨다.

## 9. 🔴 그 대화가 결함을 하나 더 꺼냈다 — 리빌드 경로에서 「붙음」이라고 거짓말한다

사용자가 말한 리빌드 흐름을 코드로 따라가 보니:

    세션 시작 붙음(at_start=True) → 빌드하려고 에디터 닫음(gone) → 빌드 → 다시 켬
    → live=True · at_start=True → **판정 `ok` → "붙음"**   ← 🔴 거짓이다

에디터를 닫는 순간 이 세션의 연결은 **죽고 돌아오지 않는데**, 다시 켠 서버를 보고 「붙어 있다」고
말한다. **이 기능이 가장 자주 만나는 경로가 정확히 그것이다.** 고쳤다 — `gone` 을 본 세션은
`at_start` 를 내리므로 다시 켠 뒤의 정답은 `stale`(재연결 요청)이다.

[주의] 그 수정이 **소음을 하나 만들었고 테스트가 잡았다** — `gone` 다음 턴에 `off` 로 판정이
바뀌어 **같은 사실을 두 번** 말했다. 중복 판정을 「코드」가 아니라 **「부류」**(up · down ·
detached · …)로 바꿨다.

[중요] **둘 다 대화에서 나왔지 테스트에서 나오지 않았다.** 유닛 30건이 통과하는 동안 둘 다
살아 있었다 — 리포트 45 이후 반복되는 그 모양이다.
