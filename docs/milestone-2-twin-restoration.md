> 사용자 지시: **"플랜 문서 기존꺼 이전 마일스톤으로 기록하고 이게 지금 시작하는 다음
> 마일스톤이야. 일단 된거 안된거 구분하는거"**

## 왜 이 마일스톤인가

마일스톤 1 이 **파이프를 이었다.** 큐·브로커·검색·작업 루프가 돌고 층2/층3 게이트가 있다.
그런데 그 파이프에 흐르는 **정보를 만드는 능력이 없다.**

```
트윈을 쓰는 쪽 (검색)   ← 부분적으로 있다 (1,066 / 3,921줄)
트윈을 만드는 쪽 (합성) ← 🔴 0줄 (온톨로지 7,173 + MD 1,036 + 그래프 1,341)
```

**지금 트윈은 2026-08-08 12:56 에 받은 스냅샷이고 스스로 자라지 못한다.**
워크플로우가 코드를 새로 짜도 그 코드는 트윈에 들어가지 않는다. 시간이 갈수록
RAG 근거가 실제 코드베이스와 벌어진다 — **조용히, 에러 없이.**

## 진행 규칙 (마일스톤 1 의 실패에서)

1. **"완료" 는 영역 전체에만 쓴다.** 부분이면 분모를 같이 적는다
2. **조사 없이 라벨 붙이지 않는다** — "2단계"·"나중 문제" 로 미루기 전에 열어본다
3. **원본이 남긴 경고를 먼저 찾는다** — 독스트링·주석에 함정이 적혀 있는 경우가 있었다
4. **순서는 사용자가 정한다** — 임의로 하나 골라 파고들지 않는다
