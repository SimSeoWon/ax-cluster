## 3. 🔴 사용자 push 가 색인 정지를 드러냈다 (`#376`)

*"메인 브랜치에 작업 완료되어 코드 커밋했는데, 분석 시작하니?"* — 시작했고, **죽어 있었다.**

    19:43:04  · Sim/NS c5d2c6e7→d93e7c88
              [실패] fast-forward 실패 — 미러가 갈라졌다: 업데이트 중 c5d2c6e..d93e7c8
              Error downloading object: IA_Interact.uasset (346bd89): Smudge error

### 원인 — 몰랐던 게 아니라 **지속되지 않은** 것

`onboard.py:443 do_clone` 은 이 함정을 **이미 알고 주석까지** 달아 뒀다. 그런데 처방이
**클론 그 순간의 환경변수** 하나였다:

    env_extra={"GIT_LFS_SKIP_SMUDGE": "1"}

환경변수는 그 명령에만 듣고 **저장소 config 에 남지 않는다.** 그래서 이후 색인기가 도는 모든
`pull`/`checkout` 이 smudge 를 켠 채 돌았다. 실측: NS 미러의 `filter.lfs` **0건**.

[주의] **왜 이제 터졌나** — ModularStage 는 LFS 를 안 쓰고, NS 는 파이프라인 커밋이 전부
`.h`/`.cpp` 라 **미러 생성 이후 `.uasset` 을 건드린 첫 커밋이 이번**이었다.
[주의] 오브젝트가 없어서가 **아니다** — 서버에 정상 존재했고(`/var/lib/gitea/data/lfs/34/6b/…`
1,680B) `.33` 의 `git lfs push --dry-run` 도 올릴 것이 없었다. **사용자 push 는 완전했다.**

### 고친 것 ⑴⑵⑶ (`d749edf`)

    ⑴ 클론이 **config 로 남긴다** (filter.lfs.smudge/process/required)
    ⑵ probe 가 **그 config 를 본다** — 없으면 세 키를 이름으로, `--confirm` 이 **보정만** 한다
       [중요] 사용자 질문에 답이 있었다: *"LFS 를 받으려고 한 것인지 체크하는게 필요한거야?"* —
       아니다. **탐지가 아니라 선언 확인**이다. 받으려 한 것을 잡으면 워킹트리가 이미 반쯤 적용된 뒤다
    ⑶ 실패 라벨을 **재서** 붙인다 — `FETCH_HEAD..HEAD` 를 세고 0이면 「갈라졌다」고 하지 않는다

[중요] **ModularStage 미러에도 그 설정이 아예 없었다** — LFS 를 안 써서 안 터졌을 뿐이다. 둘 다 보정했다.
[주의] ⑷(더러워진 미러 자동 복구)는 **파괴적 명령의 자동화**라 사람 결정으로 남겼다.

## 4. 🔴 원전과 갈라진 자리 둘 — 화면이 통째로 비어 있었다 (`#378`)

*"어떠한 도큐먼트도 나오지 않는데 이거 버그일까?"* → 버그였다. 그리고 **NS 만이 아니라 모든
프로젝트에서 처음부터** 비어 있었다.

    화면이 보내는 것   POST /api/v1/search/vector {"query":" ","n_results":48}
    우리 응답          {"results": [], "count": 0, "note": "query 가 비었다"}

⑴ **빈 질의 거절** — 원전 서버는 질의를 검사하지 않는다(`search_routes.py:66,132`). 원전 화면은
**문서 전체 목록을 빈 질의로** 가져온다(`loadDocs`). [중요] **규칙이 틀린 게 아니라 자리가
틀렸다** — 같은 규칙이 클라이언트에 이미 있고(`client_mcp.tool_search_context`) 거기가 옳다.
서버는 **원전 화면이라는 다른 호출자**도 받는 자리였다.

⑵ **`n_results` 를 안 읽었다** — 원전 모델도 화면도 `n_results` 인데 우리는 **우리 클라이언트가
쓰는 `n`** 만 읽었다. 화면이 48을 보내도 **조용히 5로** 떨어졌다.

[주의] 사용자가 *"작업 컴퓨터가 인프라 마스터에게 질의할 때 양식을 먼저 확인해"* 라고 잡아 준
덕에 **세 계약이 다르다**는 것이 드러났다 — `.33`(태그 자동 부착 · 클라가 빈 질의 차단) ·
웹 UI(마운트로 스코프 · 빈 질의가 목록) · 원전 서버(검사 없음).

구현은 한 곳 다르다: 원전은 공백 임베딩의 최근접 이웃으로 목록을 흉내내는데 **우리 융합 검색은
공백이면 0건**이다(실측). 그래서 `routes.api_documents` 로 **결정적으로** 세웠다 — 화면이 읽는
필드는 넷뿐이라 순위가 필요 없다. 라이브 `count 48`. (`5150baf`)

[주의] **내가 화면 구조를 오인했다** — 처음엔 *"루트가 온톨로지 도메인 목록이라 NS 는 도메인이
0개여서 빈 것"* 이라고 답했다. 사용자: *"온톨로지 뷰어는 별도로 있는데?"* 맞다 — 루트는 **컨텍스트
서버**이고 온톨로지 뷰어는 `/index.html` 이다. 목록이 아니라 **화면을 안 읽고** 답한 것이다.
