## 2. [중요] `#256` — 산문이면 안 보였을 구멍 둘

완료 조건이 *"명령 단위로 적어라, 산문만 있으면 미완"* 이었다. 명령을 쓰려 하자 **실행 표면이
없는 자리**가 나왔다:

    onboard CLI 없음   `run()` 이 안내 문구로 *"python -m master.projects.onboard <name>
                       --confirm"* 을 돌려주는데 **그 명령이 존재하지 않았다** — `plan`·`run` 은
                       라이브러리뿐이라 파이썬 세션에서만 부를 수 있었다. **절차가 문서가 아니라
                       세션의 기억에 살았던 정확한 원인이다**
    role 을 못 준다    `logic.set_workshop` 엔 `role` 이 있는데 MCP 도구가 안 열어 뒀다 →
                       `requester`(사람의 기계 `.33`)를 문서화된 표면으로 등재할 수 없었다.
                       기본값(`worker`)에 기대면 **사람 기계에 파견이 간다**

런북이 낡는 것은 `test_runbook`(39건)이 막는다 — 적힌 `python -m X` 가 **실물로 존재하고 진입점이
있는가** · MCP 도구가 **적힌 인자를 받는가** · `spec.SERVER_STEPS` 가 전부 문서에 있는가 ·
단계마다 「안 됐으면」 줄이 있는가. **①이 없었다면 `onboard` 는 계속 없는 명령이었다.**

[주의] 테스트가 문서를 왜곡하지 않게 규칙을 정교화했다 — 줄바꿈·인용 표시(`>`)를 걷어내고 보고,
**절차 절과 기록 절을 가른다**(「드러난 구멍」 절에 명령을 요구하면 규칙이 문서를 망친다).

## 3. `#267` — 합성은 있었고 읽는 쪽만 없었다

`recipes_synthesizer`(원전 629줄 이식) 독스트링이 그 구멍을 **스스로 적어 뒀다**. 원전 주석은
호출 시점까지 못박았다: *"code-writer 는 작업 시작 직후에 호출해 step-by-step 가이드를
컨텍스트로 받는다."*

이식의 갈림길은 **경로 권위**였다. 원전은 `.claude/recipes/` 를 로컬에서 읽었지만(그 데몬이 UE
프로젝트 안에 살았다) 우리는 레시피가 **마스터 트윈**에 있고 요청자 기계엔 그 디렉토리가 없다 →
`signals`·`history` 와 같은 **대행 구조**(클라 MCP → 큐 → 마스터 파일).

## 4. [중요] 사용자 지적 셋이 설계를 고쳤다

**① *"URL에 왜 한글이 있어?"*** — 질의는 한글(*"미션 태스크 추가"*)인데 GET 쿼리에 넣었다.
저널이 퍼센트 인코딩으로 남고 **손으로 curl 하면 깨진다**(실측: raw 한글 GET →
`Invalid HTTP request`). 이 저장소 관례가 이미 본문이다(`POST /api/v1/search/combined`) →
**`POST /api/v1/recipes/search`**.

**② *"검색에 사용하는 태그를 한글로 하면 되는거 아니야?"*** — **이것이 근본이었다.**
라이브 런에서 신호는 한글인데 **합성된 레시피는 전부 영문**이라(원전 규칙 *"Output ENGLISH for
… tags"*) 한글 질의가 자기 레시피를 못 찾았다.

    종전  tags: [Mission, Task, Enum]                "미션 태스크 추가" → 0건
    지금  tags: [Mission, Task, Enum, 미션, 태스크]    "미션 태스크 추가" → score 10

태그는 **검색 색인**이므로 찾는 사람의 언어여야 한다. 한글은 **신호 원문에서 그대로** 뽑는다
(지어내면 없는 말로 색인된다). [주의] 한글↔영문 사전을 심지 않았다 — 이 저장소엔 시소러스·
`resolve_terms` 가 이미 있고 두 벌은 갈라진다.

**③ *"워커들이 작동하는 디렉토리는 어디야? … MCP를 추가 안했다는거야?"*** — 실측: 워커 루트에
`CLAUDE.md` 는 있고 **`.mcp.json` 은 없었다**(사양이 `worker: ()` 로 선언). 즉 **코드를 추론하는
자리에서 컨벤션을 읽을 수 없었다** — `#267` 의 루프가 반 바퀴만 돌았다. 사용자 결정
**「전부 열어 준다」** + **「호출 시점까지 적는다」**.

## 5. [중요] 선언만 바꿔선 동작이 안 바뀌었다

`spec.MCP_BY_ROLE["worker"]` 를 열고 배달했는데 **워커에 `.mcp.json` 이 안 갔다.** 막은 것이 둘:

    bundle.deliver     `if facts.role == "requester":` **하드코딩** → `spec.mcp_for(...)` 로
    PAYLOAD_BY_ROLE    워커 목록에 `client_mcp.py` 가 **없었다** → 폐포 둘을 넣었다
                       (옆 파일로 로드되는 `ontology_cache.py` 가 빠지면 조회가 조용히 죽는다)

**선언과 배선이 두 벌이면 이런 일이 조용히 난다.** 이제 한 곳(`mcp_for`)이 정한다.

## 6. κ.0 경계는 토큰이 지킨다 — 라이브 양방향

    워커 · find_recipes / get_anti_patterns   isError=false · 빈 상태는 사유로
    워커 · mark_not_a_class                   **403** "판단·쓰기는 마스터가 한다"

[중요] **도구를 여는 것과 권한은 다른 축이다.** MCP 를 전부 열어도 `auth.WORKER_SCOPE` 가 쓰기를
막는다 — κ.0(판단은 마스터, 워커는 실행+보고)은 토큰이 강제한다.

[주의] 그 403 문구가 역할을 **"requester" 로 박아** 뒀다 → 워커에서 **틀린 말**을 했다. 배달된
config 에서 읽고 모르면 말하지 않게 고쳤다.
[주의] `auth.py` 를 고친 뒤 **큐 재기동을 잊어** 첫 라이브가 403 이었다(§11.5 를 내가 어겼다).

## 7. 배달되던 안내가 「없는 서버」를 가리켰다

`code-writer.md` 가 `mcp__code-recipes__find_recipes` 를 부르라고 적어 뒀는데, `workshop/README`
는 그 MCP 서버를 **미이식**으로 적어 둔 채였다 — **에이전트에게 없는 도구를 시키고 있었다.**
`ax-client` 로 고치고 호출 시점을 두 곳에 못박았다:

    ax-infer SKILL §4.5   워커의 실제 지시서 — *"소스를 읽기 전에 관습을 먼저 묻는다"*
    워크숍 CLAUDE.md      도구 표를 실물로(조회 11) + [중요] 호출 시점

[주의] `ax-infer` §2 의 *"큐(8101)는 401 이 정상 — 토큰은 마스터에만 있다"* 도 **낡아 있었다**
(워커 역할 토큰이 배달된다) — 열린 것과 403 인 것을 갈라 적었다.

## 8. 여기서 배운 것

1. [중요] **문서를 명령으로 쓰면 없는 것이 드러난다.** `#256` 의 값은 문서가 아니라 그 과정에서
   나온 구멍 둘이었다. 산문으로 적었으면 둘 다 안 보였다.
2. [중요] **선언을 바꿨는데 동작이 안 바뀌는 것**이 가장 조용한 실패다. 선언과 배선이 두 벌이면
   테스트도 통과하고 배달도 「완료」로 보고한다 — 실물만 안 바뀐다.
3. [중요] **색인은 찾는 사람의 언어여야 한다.** 원전 규칙을 그대로 옮겼더니 검색이 죽었다.
   이식은 「같게 만드는 것」이 아니라 **같은 목적을 우리 위상에서 달성하는 것**이다.
4. [주의] **낡은 계약을 담은 테스트를 이번 세션에 세 번 갈아 썼다**(`test_it_never_deletes` ·
   *"둘 다 -1 이면 stale 아니다"* · *"워커는 못 받는다"*). 셋 다 결정이 바뀐 자리다. 갈아 쓸
   때마다 **왜 갈았는지를 그 자리에** 적었다 — 다음 사람이 되돌리지 않게.
5. [주의] **동결값은 사고를 막는 장치이지 결정을 막는 장치가 아니다.** payload 동결(`#262`)을
   결정으로 갱신하며 그 구분을 주석에 남겼다.
