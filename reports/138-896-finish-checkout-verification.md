# #896 — 마감 전환의 옛 main 노출 제거 검증

## 범위와 실제 운영 문제

사용자 선택은 로컬 서브 에이전트다. 마스터 `.57`의 `issue_flow.finish`가 원격 push 뒤
`switch main` → `merge --ff-only end`로 본 체크아웃을 바꾸면서 옛 main 파일을 잠시 놓는
경로를 고친다. 그 순간 타이머가 실제로 시작됐다는 실증은 없다. 워커나 `.33`에서 리뷰를
실행한 문제가 아니다.

운영 본 체크아웃은 `/home/sim/ax-cluster`, `issue/896`, 문서 커밋 `9166654`이며 깨끗하다.
코드·테스트 수정은 `/home/sim/ax-896-local`(기준 `fed2dc5`, detached)에만 미커밋으로 있다.
`9166654`는 PC 타입 명세 두 문서의 별도 승인 커밋이며, #896 코드 수정안은 배포하지 않았다.

## 수정과 이전 검증의 정정

- 기존 fast-forward 조상 검사·로컬/원격 main 일치 검사를 유지한다.
- 끝 커밋을 지정한 `switch -C main end` 한 번으로 전환한다. 옛 main 체크아웃을 거치지 않는다.
- 같은 로컬 저장소의 다른 worktree가 main을 점유하면 push 전에 명시 거절한다. 목록 조회
  실패도 거절한다. 다른 PC의 독립 클론을 조사하거나 바꾸는 기능이 아니다.
- Git 2.34.1에서 `branch -f`나 `switch -C`가 worktree 점유를 자동 거절할 것이라는 가정은
  실제 테스트로 틀린 것으로 확인했다. 이전 읽기 검토보다 실행 결과를 우선한다.
- 별도 worktree 점유는 테스트에서 만든 가상 조건이다. 현재 운영에서 main 점유를 발견한
  것이 아니며, 그 자체를 운영 장애나 마스터 작업 불가로 설명한 것은 잘못이었다.
- 이전 137/142 실패 중 2건은 전환 로그의 `ff` 기대값을 수정하지 않은 테스트 정비 누락이었다.
  나머지 3건은 가상 점유 조건이었다. 사용자 재개 승인 뒤 기대값과 명시 보호를 보완했다.

  상세 원인·해소는 미확인이고 해당 소스는 수정하지 않았다.

## 남은 상태

사용자는 기준에서도 동일한 이번 변경 밖 테스트 실패를 조사·차단 대상으로 삼지 말고
#896을 계속 진행하라고 결정했다. 이 실패를 운영 플로우의 결함이나 #896 진행 불가로
설명하지 않는다. 전체 통합 성공으로 보고하지는 않으며 기존 실패와 관련 검증을 구분한다.
T3는 검증·기록 완료로 정리했다. 사용자가 소스·테스트 및 이 보고서·인수인계서의 커밋과
배포를 승인했다. 검증된 결과를 issue/896에 커밋하고 마운트된 AXCluster 배달·검사를 수행한다.
서비스 반영은 ax-projects 재기동으로 확인한다. main 반영은 finish 미리보기·별도 승인 절차를
따른다. 커밋·배달·서비스의 실제 결과는 Redmine #896 후속 노트를 기준으로 확인한다.
점유 조회와 전환 사이 타 세션이 동시에 Git 상태를 바꾸는 동작은 단일 지휘 세션 규칙 밖이다.
