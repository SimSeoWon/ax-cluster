### 2.1 ① diff.patch 가 윈도우에서 CRLF 로 오염됐다 (진짜 버그)

`client/runtime/fix_flow.py:312` 의 `Path.write_text` 가 텍스트 모드라 윈도우에서만
줄바꿈을 CRLF 로 번역했다. 저장소 blob 은 LF 이므로 `git apply` 가 거절한다.

| | CR | LF | `git apply --check` |
|---|---|---|---|
| 고치기 전 (22:01) | 16 | 16 | 실패 |
| 고친 뒤 (배달 후) | **0** | 16 | **OK** |

[중요] **리눅스 유닛 테스트로는 영원히 못 잡는다** — 번역은 이 파일이 도는 윈도우에서만
일어난다. 그래서 회귀 방지를 **소스 자체**에 걸었다(바이트로 쓰는지 테스트가 확인한다).

### 2.2 ②③④ 적용 자리를 사람 체크아웃으로 되돌렸다 (설계)

옆 worktree 기본은 ⑴ 소스트리에 안 보이고 ⑵ git 이 같은 브랜치를 두 작업 폴더에 못 붙여
사람이 그 브랜치를 자기 폴더에서 열 수도 없고 ⑶ `Intermediate`/`Binaries` 가 없어 첫 빌드가
풀빌드라 확인이 실질적으로 불가능한 자리였다.

- `prepare`(신규 기본) — 깨끗하면 **이 체크아웃**에 `fix/<번호>`, 더러우면 **거절**하고 갈래를 말한다
- `release` — worktree 모드의 브랜치 점유를 푼다(미커밋이면 거절)
- 스킬 ⑤ 가 **서브에이전트를 보내기 전에** `path`·`branch`·`mode` 를 사람에게 말한다
- 옛 이름 `worktree` 는 **격리를 뜻한 채로** 별칭으로 남겼다 — 이름이 동작을 말해야 한다

### 2.3 새 테스트가 in-place 경로의 결함 둘을 더 잡았다

유닛이 아니라 **새 경로를 실제로 돌려서** 나왔다.

1. `.ax/`(도구 자기 산출물)를 「사람 작업」으로 세서 `prepare` 가 **영원히 거절**되던 것.
   요청자 체크아웃은 `.git/info/exclude` 로 가려져 있었지만 그 배선에 기대지 않고 코드가 집행한다.
2. `git add -A` 가 **사람 저장소에 `.ax/` 를 커밋**하던 것 — worktree 모드엔 없던 위험이다.
