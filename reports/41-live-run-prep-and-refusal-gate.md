## 2. `#331` 거절 게이트 — 통합자가 base 를 만들어 버렸다

### 발견

`.33` 절차서에 「base 브랜치 생성 + 골조 실물 커밋」 단계가 **없다**는 것을 찾다가, 그 부재를
통합자가 어떻게 다루는지 봤다. `integrate.py:822` 는 `git push origin HEAD:refs/heads/<durable>`
이고 **원격에 ref 가 없으면 이 push 가 브랜치를 만든다.** 그래서 요청자가 base 를 안 만들어도
통합자가 **골조 없는 `task/<W>/base` 를 만들어 버린다.**

`twin_base` 의 계약과 정면으로 부딪힌다 — *"브랜치를 만드는 것은 요청자다"* · *"골조 없는 base
에서 조각이 갈라지면 인터페이스 동결이 다시 약속으로만 남는다"*. 방어선은 `[주의]` note 한 줄
뿐이고 실행은 계속됐다.

### 사용자 결정 (2026-08-28) — fail-closed 거절

    durable 이 원격에 없다     → 거절. at_commit="" · 적용도 커밋도 push 도 없다 · ok=False
    브랜치는 있는데 못 쌓는다   → 종전대로 폴백 (자손 아님 · 대상 파일 접촉 · diff 실패)

호출부는 `ast` 로 셌다 — 6곳 전부 2-튜플 언패킹이라 `at=""` 센티널이 모양을 안 바꾼다
(`#321` 이 값을 치른 교훈: 모양이 바뀌는 변경은 파서로 찾는다).
