## 58.1 이 구간의 형태 — **결함이 결함을 불렀다**

리포트 `57` 이 남긴 것은 *"`#385` 실증을 재시도해야 하는데 `reverify` 를 못 쓴다"* 였다.
그 「못 쓴다」를 파고들자 **원전 대조가 두 개의 이식 누락을 드러냈고**, 둘 다 오늘 닫혔다.

    질문        "실패한 조각을 어떻게 되살리나"
      ↓ 원전 대조

      ↓ 사용자 지적

[중요] **둘 다 「만들기 전 3문」의 ①(원전에 있나)이 찾았다.** 내가 처음 제안한 것은
`requeue` 엔드포인트 신설이었고, 사용자도 *"아마 기존에는 이런 내용이 없었을꺼같아"* 라고
봤다. **둘 다 틀렸다** — 원전에 있었고, 우리가 안 옮겼을 뿐이다.

## 58.2 `#388` — 원전은 2026-05-10 에 이미 고쳤다

`~/AgentTest/mcp/master_orchestrator/verifier.py:55` 의 독스트링이 **우리의 종전 상태를
그대로 서술한다**:

    "이전엔 「마크다운 펜스/영어 prose/0줄」 만나자마자 reject(=terminal failed) 로 즉시
     종료 → **워커가 feedback 받아 고칠 기회조차 없었음.** 정책 전환: 모든 issue 는 기본
     **revise** … attempt_count >= max_attempts (기본 3) 도달 시에만 reject 로 escalate."

그리고 `verifier.py:396~432` 가 **우리 실패 케이스를 이름으로** 다룬다:
*"PSEUDO 있었는데 변경 없음 … 재시도 가능하면 revise, max 이상이면 reject."*

🔴 **배관은 이미 있었다 — 판정만 없었다.**

    models.py:36        `revise` → `needs_revision`             이식돼 있었다
    logic_claim.py:162  후보 = pending + needs_revision          이식돼 있었다
    🔴                  `needs_revision` 을 **만드는 코드가 0건**

**진짜 원인**: 원전엔 검문소가 둘인데(워커의 디스크 검증 = terminal · 검증 워커의 diff 검사
= revise), 우리 층1 은 마스터 `wcommit` 안에 있다 — **위치는 ①이고 하는 일은 ②다.** 그래서
①의 정책을 물려받았다. **검사를 앞으로 옮기면서 정책을 같이 안 옮긴 것이다.**

### 만든 것 — `master/work/revise.py`

    classify(issues, attempt)   pass / revise / reject · MAX_ATTEMPTS = 3 (원전 값)
    embed(...)                  피드백을 **파일 안에** 박아 커밋·push
    strip_feedback(text)        이전 블록을 걷는다 — 누적 방지

🔴 [중요] **피드백은 메시지가 아니라 파일 내용으로 간다.** 그래서 ⑴ 다른 기계가 집어도
지시가 따라가고, ⑵ 마스터가 「누구에게 뭘 말해줬는지」를 기억할 필요가 없다 — **git 이 나른다.**
[주의] **피드백을 못 실으면 revise 로 보내지 않는다** — 피드백 없는 재시도는 같은 실수를
반복하며 상한만 태운다.

### 원전과 의도적으로 갈린 둘

⑴ 피드백을 대상 파일 **전부**에 박는다(원전은 하나) — 워커가 `.h` 를 먼저 열어도 보이게.
⑵ 판정 자리가 `verify` 가 아니라 **`submit-fail`** 이다 — 우리 층1 은 커밋 **전**이라 그때
   상태가 `claimed` 이고 `verify_task` 는 `submitted` 만 받는다. `submit_fail` 은 이미 같은
   두 게이트(epoch fencing · `#318` 신원)를 갖고 있어 거기 갈래를 넣었다. **새 엔드포인트를
   만들면 그 게이트를 한 벌 더 짜야 하고, 그것이 조용히 갈라지는 것이 이 저장소가 물린 유형이다.**

## 58.3 `#389` — 같은 교훈이 세 줄 위에 있었다

사용자 지적: *"마스터 서버에 등록한 것을 기준으로 모두 설정 해야하지 않아?"*

    work 레코드 20필드   worker_mode **없음**
    autodispatch.py:387  fn(paths, limit=n, …, parallel=True)   mode 미전달
    infer.py:812         _MODE.current(mode)   ← mode="" 라 **조각마다** 전역을 읽는다

🔴 **같은 파일, 같은 호출, 세 줄 위**에 이미 이렇게 적혀 있었다(`#340`):

    "🔴 [중요] **병렬을 명시로 넘긴다** … 기본값에 의존하면 그 기본값이 바뀐 줄도 모른다."

모드는 그 교훈이 적용되지 않은 채였다. 고친 모양은 `distribution_mode`(원전에서 온
per-work 스탬프)와 **같은 결**이다:

    등재   register_work(…, worker_mode="")   요청자 지정 · 안 주면 **그때의 전역값** 스탬프
    레코드  work["worker_mode"]
    파견   autodispatch → run_many(mode=…)    **명시 전달**
    전역   「지금부터 등재되는 것의 기본값」    도는 work 은 안 흔들린다
