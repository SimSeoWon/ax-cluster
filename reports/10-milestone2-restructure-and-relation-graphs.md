## 1. 이 세션이 고친 가장 큰 것 — **목표를 문서 머리에 고정했다**

사용자가 프로젝트 목표를 두 줄로 확정했다:

1. **온톨로지 문서를 자동으로 작성한다** — 커밋마다 컨텍스트 문서 → 연관 클래스 관계 그래프
   → 검색용 BM25 → 최종적으로 **사용자의 수동 명령과 대화형으로 휴리스틱이 포함된** 온톨로지
2. **그 트윈 데이터를 코드 작성 에이전트에게** 관련된 것만 추출해 전달한다

그 서술이 내 이해를 **세 군데** 고쳤다.

### 1.1 시소러스를 대조표에서 통째로 빠뜨렸다

목표 ①에 들어 있는 산출물인데 내 분석에 없었다. 실체:

- **데이터**: object yaml 의 선택 필드 `aliases:`. 🔴 **LLM 이 만들지 않는다** — 사용자가
  `/manage-domain edit-item` 으로 넣거나 작업 요청에 `미션 시스템[UDPManager_Mission]` 처럼
  쓰면 그게 등록 신호다
- **왜 있나**: BM25 토크나이저가 `[A-Za-z0-9_]+|[가-힣]+` 리터럴 매칭이라 **"몬스터" 와
  `AMonster` 가 영원히 안 만난다.** 원래는 한국어 임베딩 우회책으로 시작했으나, 384차원 다국어
  모델은 저장 증가가 0 이어서 *"임베딩 교체의 대체재가 아니라 BM25/태그 채널의 리터럴 갭을
  메우는 별개 보완책"* 으로 재정의됐다
- **우리 데이터**: 🔴 **247 yaml 중 `aliases` 보유 0건**

## 2. 파이프라인 실측 — 태스크 경계는 계산 성격이다

`watch.py` 커밋 처리 순서:

```
커밋 → process_commit                 컨텍스트 MD + source_commit 스탬프 + 색인 upsert  🔴 LLM
     → update_dependency_graph        #include 그래프                                   LLM 0
     → class_graph.update_incremental 상속 그래프 (tree-sitter)                         LLM 0
     → sync_object_paths / [헤더변경시] sync_declared_contracts                          LLM 0
     → 시간 게이트(평일 10시 이후 첫 폴링) → ontology_refresh.run                       🔴 LLM
```

두 가지가 여기서 나왔다.

1. 🔴 **컨텍스트 MD 가 온톨로지 재합성의 신호원이다.** Phase η.8 이 dirty 플래그를 없애고,
   MD 의 `source_commit` 갱신 → `compute_stale_domains` 가 "저장값 ≠ 문서값" 으로 stale 판정
   하게 바꿨다. **컨텍스트 문서가 없으면 온톨로지는 자기가 낡은 줄 모른다.** 우리 색인기가
   남기는 스킵 사유 `"변화 없음 — 합성기 미이식"` 이 정확히 그 상태다
2. **LLM 을 쓰는 것만 시간 게이트 뒤에 있다** — *"event-based race 본질 해소"*

그래서 태스크를 **파일 이름이 아니라 계산 성격**으로 잘랐다: LLM 0(커밋 즉시) / LLM 자동
(게이트) / 사람·대화형 / 소비. 결과는 **대 2 · 중 8 · 소 32.**

### 5.1 🔴 원본 버그를 하나 찾아 고쳤다

`class_graph_parse.py:71` `_find_function_declarator` 가 재귀를 멈추지 않아 **중첩 클래스의
메서드가 바깥 클래스 소유로 기록된다.** AST 를 떠서 원인을 확인했다:

```
field_declaration
  └ class_specifier (FInner)
      └ field_declaration_list
          └ field_declaration → function_declarator (InnerOnly)   ← 여기까지 내려간다
```

`_extract_methods_from_body` 가 "직계 자식만 훑는다" 고 해도 declarator 탐색이 그 안까지
내려간다. 실측으로 `AMonster` 의 메서드 목록에 `InnerOnly` 가 들어왔다.

**왜 사소하지 않은가**: `methods` 테이블의 존재 이유가 **온톨로지 추출의 오탐 교차검증**이다.
그 표에 오탐이 섞이면 게이트가 반대로 작동한다. 중첩 스코프에서 하강을 멈추게 고쳤고,
중첩 클래스는 원래대로 자기 항목으로 잡힌다(테스트가 양쪽 확인).

### 5.2 원본과 의도적으로 다르게 한 것

| | 바꾼 것 | 왜 |
|---|---|---|
| ⑴ | 위치 `<Name>/class_graph.db`·`dependency_graph.db` | §5.5.2 — 경로는 상수가 아니라 함수다 |
| ⑵ | **fail-closed** — 파서 부재·git 실패·소스 0건이 전부 예외 | 원본은 로그 한 줄 남기고 `return`/빈 dict → "없다" 와 "실패했다" 가 구분되지 않는다. **우리가 반복해 온 실패 모양** |
| ⑶ | `Source/` 경계를 pathspec **+ 접두 두 겹** | 테스트가 한 겹뿐인 것을 잡았다. 인자를 한 번 잘못 넘기면 `Content/`(워킹트리 93%)가 조용히 들어온다 |
| ⑷ | 파싱 건수(`parsed`)와 DB 건수(`classes`) 분리 | `name` 이 PK라 같은 이름이 덮인다. 실측 1,847 vs 1,806 = **이름 중복 41건**. 온톨로지 귀속 모호성 신호라 보고한다 |
| ⑸ | 질의를 SQL 로 | 원본은 매 호출마다 그래프 전체를 dict 로 적재하고, `get_dependencies` 는 의존마다 전체 키를 다시 훑어 **O(N·M)** 이다. `dst_base` 인덱스로 한 번의 질의로 끝냈다 (의미 동일) |
| + | 마이그레이션(레거시 JSON·ALTER) 미이식 | 대신 `domains`·`class_ontology` 를 **처음부터 만들어** 중 1.3·소 2.2.2 가 스키마를 안 고치게 했다 |
| + | 동시성 PRAGMA 명시 (WAL·busy_timeout) | 색인기와 검색기가 **별개 프로세스**다 — 세대 포인터 사고와 같은 계열 |

### 5.3 ⚠️ 소비자가 알아야 하는 한계 — 역방향은 basename 근사

`included_by` 는 경로가 아니라 **파일명으로 역산**한다. `#include "Foo.h"` 의 경로는 UBT 가
모듈 include 디렉토리로 해석하므로 그 정보 없이는 어느 `Foo.h` 인지 알 수 없고, 원본은 이름이
같으면 전부 연결한다.

**옮기기 전에 범위를 측정했다**: ModularStage 소스 1,662개 중 **basename 이 겹치는 헤더 9종**
(각 2개). 작지만 0 이 아니라 `BuildStats.ambiguous_basenames` 로 보고하고 요약 문자열에도
띄운다. 소 2.x 영향도 질의는 **이 숫자를 근거로 결과를 의심할 수 있어야 한다.** 테스트가 그
한계를 재현까지 해 둔다(같은 이름 두 헤더가 같은 참조자 집합을 갖는 것을 확인).

### 5.4 도메인 자동 추론 — 원인이 옮겨왔을 뿐이다

`class_graph.db` 는 생겼지만 그 안의 **`class_ontology` 가 0건**이라 질의→도메인 추론은
그대로 빈 결과다(그 테이블은 중 1.3 이 채운다). **"DB 가 없다" 에서 "DB 는 있고 분류가
없다" 로 옮겨온 것**이고, 검색은 여전히 설계된 성능이 아니다.

|---|---|
| 모델 기본 `context_length` | **262144 (256K)** — 요청이 `num_ctx` 를 안 주면 이 전제로 잡는다 |
| 컨텍스트 체크포인트 | **최대 32개 × 62.8 MiB ≈ 2.0 GB** |
| 프롬프트 캐시 저장 | 요청마다 **72.25 MiB** |
| 보드 여유 | **2.2 GB** (15.2GB 중 12.9GB 가 모델·UMA 점유) |
| swap | **zram 8GB — 압축 RAM.** 물러설 물리 저장소가 없다 |

→ 체크포인트가 쌓이며 여유를 소진 → zram 스래싱 → 커널 정지. **OOM 킬러가 도는 대신
그냥 멈췄다** — 이전 부팅 로그에 `oom-kill`·`panic` 이 **없다.**

노드 쪽 완화는 **이미 켜져 있었다** — `OLLAMA_KV_CACHE_TYPE=q4_0`, `OLLAMA_FLASH_ATTENTION=1`,
`OLLAMA_MAX_LOADED_MODELS=1`. 그것만으로 부족했다.

**그래서 상한을 요청에서 건다**: `call_broker(..., num_ctx=...)` 신설, 합성은
`SYNTH_NUM_CTX = 4096`(프롬프트 ~1,500토큰 + 출력 ~800토큰에 넉넉). 코드 생성 경로는
기본값을 안 넣어 동작이 바뀌지 않는다.

### 클라이언트 쪽에서 같이 드러난 결함

배치가 `TimeoutError` 로 **통째 크래시**했다. `call_broker` 가 `HTTPError`/`URLError` 만
잡는데 **소켓 읽기 타임아웃은 `TimeoutError`(OSError 계열)** 로 올라온다. 내가 문서에 적은
불변식 *"한 그룹이 죽었다고 배치를 멈추지 않는다"* 가 **가장 흔한 실패 모드에서 정확히
깨져 있었다.** 수정 `18dc657` — `OSError` 와 `(ValueError, TypeError)` 를 `GenerateError` 로
포섭한다(후자는 응답이 JSON 이 아니거나 스트림이 끊긴 경우).

### 하지 않은 것

§6.6 에 원격 전원 재투입 경로가 있지만 **손대지 않았다.**

- 정상 종료(`sudo -n systemctl poweroff`)는 **SSH 를 타므로 지금 쓸 수 없다**
- 스마트 콘센트 조작은 문서가 *"지금은 사람이 콘센트를 조작해야 한다"* 라고 적어 뒀고,
  *"자동 전원 차단은 신중할 것 — 살아 있는 노드를 오판해 끊으면 더티 종료"* 경고가 있다

→ **복구는 사람의 판단이다.** 콘센트 재투입 후 §6.6 실측대로 약 30초에 SSH, 그 뒤 자동으로
추론 노드로 복귀한다.

### 대책 (적용)

0. 🔴 **`num_ctx=4096` 을 요청에 건다** — 위에서 확정한 진짜 원인에 대한 직접 대응
1. **프롬프트 본문 상한 8,000 → 4,000자.** 원본이 8,000이었던 이유는 **상용 API** 를
   불렀기 때문이다 — 우리 하드웨어 전제가 다르다. `--content-limit` 로 올릴 수 있게 두되
   *"올리기 전에 노드 여유를 확인할 것"* 을 상수 주석에 박았다
2. **대안 모델 상수** `FALLBACK_MODEL = qwen2.5-coder:14b`(rtx3060 핀) + CLI `--fallback`.
   품질은 35B 가 낫지만 **사실 게이트가 걸러 주므로** 나쁜 문서가 통과하지는 않는다 —
   통과율이 떨어질 뿐이다
3. `--model` / `--content-limit` 을 CLI 로 노출 — 노드 상태에 맞춰 조정 가능하게

### 남는 교훈

🔴 **"원본 값을 그대로 옮긴다" 가 항상 안전하지는 않다.** 프롬프트 크기·타임아웃처럼
**실행 환경 전제가 박힌 상수**는 우리 하드웨어로 다시 재야 한다. 파싱 규칙·정규식처럼
환경 무관한 값과는 성격이 다르다 — 이식할 때 이 둘을 갈라야 한다.

🔴 **그리고 원인을 추측으로 닫지 말 것.** 나는 처음에 "프롬프트가 길어서" 라고 적었다.
보드가 살아난 뒤 이전 부팅 로그를 읽으니 **`num_ctx` 미지정 → 256K 전제 KV 할당** 이라는
다른 원인이 나왔다. 프롬프트를 줄이는 것만으로는 재발했을 것이다 — **노드가 죽으면 그
노드의 로그를 반드시 읽는다.**

## 9. 중 1.2 완료 · 중 1.3 착수 · 검색 재설계 (2026-08-08 밤 ~ 08-09)

### 9.1 트윈이 처음으로 자랐다

색인기에 관계 그래프 증분과 컨텍스트 MD 합성을 물렸다. 미러의 실제 커밋 diff 로 검증:

    ✅ 9efbfc1a→bc4b38f4 · 소스 3건 · 그래프 상속 3·의존 18 · 합성 3건 · 재색인 961건

`source_commit` 이 3개 문서 전부에 스탬프됐고(중 1.3 stale 판정의 원천), *"소스 변경이
색인에 반영된다"* 가 **처음으로 참**이 됐다.

🔴 **유실을 삼키지 않는다.** 원본 판별 기준이 *"skip 후 워터마크가 전진하느냐"* 인데, 이
지점 뒤에서 워터마크가 전진하므로 문서를 못 만들면 그 커밋의 변경은 **영구 유실**이다.
그래서 유실 그룹을 **이름과 사유로** 로그에 찍는다.

### 9.5 사용자가 확정한 성격 — **문서는 지도지 정답이 아니다**

> *"모든 문서는 소스코드라는 원천을 바탕으로 참조하거나 찾거나 이해하기 쉽도록 하는
> 지도·네비게이션 역할이다."*

원본 `rag-system.md` 첫 절과 같은 말인데 **내가 읽고도 일관되게 적용하지 못했다.** 판단

없는 것을 있다고 하면 **틀린 자리로 보내므로** 사실 게이트는 남는다.

🔴 **그 연장선에서 구멍이 하나 드러났다** — 추론 노드는 파일을 못 읽는데(§2) 코드 생성
