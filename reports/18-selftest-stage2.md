## §3 [중요] 착수 전 정독이 뒤집은 전제 둘

`#141` 노트는 이 칸을 *"가드가 막으니 ⓐ/ⓑ/ⓒ 중 결정이 필요하다"* 로 적어 뒀다. 원전 416줄과
우리 595줄, 그리고 **가드에 직접 입력을 넣어** 잰 결과 그 전제가 둘 다 틀렸다.

### §3.1 가드는 이 경로에 아예 없다

`run_live` 의 git 은 **한 줄도 마스터에서 돌지 않는다** — 전부 `_ssh` 로 작업장에서 돈다.
그리고 작업장 `.43` 클론에는 **pre-push 훅이 없고** `origin` 이 곧장 Gitea 다(실측).

    가드 직접 입력 실측 (rc 가 아니라 **누가 막았는지**를 봤다 — 리포트 16 §2 의 교훈)
    selftest/<slug>       push    [중요] 거부   ← 마스터에서 밀 때만 해당
    attempt/selftest-…/…  push    [완료] rc=0
    도달 불가 attempt/*   삭제    [중요] 거부   ← 원전 8단계 cleanup 이 하는 일
    도달 불가 task/<id>   삭제    [중요] 거부

[중요] **그래서 ⓐ/ⓑ/ⓒ 는 브랜치명 문제가 아니라 「잔재를 어떻게 하나」 문제였고, 그것은 하니스를
Flow Y(마스터가 push)로 옮길 때 비로소 생긴다.** 지금 형태의 2단계에는 가드 결정이 **필요 없다.**
[주의] 리포트 14 §15 가 *"증명 안 한 것: 마스터가 쓰기 주체"* 라고 적어 둔 칸이 정확히 이것이다.

### §3.2 ⑤ C.7 통합 머지는 상류가 미이식이다

원전 7b 는 *"실 leader 가 쓰는 `_integrate_push_durables` 를 **그대로** 태워"* 통합 정합성을
본다(머지만·push 없음). 그 헬퍼는 `executor_review_finalize.py`(중 2.1 `#135`)에 있고
**우리 코퍼스 grep 0건 = 미이식**이다. [중요] 여기서 머지를 **새로 쓰면 검사의 뜻이 바뀐다** —
*"실 leader 경로가 합류시킨다"* 가 아니라 *"셀프테스트가 자기 머지를 돌렸다"* 가 된다.
따라서 **`#135` 가 상류**이고 오늘 옮기지 않는다. [주의] per-task durable 을 올리는
`verify_and_merge`(push 함)와는 **다른 능력**이다 — 이름이 비슷하다고 대응으로 보지 말 것.

## §5 [중요] 원전 판정식을 글자로 옮기면 우리 큐에서 거짓말을 한다

원전은 *"등록 워커(대부분 stale)가 아니라 **실제 폴링 중**(`last_seen` 있음) 워커 수"* 로
병렬 가능성을 판정한다. 그대로 옮기고 실 큐에 대 보면:

    등록 4명 · 원전식(존재로 셈) = **4명**
      192.168.0.2            경과 167시간
      192.168.0.43           경과 170시간
      probe-HV0I6DL          경과 194시간
      selftest-192.168.0.43  경과  66시간
    [중요] 실제 폴링 데몬 = **0개** (`worker/` 는 README 뿐)

원인은 전제 차이다 — 원전은 상주 워커 데몬이 heartbeat 를 계속 찍고, 우리
`worker_last_seen` 은 claim/heartbeat 때 찍히고 **만료되지 않는다**(`logic_claim.py`).
리포트 16 §12.7 의 σ.9.0 `mtime` 과 **같은 부류**다: 기제는 옮기고 신호원은 다시 고른다.

[중요] **임계값은 발명하지 않고 이 저장소에 이미 있는 것을 재사용했다** — `reclaim.py` 의
`_VERIFY_CAPABLE_RECENT_SEC = 300`("최근 접촉"에 대한 우리 답). 새 숫자를 만들면 같은 뜻의
임계값이 둘이 되어 조용히 갈라진다.

**그것이 바꾼 판정**: 원전식이면 폴링 4명 → `polling >= 2` 성립 → **병렬 단정이 켜진다** →
직렬로 도는 하니스가 매번 실패 → **없는 결함**. 신선도로 세면 0명 → skip(로그) → 정상.

## §7 라이브 런 — [중요] **첫 판이 통과했는데, 그 통과가 아무것도 증명하지 않았다**

첫 실행은 **30개 단정 전부 통과 · ok=True · 흔적 0** 이었다. 그런데 결과를 보다가 알아챘다:

    by_backend = {'probe_lane_a': {'ok': 1, 'total': 1}, 'probe_lane_b': {'ok': 1, 'total': 1}}

이 집계는 **하니스 자신의 로컬 dict**(`backend_of`)로 센 것이다. [중요] *"내가 아는 값을 내가 안다"*
일 뿐 **`force_backend` 가 큐까지 갔는지는 아무것도 말하지 않는다.** NONCE 증명이 값을 주입하지
않고 디스크에서 읽게 만든 것과 **정확히 같은 논리**인데, 내가 그 논리를 옆 칸에 적어 놓고
밟았다 — 리포트 13 §14 *"주입은 계약을 재고 실물을 재지 않는다"* 의 **다섯 번째** 재발이다.

큐가 돌려준 claim 응답으로 판정하는 단정을 넣고 다시 돌렸더니 **실패**했다:

    [중요] force_backend 가 **큐를 거쳐** claim 응답으로 돌아왔다
       기대={0:probe_lane_a, 1:probe_lane_b}  실측={0: None, 1: None}
