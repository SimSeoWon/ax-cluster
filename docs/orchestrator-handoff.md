## 1. 🔴 `.2` 는 이제 codex 지휘자로 **쓴다** — 종전 금지는 폐기됐다

종전 기록(*"`.2` 에 codex 모드를 보내지 않는다"*)은 **SSH 가 직접 `codex exec` 를 미는 경로**
를 전제한 것이다. 그 경로는 여전히 죽지만, 파견이 더 이상 그 경로로 가지 않는다:

    SSH 직접 실행               세션 0   ❌ 0xC0000142
    SSH → schtasks /run (/IT)   세션 1   ✅ 설치본 0.153.4 가 그대로 돈다

`runner.uses_session1(facts, mode)` = **Windows AND codex** 일 때 `run_worker_session1` 로
간다. 마스터는 `job.json`(데이터만: `task_id`·`files`·`approvals`·`timeout`)을 쓰고
`schtasks /run` 으로 **부탁만** 한다. 명령 문자열은 워커의 런처가 만든다.
🔴 **그래서 패치 codex·Rust 툴체인·아티팩트 배포·CI 빌더·저장소 분리가 전부 불필요하다.**

**운영 조건 하나**: `AxConductor_NS` 는 `로그온 모드: 대화형만`이고 `.2` 에 **자동 로그온이
없다**(`AutoAdminLogon` 키 부재, 실측). 🔴 **재부팅하면 janus 로 로그인해야 세션 1 이 생긴다.**
안 하면 `.2` 가 조용히 파견에서 빠진다. RDP(3389)로도 된다.

## 2. 오늘 닫은 것 — 파견이 「묻는 자리」가 되어 있었다

`.2` 조각 2건이 각각 시도 3회를 태우고 죽었는데, **원인은 코드가 아니라 내가 `#402` 에서
심은 문서 규약**이었다. codex 는 `AGENTS.md` 의 *"고치기 전에 동의를 받는다"* 를 따라
`RESULT: BLOCKED` 했다 — 대화 세션용 규칙인데 파견 세션엔 물어볼 사람이 없다.

고친 자리는 **문서가 아니라 지시문**이다(근거 넷은 리포트 64 §4):

    runner.INSTRUCTION / session1_conductor.INSTRUCTION  ← 같은 글자, 핀으로 고정
      "This message is dispatched work from the AX master, not a human chat: …"
      "Do not ask for approval, do not propose a plan for review, … implement the bodies now."

배달물(`AGENTS.md`)의 워커 한정 예외도 함께 나갔다(`103d64e`) — 그쪽은 보조다.
