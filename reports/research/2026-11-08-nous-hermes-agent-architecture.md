# Nous Research Hermes Agent 아키텍처 및 스킬 학습 루프 분석

> 2026-11-08 · Antigravity 리서치 보고서  
> 대상: Nous Research `hermes-agent` (GitHub: `NousResearch/hermes-agent`)  
> 목적: Hermes Agent의 스킬 생성/학습 루프 메커니즘 분석 및 AX 클러스터(작업 리포트·주간 분석·스케줄) 적용성 검토

---

## 1. 개요 및 핵심 철학

**Hermes Agent**는 Nous Research에서 개발한 오픈소스 자율형 에이전트 프레임워크입니다.  
기존의 일회성 API 래퍼나 단일 세션 코딩 코파일럿과 달리, 세션이 끝나도 사라지지 않는 **폐쇄형 학습 루프(Closed Learning Loop)**를 내장하여 에이전트가 경험을 축적하고 스스로 스킬과 메모리를 확장하도록 설계되었습니다.

---

## 2. 핵심 아키텍처 구성

1. **코어 런타임 (Core Runtime)**:
   - 에이전트 메인 루프, 모델 라우팅, 메시징 게이트웨이(CLI, Telegram 등), 도구 런타임 주관.
2. **점진적 노출 (Progressive Disclosure)**:
   - 시스템 프롬프트에는 스킬의 이름과 한 줄 요약만 담긴 가벼운 인덱스(`skills_list()`, 약 3k 토큰)만 로드.
   - 대화 중 해당 스킬이 필요해지면 `skill_view(name)` 도구로 상세 본문을 동적으로 불러와 컨텍스트 토큰 낭비 방지.
3. **MLOps 및 파인튜닝 파이프라인 연결**:
   - 단순히 개인 생산성 도구에 그치지 않고, 에이전트의 도구 호출 궤적(Trajectories)을 압축·수집하여 ShareGPT 포맷으로 내보내거나 강화학습(RL, Atropos) 파이프라인으로 연결해 모델 자체를 사후 학습시키는 데이터 생성기로도 작동.

---

## 3. 스킬 학습 메커니즘 (`/learn` 플로우)

Hermes Agent의 가장 큰 차별점은 대화와 작업 경험을 표준화된 실행 규약(`SKILL.md`)으로 변환하는 자동화 루프입니다.

### (1) 입력 소스
- 대화 내역: *"방금 우리가 디버깅하고 테스트했던 절차 정리해줘"*
- 외부 소스: 코드 디렉터리, 공식 문서 URL, 복사/붙여넣기한 메모 등

### (2) 스킬 작성 엄격 규약 (Hardline Authoring Standards)
생성된 스킬이 모델의 라우팅 정확도를 떨어뜨리거나 컨텍스트를 과도하게 차지하지 않도록 엄격한 규격을 강제합니다:
- **Frontmatter 메타데이터**:
  - 이름: 소문자 하이픈 연결 (`kebab-case`)
  - `description`: **60자 이하 단일 문장**, 마침표로 종결 (시스템 프롬프트의 스킬 인덱스가 60자에서 절단하기 때문)
  - `author`: 호스트 사용자명이 아닌 리터럴 `Hermes`로 강제
- **레이아웃**:
  - 단일 작업: 단일 `SKILL.md`
  - 복잡한 지식: 린(lean) 인덱스 문서 + 챕터별 세부 참조 문서 구조

### (3) 저장 및 승인 게이트
- 생성된 스킬은 `skill_manage` 도구를 통해 로컬 스킬 디렉터리(`~/.hermes/skills/`)에 영구 저장.
- 사용자 설정에 따라 파일 쓰기 전 사람의 승인(Approval Gate)을 거침.

## 4. AX 클러스터와의 비교 및 시사점

| 비교 항목 | Nous Research Hermes Agent | AX 클러스터 (현행) |
|---|---|---|
| **스킬 포맷** | `~/.hermes/skills/*/SKILL.md` | `~/.agents/skills/*/SKILL.md` (완전 호환) |
| **스킬 로드 방식** | Progressive Disclosure (`skill_view`) | 마스터/워커 시작 시 디렉터리 인덱싱 후 호출 |
| **스킬 생성 주체** | 에이전트 자동/반자동 (`/learn`) | 사람이 지침 정립 또는 일감(#N) 개발 후 등록 |
| **기록 축적** | 궤적(Trajectory) 로그, 메모리 | 작업 리포트(`reports/N-*.md`), Redmine 노트 |
| **사람 게이트** | 파일 쓰기 승인 게이트 | ⑺ 전진·finalize·커밋/푸시의 명시적 2중 게이트 |

---

## 5. AX 클러스터 적용 아이디어: 주간 분석 & 스킬 자동화 파이프라인

사용자가 제안한 **「주간 작업 플로우 분석 및 스케줄 추가」**와 결합할 경우 다음과 같은 고도화가 가능합니다:

1. **리포트 기반 패턴 추출 (일간/주간 타이머)**:
   - `ax-followup.timer`나 주간 cron 작업으로 최근 완료된 작업 리포트(`reports/N-*.md`)와 Redmine 마감 노트를 스캔.
   - 반복되는 트러블슈팅(예: 특정 빌드 에러 해결 루틴, 특정 서비스 재기동 순서 등)이나 자주 쓰인 복합 명령 패턴을 감지.
2. **스킬 초안 자동 제안 (`draft-skill`)**:
   - 감지된 패턴을 바탕으로 `~/.agents/skills/<새스킬>/SKILL.md` 초안을 작성.
   - 곧바로 반영하지 않고, Redmine의 `아이디어` 마일스톤 일감으로 등록하거나 대화 세션에 *"최근 3회 이상 반복된 작업 패턴을 스킬로 묶었습니다. 검토하시겠습니까?"* 형태로 사람에게 제안.
3. **승인 후 정식 편입**:
   - 사용자가 승인하면 스킬 저장소에 정식 반영되어 워커 및 마스터 세션이 즉시 재사용.
