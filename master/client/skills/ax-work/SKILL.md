# ax-work — 마스터 작업 수행 (워커 측 계약)

> 마스터가 생성해 배달한다. **손으로 고치지 말 것** — 다음 배달에 덮인다.
> 정본: `~/ax-cluster/master/client/skills/ax-work/SKILL.md` (마스터)

## 0. [중요] 이 스킬의 전제 (사용자 확정 2026-08-09 · ⑤는 2026-09-02)

1. **이 머신에 프로젝트 소스 클론이 있다.** 없으면 작업하지 않는다
2. **마스터의 작업 요청은 네가 1차로 받고, 네가 오케스트레이션한다.** 마스터는 컨텍스트·큐·
   라우팅만 댄다 — 실행 판단은 이 머신의 몫이다
3. [중요] **컨텍스트 문서·도메인 규범은 어디까지나 참조다. 모든 판단의 기준은 소스 파일이다**
4. 🔴 **대상 파일의 본문은 네가 직접 쓴다** (사용자 결정 2026-10-10, `#784`) — 분산 작업에서는
   본문 초안을 `agy`·`codex exec`·로컬 LLM 에 맡기지 않는다. 위임은 **조사가 필요할 때만**
   `agy` 에 한다(§4). [주의] 종전 「대량 생성은 `codex` → `agy` → 로컬 순으로 위임」(2026-09-06)은
   이 스킬(지휘자)에서는 폐기됐다 — 마스터 `lane` 모드의 레인 순서(`work/lanes.py`)와는 별개다
5. 🔴 **너는 git 을 만지지 않는다** (정본 ⑸, 사용자 확정 2026-09-02). 브랜치는 마스터가
   배정해 **이미 체크아웃해 뒀고**, 커밋·push 는 마스터가 결정적으로 한다. 원전도 그랬다 —
   워커 데몬의 `git_ops.py` 가 git 을 하고 LLM 은 **파일 본문만** 썼다. 커밋 경계를 LLM
   판단에 맡기면 무엇이 들어갔는지 아무도 모른다

## 1. 먼저 `./.ax/config.json` 을 읽는다

작업은 **체크아웃 디렉토리에서 시작한다.** 설정은 항상 같은 상대경로에 있다:

    ./.ax/config.json        이 머신·프로젝트 설정 (마스터가 생성)
    ./.ax/work/<task_id>/    작업 부산물은 전부 여기 (git 이 무시한다)

거기서 읽을 것: `master.services`(포트) · `checkout.path` · `capabilities` · `backends`.

[중요] **없으면 추측하지 말고 멈춘다.** 경로를 역산하거나 다른 머신의 값을 가져다 쓰지 말 것 —
그렇게 복사된 설정이 죽은 채 남아 있던 사고가 실제로 있었다(`.mcp.json` 이 다른 머신의
사용자 경로를 가리키고 있었다). 마스터에 배달을 요청한다.

## 2. [중요] 일감은 배달되어 온다 — 큐를 직접 부르지 않는다

    마스터: claim → 서브 브랜치 배정·체크아웃 → 너를 실행
    너:     골조 주석 읽기 → 작업 → **파일 본문 쓰기** → `RESULT: DONE`
    마스터: 되읽어 층1 검증 → **통과분만 커밋·push** → 큐에 submit

🔴 **네가 읽을 것은 배정된 브랜치의 대상 파일 그 자체다** (정본 ⑸, 2026-09-02):

    <대상 `.h`>    `[DOC]`·`[STATE]`·`[BIND]` 주석 = 설계·계약. **선언은 동결이다**
    <대상 `.cpp`>  `[PSEUDO]` 주석 = 채울 본문의 작업 지시서

🔴 **대상이 `.py` 면** (`kind: code` 프로젝트 · `#695`) 한 파일이 두 역할을 다 한다:

    `# [DOC]`     설계·계약 — 그대로 둔다
    `# [PSEUDO]`  채울 자리 — 본문을 쓰고 **그 줄을 지운다**. 옆의 `raise NotImplementedError`
                  도 본문으로 **바꾼다** (남기면 층1 이 「스텁 그대로」로 막는다)
    함수·메서드·클래스의 **이름·인자·기본값·반환 표기는 동결이다** — 바꾸거나 지우면 층1 이
    막는다. 새 비공개 도우미 함수를 **추가**하는 것은 된다.
    [중요] **서버를 띄우지 말고, 프로그램·테스트를 실행하지 말 것** — 검증은 요청자(`.33`)의
    통합에서 한다. 새 서드파티 import 를 넣지 않는다.

[중요] **별도 지시서 파일은 없다** — `manifest.md` 는 2026-09-02 에 걷었다. 이유는 셋이고
전부 실측이다: ⑴ 등재 시점엔 골조가 없어 그 문서가 자기 안에서 모순됐다 ⑵ `.ax/` 는 git
관리 밖이라 `add -f` 억지 커밋이 필요했다 ⑶ 조각 간 관계를 아는 것은 골조뿐이다.
**그래서 지시가 소스 주석으로 갔다** — git 이 이미 나르고 `main` 까지 산다.

[중요] **큐(8101)·MCP(8103)를 부르려 하지 말 것.** 이 머신에는 **베어러 토큰이 없다** — 실측
2026-08-09: 두 워커 모두 `8101/api/v1/health` 가 **401**, AX MCP 등록 **0건**. 401 을 받고
"인증을 설정해야겠다" 며 우회로를 찾지 말고, **골조 주석과 소스 파일로** 한다.
정말 부족하면 `RESULT: BLOCKED` 로 무엇이 없었는지 적는다.

이유: 토큰을 워커에 복사하지 않기로 했다. 리스 하트비트도 마스터가 대신 친다 — 너는
**작업에만** 집중하면 된다.

[중요] **능력을 부풀리지 말 것.** `./.ax/config.json` 의 `capabilities` 에 없는 일을 "되겠지" 로
시도하지 않는다. 특히 `ue5` 가 없으면 **층3 검증은 이 머신에서 불가능하다** — 되는 척하지
말고 그렇게 적는다.

## 3. [중요] 주석은 지도다 — 판단은 소스로 한다

골조의 `[DOC]` 주석에는 설계 의도와 조각 간 연결이 적혀 있다. 그건
**어디를 볼지 알려주는 것**이지 사실의 원천이 아니다.

    지도(`[DOC]`)로  →  어느 파일·어느 클래스인지 좁힌다
    그 다음 반드시   →  Read 로 그 소스 파일을 직접 읽는다

**실측된 이유**(2026-08-09): 규범만 주고 로컬 모델에 코드를 시켰더니 실재 멤버 4/4 를 쓰고
invariant 도 지켰지만, `CurrentStep`(실제는 `Step`) · `EMissionTaskExecutorState`(실제는
`EMissionExecutorState`) 처럼 **한 글자 차이로 지어낸 이름**이 남았다. 정확한 철자는
**헤더에만 있다.** 너는 파일을 읽을 수 있으니 그 오류를 낼 이유가 없다.

- 시그니처·멤버명·enum 값은 **선언부를 열어 확인**한다
- 규범(invariant)과 소스가 어긋나면 **소스가 이긴다.** 어긋난 사실을 제출물에 적는다
- 골조가 *"규범 grounding 없이 진행된다"* 라고 적어 뒀으면 그대로 믿고, **소스를 더 읽어** 메운다

## 4. 위임하고 검증한다 (모토: 무료=대량 생산, 상용/너=검증)

`./.ax/config.json` 의 `backends` 가 이 머신에서 쓸 수 있는 것을 말해 준다.
🔴 [중요] **경로로 직접 연다 — 검색으로 찾지 않는다** (`#783`). `.ax/` 와 이 스킬이 있는
`.agents/` 는 git 제외(`.git/info/exclude`)라서 `rg`·`git ls-files` 같은 도구는 **목록에 안 낸다**
(실측 2026-10-10: `rg --files --hidden -g '.agents/skills/ax-work/SKILL.md'` 가 exit 1 → 지휘자가
「찾지 못했다」며 BLOCKED). 이 스킬은 `.agents/skills/ax-work/SKILL.md`, 설정은 `.ax/config.json` 이다.

🔴 **본문은 네가 직접 쓴다 — 본문 초안은 위임하지 않는다** (§0④, `#784`). 아래 표의 위임은 **조사**용이다.
시도한 위임이 실패했을 때의 규칙은 아래 「위임이 실패하면」이다.
**조사·분석 위임은 네가 필요하다고 볼 때만 한다** (`#764` 2026-10-09 · 사용자 결정 2026-10-10 으로 완화, `#780`).
너는 체크아웃을 직접 읽는다 — **대상 파일을 읽고 고치는 일은 직접 한다.** 위임하지 않은 것은 실패가 아니다
(아래 「위임이 실패하면」은 **시도한** 위임에만 걸린다).
[주의] **파일 크기는 위임 사유가 아니다** — 너에게도 agy 에게도 글자 상한이 없다(실측 2026-10-10: agy 가
`--add-dir` 1M자 파일의 중간·끝 표지를 정확히 읽었다, 16K~1M 5/5). 실측 `#777`(`.43`): 몇 줄 수정에 agy 를
두 번 불렀고 두 번째는 6분을 넘겼다.

| 백엔드 | 쓰는 자리 |
|---|---|
| **`agy`** (`backends.agy` 가 true 일 때) | **소스 조사·분석·요약** — 관련 클래스·호출 관계·선언부 정리(필요할 때만 · 대상 파일 수정은 직접). **본문 초안은 맡기지 않는다**(`#784`). [중요] **`--add-dir` 로 파일을 쥐여줄 것** — 웹에서 찾으라고 시키면 출처를 지어낸다(실측). `-p` 는 **프롬프트 직전**에 둔다 |
| **너** | 오케스트레이션 · 소스 대조 · **본문 작성** · 위임 결과 검증 |

`agy` 호출 모양 — 자료 사본과 지시서는 **`.agy-work/in/`**, 응답 봉투는 **`.agy-work/out/<번호>.json`**
(마스터가 비운 채로 미리 세워 둔다 · 저장소를 통째로 주지 않는다). 직접 호출(리눅스 등 `VIA_LAUNCHER` 가 없을 때) 예:

    D="$(pwd)/.agy-work/in/1"     # 체크아웃 루트에서 — 체크아웃 절대 경로 + /.agy-work/in/<n>
    timeout 300 agy --dangerously-skip-permissions --output-format json --add-dir "$D" -p "Read BRIEF.md in the added directory and follow it exactly. Return the result as your response. Do not create or modify files." > .agy-work/out/1.json

🔴 [중요] **`--add-dir` 는 절대 경로다** — agy 는 상대 경로를 *"must be an absolute path"* 로 거부하고
BRIEF 없이 돈다(실측 `#777`). 자료와 `BRIEF.md` 는 `.agy-work/in/<n>/` 에 두고 그 절대 경로를 넘긴다.
🔴 [중요] **직접 호출은 한 번에 5분이 상한이다** — `timeout 300` 으로 감싼다. 시간 초과(종료 코드 124)는
아래 「위임이 실패하면」의 실패다. 아래 중계 대기도 5분이며 그것은 **`VIA_LAUNCHER` 가 있을 때만** 쓴다.

[주의] **`.ax/` 아래에 쓰지 않는다** — Windows 샌드박스는 그 아래 쓰기를 거부한다(실측 2026-10-09). `.agy-work/` 는
git 이 무시한다(`.git/info/exclude`).

🔴 [중요] **`.agy-work/VIA_LAUNCHER` 가 있으면 agy 를 직접 부르지 않는다** (Windows 세션 1 · 사용자 결정 2026-10-09 ⓑ).
그 경로에서는 샌드박스 안의 agy 가 홈(`C:\Users\…\.gemini`) 쓰기 거부로 죽는다(실측). 대신 **런처에 요청한다**:

1. `.agy-work/in/<n>/` 에 자료 사본과 `BRIEF.md` 를 쓴다 (`<n>` 은 `1`, `2` … — 영문·숫자·`-`·`_` 만)
2. **다 쓴 뒤** 빈 파일 `.agy-work/in/<n>.go` 를 만든다 — 런처가 그것을 보고 샌드박스 밖에서 agy 를 돈다
3. `.agy-work/out/<n>.done` 이 생길 때까지 **짧은 명령으로 반복해** 기다린다(한 번에 60초 이하 · 최대 5분 — 런처도 5분에 agy 를 죽이고 종료 코드 124 를 쓴다).
   PowerShell 예: `$t=0; while (-not (Test-Path .agy-work/out/1.done) -and $t -lt 55) { Start-Sleep 5; $t+=5 }`
4. `out/<n>.done` 의 값이 agy 종료 코드다. `out/<n>.json` 이 응답 봉투, `out/<n>.err` 가 stderr 끝부분이다
   — 응답 파일을 따로 저장할 필요가 없다(이미 `out/` 에 있고 마스터가 회수한다)

🔴 [중요] **위임이 실패하면 다음 레인, 다 실패하면 멈춘다 — `RESULT: BLOCKED`** (사용자 결정 2026-10-10, `#774`).
네가 **시도한** 위임(agy · `codex exec` · 로컬 브로커)이 실패하면 — 종료 코드(`done`)가 0 이 아니거나,
5분 안에 안 오거나, 응답이 비었거나 쓸 수 없으면 — 그 조사를 **다른 활성 백엔드**로 다시 맡겨도 된다
(본문 초안은 애초에 위임하지 않는다 — §0④, `#784`). **시도한 백엔드가 모두 실패하면 그 일을
네가 직접 하지 않는다** — 원응답 파일은 `.agy-work/out/` 에 그대로 두고, 백엔드마다 종료 코드·오류를 적은 뒤
마지막 줄을 `RESULT: BLOCKED` 로 끝낸다. 어떤 경우에도 실패한 일을 직접 구현해 덮지 않는다.
[주의] `backends` 에 없거나 false 인 백엔드에 **위임하지 않은 것은 실패가 아니다**(건너뛴다).
10-09 `#764` 의 「멈추지 않는다」를 뒤집었다 — 실패를 직접 구현으로 덮으면 위임 경로 고장이 성공으로
보였다(`.43` agy 3/3 실패가 그렇게 묻혔다).

🔴 [중요] **응답은 반드시 `.agy-work/out/` 에 파일로 남긴다** (사용자 결정 2026-10-09, `#764`). 마스터가 조각을 마칠 때
그 폴더를 `~/ax-state/delegations/<work_id>/<task_id>/` 로 회수하고, 워커의 `.agy-work/` 는 지운다
— 파일로 안 남기면 「agy 가 무엇을 답했나」를 아무도 다시 볼 수 없다. 두 번째 호출은 `2.json` 이다.

- 지시 내용은 `BRIEF.md` **파일**에 쓴다 — 명령줄에 한글·백틱을 싣지 않는다(Windows 콘솔 CP949 · 셸 치환)
- 지시서에 「주장마다 `src/경로:줄번호` 를 링크 없이 단다 · 확인 못 한 것은 「확인 불가」」를 넣는다
- 응답은 JSON 봉투다 — `response` 가 본문. `status` 가 `ERROR` 여도 agy 가 스스로 재시도해 끝냈을 수 있다
  (실측 2026-10-09, 503 용량 부족) — 본문이 비었는지·잘렸는지 네가 본다
- 인용 몇 개를 원본과 대조한 뒤에만 그 결과로 판단한다

🔴 [중요] **무엇을 위임했는지 제출물에 적는다** (§6) — 백엔드 · 무엇을 · 어떻게 검증했나. 마스터는
codex 지휘자의 명령 실행 기록에서 `agy`·`codex exec`·브로커 호출을 따로 세어 조각 기록에 남긴다.

[중요] **위임 결과의 "완료" 를 믿지 말고 산출물을 확인한다.** `agy` 가 `status:"SUCCESS"` 를
반환하면서 파일을 안 쓴 사건이 있다. 파일이 생겼는지, 내용이 맞는지 **네가 본다.**

[중요] **결정적 게이트가 LLM 판단보다 우선한다.** 컴파일·테스트·린트가 있으면 그것이 최종 판정이고,
"모델이 괜찮다고 했다" 는 근거가 아니다.

## 5. 파일을 어디에 쓰나

| 산출물 | 위치 |
|---|---|
| **코드 변경** | 체크아웃 안, **이미 체크아웃된 브랜치 위에서.** 브랜치를 바꾸지 않는다 |
| 로그·중간물 | `./.ax/work/<task_id>/` — git 이 무시한다 |
| 그 밖 | **아무 데도 쓰지 않는다** |

🔴 [중요] **git 명령을 하나도 실행하지 않는다** (정본 ⑸, 2026-09-02).
`status`·`diff` 같은 조회조차 필요 없다 — 마스터가 트리를 세워 뒀고 되읽어 검증한다.

    add · commit · push · checkout · branch · reset · clean · rebase · stash
    → **전부 마스터의 일이다.** 하나라도 실행하면 계약 위반이다.

[주의] 특히 `reset --hard`·`clean` 은 마스터가 **작업 시작 전에 이미** 돌렸다. 네가 다시
돌리면 네가 방금 쓴 본문이 사라진다.

특히 **`git clean` 은 절대 부르지 않는다.** 미추적 파일을 통과시키는 더티 체크의 전제가
그것이다. 그리고 사람이 편집 중인 미커밋 파일이 있을 수 있다 — `.uasset` 은 바이너리라
날리면 복구할 수 없다.

### [중요] 더티 판정은 **등록된 소스 경계**를 따른다

    Unreal: config.yaml의 source.roots/exclude (없으면 Source/), 확장자 제한 없음
    code:   등록 소스 루트·제외·확장자 경계
    index_only: 파견 대상 아님
    경계 안 추적 변경 → BLOCKED (rename은 이전·새 경로 모두 검사)
    경계 밖 추적 변경 → 막지 않는다

이유: `.uproject`·`.slnx` 는 **UE5/VS 가 프로젝트를 열기만 해도 다시 쓰는 머신 지역 파일**이다
(실측: `.uproject` 의 diff 는 `EngineAssociation` GUID → `"5.8"`). 그걸 감시하면 게이트가
**항상 빨간불**이 되고, 항상 빨간 게이트는 게이트가 아니다. 기존 Unreal 기본값은
`Source/`다. 플러그인 프로젝트는 등록된 소스 루트를 쓴다. Unreal 더티 검사는 그 루트 안의
모든 추적 파일을 보호하므로 색인 확장자로 범위를 좁히지 않는다.

[주의] 대신 이것을 지킨다: 범위 밖 파일을 **네가 고치지 않는다.**

[중요] 마스터도 **같은 범위**로 파견 대상을 고른다. 네가 더 넓게 보고 거부하면 *마스터는 보냈는데
워커는 거절하는* 왕복만 생긴다 — 실측 2026-08-09에 실제로 그렇게 한 번 헛돌았다.

### 🔴 [중요] 시작 자세와 종료 자세 — **둘 다 네 일이 아니다** (정본 ⑸, 2026-09-02)

    시작:  마스터가 이미 했다 — fetch --all → reset --hard → clean -fd
           → checkout -B task/<work>/<task> <골조 커밋>
    너:    **대상 파일 본문만 쓴다**
    끝:    마스터가 한다 — 되읽기 → 층1 → add(명시 목록) → commit → push --force-with-lease
           → main 복귀 → 큐에 submit

[주의] 종전에는 이 절이 워커에게 `checkout -b attempt/...` 와 `push` 를 시켰다. 그 계층은
`#327`(2026-08-27)에 걷혔고, 정본 ⑸ 는 **워커가 자기 서브 브랜치에 커밋**하는 것이지만 그
git 연산의 **주체는 마스터**다(원전도 데몬의 `git_ops.py` 가 했다).

[중요] **그래도 남는 규칙 하나**: 체크아웃된 브랜치에서 **나오지 마라.** 실측 2026-08-09:
시험 파견 후 `.43` 이 작업 브랜치에 남아 다음 작업이 무관한 이전 시도 위에서 가지를 쳤다.
`main` 복귀도 마스터가 하므로 **네가 `checkout` 을 부를 이유가 아예 없다.**

## 6. 제출 — [중요] 마지막 한 줄이 계약이다

작업이 끝나면 **파일을 저장한 상태로** 두고, 출력의 **마지막 비어 있지 않은 줄**을 정확히
이렇게 낸다:

    RESULT: DONE

못 끝냈으면 `RESULT: BLOCKED` 이고, **그 위에 왜인지 적는다.**

🔴 [중요] **`ATTEMPT`/`HEAD` 를 내지 않는다** (정본 ⑸, 2026-09-02) — 커밋을 만드는 것은
마스터이므로 너에게는 알려 줄 sha 가 없다. 지어내면 그 자리에서 막힌다.

[중요] **판정은 마커가 아니라 디스크다.** 마스터가 대상 파일을 되읽어 층1(휘발 태그 잔재 ·
`[FEEDBACK]` 잔재 · 마크다운 펜스 · 선언 동결 위반)을 돌리고, **통과분만 커밋한다.**
그래서 산문으로 "성공적으로 완료했습니다" 라고 써도 성공이 아니고, 반대로 마커를 냈는데
`[PSEUDO]` 가 남아 있으면 **커밋 자체가 안 생긴다.**

[중요] 마커는 여전히 **fail-closed** 다 — 없거나·마지막 줄이 아니거나·철자가 다르면
BLOCKED 다. 거짓 완료가 큐에 쌓이면 다음 태스크의 `depends_on` 이 잘못 풀린다.

제출물(마커 위 본문)에 **반드시** 담을 것:

- 무엇을 바꿨나 (파일·브랜치)
- **소스로 확인한 것** — 어떤 선언부를 읽고 무엇을 맞췄나
- 규범과 소스가 어긋난 지점이 있었으면 그 사실
- 위임한 것이 있으면 **무엇을 어디에 맡겼고 어떻게 검증했나**
- 결정적 게이트(빌드·테스트)를 돌렸으면 그 **원문 판정**. [중요] 요약하지 말 것 —
  `ssh` 종료 코드는 **양방향으로 못 믿는다**(빌드 실패에 0, 테스트 성공에 1이 나온 실측이 있다).
  로그의 판정 문자열이 근거다

## 7. 막혔을 때

[중요] **막혔을 때도 `RESULT: BLOCKED` 를 내고 끝낸다.** 조용히 멈추면 마스터는 타임아웃까지
기다리다 같은 판정을 내리는데, 그 사이 시간과 리스를 버린다.

- **설정이 없다** → 배달이 안 된 것이다. `BLOCKED` + 없는 경로를 적는다. 추측 금지
- **대상 파일에 `[DOC]`·`[PSEUDO]` 가 없다** → 골조가 덜 만들어진 것이다. `BLOCKED` +
  어느 파일에 무엇이 없는지. [중요] **지시가 없는데 지어내지 않는다**
- **체크아웃이 낡아 보인다** → 🔴 **네가 고치지 않는다.** 브랜치를 세운 것은 마스터다.
  `BLOCKED` + 무엇이 어긋나 보이는지 적는다
- **능력이 모자란다**(UE5 없음 등) → 되는 척하지 말고 `BLOCKED` + 무엇이 없는지
- **소스와 지시가 모순** → 소스가 이긴다. 모순을 보고한다
- **401 이 돌아온다** → 정상이다(§2). 우회로를 찾지 말 것
