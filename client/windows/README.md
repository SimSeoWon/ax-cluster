# `client/windows/` — 윈도우에서만 의미 있는 **스크립트**

Windows Codex 원격 실행: [`docs/windows-codex-remote.md`](../../docs/windows-codex-remote.md).
`workspace-write`·`windows.sandbox="unelevated"`·네트워크 허용과 `/IT /RL LIMITED` 런처를 함께 쓴다.
“세션 1”은 로그인 사용자 세션이지 고정 SessionId가 아니다. 실제 apply_patch 수정과 결과 회수까지 확인한다.

    client/runtime/            OS 무관 파이썬 (데몬 본체 등) — 로직은 전부 여기
    client/windows/            윈도우에서만 의미 있는 스크립트 (빌드 등)
    client/init/residency.py   등록 **명령 조립** — 파이썬이라 윈도우 없이 테스트된다

## 🔴 [중요] 로직을 여기 넣지 않는다

**이 저장소에는 윈도우에서 도는 테스트가 없다.** 테스트(`master/test_*.py` 와 `tests/`)는 전부
마스터(리눅스)의 파이썬이다. 그래서 `.bat`/`.ps1` 안에 판단이 들어가면 **구조적으로 검증 불가**가 된다 —
리눅스에서 할 수 있는 것은 *"이 문자열이 들어 있나"* 뿐이다.

실측 2026-09-12: 등록 로직을 `.bat` 으로 새로 썼다가 폐기했다. 같은 자리에 이미
`client/init/residency.py` (`#255`)가 있었고 그쪽이 나았다 — 명령을 **문자열로 돌려주는 순수
함수**라 마스터에서 유닛으로 잡힌다:

    check("schtasks /create /f (멱등)", "/create /f" in c, c)
    check("[주의] 대화형 전용(/it)", "/it" in c, c)

그리고 그 파일에는 **실측으로 산 지식**이 주석에 박혀 있다 — `/tr` 안쪽 인용은 `\"` 로
이스케이프해야 하고(안 하면 *"잘못된 인수/옵션"*), `pythonw` 는 PATH 에 없어 절대경로를
**재야** 하며(버전 디렉토리라 박으면 업그레이드에 깨진다), 인용이 **세 겹**(bash → ssh → cmd)
이라 `for /f` 로 짜면 깨진다. 새로 쓰면 이것을 전부 다시 산다.

## 여기 놓을 것 — 예: 빌드 스크립트

윈도우 워커 하나를 빌더로 쓸 때의 스크립트가 여기 온다. [주의] **지금은 없다** — 데몬이
파이썬이고 `.2` 에 `py 3.10.6` 이 있어 빌드할 것이 없다. 원전이 exe 12종을 만든 것은
*"팀원 PC 에 파이썬이 없다"* 는 전제 때문이었고, 우리 배달은 소스를 scp + sha256 로 나른다.

🔴 [중요] **빌드 산출물을 git 에 커밋하지 않는다** (`#403`). `codex.exe` 가 284MB 였다 —
git 은 잊지 않으므로 한 번 커밋하면 저장소가 영구히 그만큼 커진다(지금 `.git` 전체가 51MB,
추적 중 최대 파일이 364KB 다). 그리고 **빌드 산출물을 워커가 push 하게 하지 않는다**(워커가 자기 서브 브랜치에 소스 조각을
push 하는 것은 정본 ⑸ 이고 별개다) — `WORKER_SCOPE` 가
쓰기를 403 으로 막고 `pre-push` 훅이 ref 를 제한하는 경계(판단은 마스터, 워커는 실행+보고)가
뚫린다. 모양은 이것이다:

    워커가 빌드 → scp 로 마스터 회수 → 마스터가 해시 검증 → 마스터가 게시
    git 에는 **매니페스트만** (소스 커밋 · 툴체인 버전 · sha256)

통과 조건은 *"어느 빌더에서 만들어도 같은 해시가 나오는가"* 다 — 그래야 한 PC 에 종속되지 않는다.
