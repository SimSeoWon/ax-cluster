## 3. 교착의 구조 — 왜 공지가 영원히 안 갔나

`merge_status` 가 `ready_for_review` 로 뒤집히며, 그 flip 에 Redmine 이슈 생성이 달려 있다.

    워커 커밋 → **submitted** → (통합자가 verify) → 공지
                                  └ 통합은 사람 승인 대기 → 공지 안 감 → 승인 못 함

`[work-ready]` 0건, Redmine 0건. **성공할수록 통보가 안 가는** 상태였다
(실패한 조각만 terminal 이 되므로 전 조각 실패에서만 참이 된다 — `#338` 이 같은 뿌리다).

### 6.1 조각의 짝이 갈리면 산출물이 통째로 버려진다

    태스크 target   Source/NS/Interaction/NSInteractable.h

    커밋            `.h` 무변경 → 스테이징 0 → "no changes added to commit" → rc=1

Public↔Private 교차)는 **이미 있었지만** 호출부가 옛 `distribute` 경로 한 곳뿐이었다.

→ `decompose.complete_pairs()` 신설. 후보는 **골조 커밋이 건드린 파일만**(`main...<base>`

### 6.3 [주의] 내가 지역화된 메시지에 판정을 걸었다

ⓑ 첫 구현이 `"nothing to commit"` 영어 문구를 봤다. **이 환경의 git 은 한국어로 답한다** —
*"커밋할 사항 없음, 작업 폴더 깨끗함"*. 테스트가 잡았다. 이제 `commit_command` 가 빈 커밋을
관용해(`|| true` · 윈도우 `|| ver >nul`) `rev-parse` 를 항상 돌리고, 판정은 **`HEAD == base`**
하나다 — 메시지를 안 읽는다.
