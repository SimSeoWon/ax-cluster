# 80. 실패 work 종결·세션1 재시도 수정과 회귀 검증

2026-10-01 · 관련 Redmine `#701`, `#695` · 기준 HEAD `6001207`.

## 요청과 범위

사용자가 두 결함 수정을 승인했다. 커밋·push·배포는 이번 변경에 대해 승인받지 않았다.
`#695` 전체 완료나 서브모듈 검수 worktree 설계까지 승인받은 것으로 넓히지 않는다.
원전 `AgentTest`의 큐 lifecycle·cleanup·워커 종결 처리를 참조했다. 원전은 수정하지 않았다.

## 작성한 변경 — 미검증·미배포

- `#695`: 기존 `.ax/session1/<task_id>` 결과를 덮거나 지우지 않고 시도별 UUID 하위
  디렉터리에 job과 결과를 분리한다. 런처는 기존·신규 두 경로를 읽으며, 신규 완료 마커는
  `request_id`를 기록한다. 마스터는 다른 시도의 마커를 성공 결과로 회수하지 않는다.
- `#701`: 전 조각이 종결됐을 때 현재 라운드의 실패는 `rejected`, 실제 취소는 `cancelled`,
  성공과 `no_work`는 기존 `ready_for_review`로 분류한다. 재시도 대기는 종결하지 않는다.
  태스크 verified 이력·워커 브랜치를 삭제하지 않으며 사람의 통합·전진·main 게이트를 실행하지 않는다.
- 통보 실패만으로 성공 결과를 자동 취소하지 않는다. 오류와 사람 판단 필요 여부를 work에
  저장하고 요청자 훅에 표시한다. 실패 종결 통보는 전진 요청과 구별한다.
- 부팅 복구도 같은 판정을 사용하도록 작성했다. 따라서 배포·서비스 재시작 전 과거
  `ready_for_review` 작업에 대한 영향 확인이 필요하다. 이번 턴은 운영 큐를 변경하지 않았다.

## 첫 검증 결과 — 통과 주장 불가

명령 둘 모두 `rc=1`. 실제 SSH·Codex·운영 큐를 사용하지 않는 임시 환경 테스트다.

1. `.venv/bin/python master/test_failed_work_terminal.py`
   - 11개 전부 `setUp`에서 오류. `logic._try_create_work_issue_async`가 없다는
     `AttributeError`이며 제품 로직 테스트까지 도달하지 않았다.
   - 읽기 조사: `register_work`가 실제 호출하는 seam은 `logic._create_work_issue_async`다.
2. `.venv/bin/python master/test_runner.py`
   - 신규 시도 분리 테스트에서 `FileNotFoundError`로 중단.
   - 가짜 write는 checkout 상대 경로를 임시 디렉터리에 저장하지만, 가짜 read는 마스터가
     보내는 `C:\\trunk\\NS\\...` 절대 Windows 경로를 그대로 Linux Path에 붙였다.
     따라서 결과 파일 조회 전에 테스트 경로 변환이 필요하다.
   - 기존 테스트 결과를 별도 집계하지 못했으며 파일 전체 통과로 기록하지 않는다.

공용 규칙 §1.1에 따라 실패 후 코드·테스트를 추가 수정하지 않고 변경분을 보존하고 멈췄다.
원인 조사는 읽기만 수행했다. 신규 실패 통보 테스트의 기대 문구도 작성된 본문과 일치하는지
재개 때 대조해야 한다. 다음은 테스트 준비 코드 수정 승인 후 재실행이며, 제품 코드가
정상이라는 결론은 그 이후에만 낼 수 있다.

통보 실패 영속화·회복·중복 방지와 훅 렌더링을 검증해야 한다.

## 재개 후 결과

사용자가 테스트 준비 수정·재검증과 통과 뒤 커밋·push·배포를 승인했다. 위 두 준비 오류와
실패 통보 기대 문구를 고쳤다. 신규 종결 테스트 11/11, runner 143/143 통과.
회귀도 완료 훅 13/13, projects 63/63, bundle 394/394, submit gates 26/26,
task data 10/10, revise 52/52와 rounds(실패 0) 통과했다.

단, `test_nowork.py`의 실제 취소 통보 검증 2건이 실패했다. 실제 취소가 있는 work를
`cancelled`로 종결하는 새 코드에 대해 테스트는 예전 리뷰 통보 제목 「일부 미완성」과
본문 「취소된 파일」 절을 기대한다. `no_work` 정상 완료 검증은 모두 통과했다.
새 계약에 맞춰 기존 취소 테스트의 기대를 바꾸되 취소 파일·사유 노출도 함께 보존할지
사용자 판단을 받은 뒤 재개해야 한다. 실패 후 추가 코드 수정 없이 멈췄으며 커밋·push·배포는
실행하지 않았다. 기존 승인 범위는 성공 검증 후 커밋·push·배포이며 실패를 무시하는 승인이 아니다.

## 최종 로컬 검증·배포 승인

사용자가 기존 취소 테스트 계약 갱신과 취소 파일·사유 보존을 승인했다. 통보 포착기는
종결 제목도 받도록 바꾸고, 종결 통보는 취소된 파일과 사유를 명시한다.
최종 재검증은 10개 파일 모두 `rc=0`: 종결 11/11, runner 143/143, 완료 훅 15/15,
projects 63/63, bundle 394/394, submit gates 26/26, task data 10/10, revise 52/52,
nowork·rounds 실패 0건. `git diff --check` 통과.

배포 전 운영 큐 8개 work 모두 merged/rejected/cancelled로, 부팅 복구가 이동시킬 열린
work는 없다. Kimodo 취소 work와 하위 verified 2건을 다시 확인했다. 해당 이력을 되살리지 않는다.
사용자 커밋·push·배포 승인은 확보했다. 배포 결과는 Redmine `#701`·`#695`에 기록한다.
`#695`는 광범위한 상위 일감이며 이번 재시도 수정만으로 전체 완료 처리하지 않는다.
운영 분산 작업 재시도·요청자 실제 대화 수신·서브모듈 통합 검수는 이 회귀의 증명 범위 밖이다.
