## 1. 문제는 「codex 가 고장났다」가 아니라 「실행 세션」이었다

`#401` 은 *"`.2` 에서 codex 셸이 `0xC0000142` 로 죽는다"* 로 시작했다. 코덱스 세션이 원인을
정확히 규명했고(Session 0 의 Window Station/Desktop 에 자식 로그온 SID 용 ACE 가 없다),
패치 빌드로 A/B 까지 증명했다. 그런데 **해법은 패치가 아니었다.**

| 실행 경로 | 세션 | 설치본 `0.153.4` |
|---|---|---|
| SSH 가 직접 실행 | 0 | ❌ 셸 자식 `0xC0000142` |
| **SSH → `schtasks /run` (`/IT`)** | **1** | ✅ `exit_code 0` · `turn.completed` |

`/IT`(로그온 시에만 실행)로 등록하면 SSH 는 **스케줄러에게 부탁만** 하고 프로세스는 스케줄러가
세션 1 에 만든다. **패치 codex·Rust 툴체인·아티팩트 배포·CI 빌더·저장소 분리가 전부
불필요해졌다.**

[주의] **평범한 자식 프로세스는 세션 0 에서도 만들어진다**(`cmd.exe` rc=0 실측). 죽는 것은
codex 의 **제한 토큰 샌드박스 자식**뿐이라 `codex sandbox cmd.exe` 로는 판정이 안 난다 —
그 시험이 설치본·패치판 양쪽 다 통과했던 이유가 이것이다.

되살릴 물건일 수 있다** … 지운다면 되살릴 조건을 기록에 남긴다."* 기계 확장이 전제가 되면서
그 조건이 성립했다.

### 새로 쓰려다 같은 함정을 다시 밟았다

그걸 보기 전에 `.bat` 으로 등록 스크립트를 새로 썼다. 그 안에서:

- `py` 를 **PATH 로** 찾았다 → 원본 주석: *"`pythonw` 는 PATH 에 없다(실측 `.2`). 그래서
  **경로를 선언에 박지 않고 잰다** — 버전 디렉토리(`Python310`)라 박으면 업그레이드에 깨진다"*
- `%~dp0` **상대경로**를 썼다 → 원본은 절대경로를 쓴다
- 중첩 따옴표를 **눈으로** 맞췄다 → 원본 주석: *"`/tr` 안쪽 인용은 `\"` 로 이스케이프한다.
  그냥 주니 cmd 가 두 번째 토큰을 옵션으로 읽어 **「잘못된 인수/옵션」** 으로 거부했다"*

**이 파일의 값어치는 코드가 아니라 실측으로 산 지식이다.** 새로 쓰면 그걸 전부 다시 산다.

## 3. 🔴 실물이 잡은 결함 둘 — 유닛은 전부 초록이었다

### ⑴ `.43` cron 이 `--types=code` 로 걸렸다

`#404` 가 데몬에서 추론(code) 경로를 들어냈는데 `types_for` 가 몰랐다. 그대로 뒀으면 데몬이
**마스터 push(`work/infer.py`)가 맡아야 할 태스크를 집어 `unsupported-type` 으로 튕겼을 것**
이다 — 남의 일을 훔쳐서 실패시키는 상태다.

    types_for   "build,code" if ue5 else "code"   →   "build" if ue5 else ""

[중요] **`.43` 부터 재본 것이 이것을 잡았다.** `.2` 는 UE5 가 있어 `build` 로 정상 등록되느라
드러나지 않았을 것이고, 다음 code 태스크를 조용히 훔쳤을 것이다.

### ⑵ 빌드 PASS 96초인데 submit 이 409

`#318`(고지자 신원 게이트)이 `#320`(상주 철거) **뒤에** 생긴 계약이라, 그 전에 지워진 데몬이
`worker_id` 필드를 몰랐다. 서버 주석의 근거가 그 사이에 죽어 있었다:

> *"큐의 submit 표면을 두드리는 주체는 **전부 이 저장소의 마스터 코드**다 … 상주 claimer 는
> `#320` 으로 철거됐다. 그래서 하위호환 예외를 둘 이유가 없다"*

판정 자체는 그대로 옳으니 게이트는 두고, 데몬이 신원을 싣게 고치고 **낡은 근거에 정정 주석**을
달았다(지우지 않는다 — 다음 사람이 같은 전제로 추론하지 않도록).

## 5. 범위를 넘어 만들었다가 폐기한 것 둘

기록으로 남긴다 — 같은 길로 다시 가지 않도록.

**⑴ 세션 1 브리지(명령 드롭박스).** 마스터가 임의 셸 문자열을 파일로 떨구고 스케줄러가
실행하는 구조를 만들었다. 동작은 했다(`ax-client` MCP 호출까지 성공). 그러나 **인증도 계약도
없는 로컬 원격실행 면**이고, 사용자 설계(데몬이 큐에서 **정의된 task** 를 claim)와 정반대다.
사용자 지적으로 즉시 걷어냈다 — `.2` 에서 작업·파일 전부 제거 확인.

**⑵ `client/windows/*.bat` + `OS_ASSETS_BY_ROLE`.** OS 축을 새로 만들려 했는데
`residency.py` 가 이미 그것이고 더 낫다 — **명령 조립이 파이썬이라 윈도우 없이 테스트된다.**
이 저장소에는 윈도우에서 도는 테스트가 **없다**(123개가 전부 마스터의 파이썬). `.bat` 안에
판단이 들어가면 구조적으로 검증 불가가 된다. 디렉토리와 **경계 규약만** 남겼다.

**⑶ 일회용 배달 스크립트.** `--host` 가 없어서 스크래치패드에 배달 스크립트를 따로 썼다.
저장소에 없으니 다음 사람이 못 쓴다 — `#407` 에서 `--host` 옵션으로 없앴다.

셋 다 *"만들기 전에 ①원전에 있나 ②**이미 잡는 게 있나**"* 를 안 본 결과다.
