# 분류: 기존 기능 수정

`#960` 착수 전 인터뷰에서 「기존 기능 수정」으로 확정된 일감의 단계별 안내다. 재현 단계는 이 분류에
적용하지 않는다(머리말 `steps`) — 도구가 건너뜀 노트를 남긴다. 모든 단계는 결과 제시 → 사용자 확인 →
단계 노트로 끝난다.

## 조사 (investigate)

- 고칠 기존 기능은 어디인가 — 진입점·모듈·설정·스킬(how).
- 그 기능은 왜 지금처럼 만들어졌나 — 그 동작을 정한 일감·사용자 결정·문서(why).
- 사용자에게 확인: 「기존의 어떤 부분을 무엇으로 고치려는가」 · 「지금 동작을 정한 결정이 이것이 맞나」.

## 명세 (specify)

- 바뀌기 전 동작과 바뀐 뒤 동작을 나란히 적는다.
- 지금 동작에 기대는 쪽이 있으면 그대로 둘 것과 바꿀 것을 사용자와 정한다.

## 파급 측정 (impact)

- 바뀌는 동작을 쓰는 호출자·인접 모듈·상주 서비스(재기동 필요 여부)·배달 대상.
- 기존 검사 중 바뀐 동작 때문에 기대값이 달라지는 것.
