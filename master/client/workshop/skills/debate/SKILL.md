# Debate — 다관점 3사이클 토론 스킬

## 목적

한 모델이 여러 역할을 동시 시뮬레이션하면 **같은 편향·blind spot 을 공유한 균형 잡힌 합의**가 나옴. 진짜 서로 다른 관점은 도출되지 않는다. 이를 깨려면 **독립 시작점에서 출발한 N개 에이전트가 서로의 의견에 정직하게 반응**하도록 격리·전달 흐름이 필요하다. 이 스킬이 그 패턴을 자동화한다.

## 호출 방법

사용자가 다음 중 하나로 호출:
- `/debate <주제>` — 기본 3역할(엔진팀/클라이언트/TD), 3사이클
- `/debate <주제> --roles "역할1,역할2,..."` — 역할 커스텀
- `/debate <주제> --cycles N` — 사이클 수 (2 또는 3)
- `/debate <주제> --roles "..." --cycles N` — 둘 다 지정

자연어 트리거도 허용 (slash 없어도 description 매칭으로 자동 발동):
- "이 결정에 대해 여러 관점에서 토론해줘"
- "이 디자인 리뷰 다관점으로 진행해"
- "각자 롤 부여한 서브 에이전트에게 시켜서 토론"

## 사용 금지 사항 (BLOCKING)

다음 경우 스킬을 발동하지 말고 사용자에게 단일 답변 또는 다른 접근 제안:

- **사소한 질문** — 단일 답변으로 충분 ("이 변수명 어떻게 할까", "이 오타 고쳐")
- **사실 확인** — 정답이 명확 ("이 함수 시그니처가 뭐야")
- **시간 압박 작업** — 9~12회 LLM 호출 + 수 분 소요
- **이미 결정된 사안** — 재검증이 아닌 실행 단계

부적합 판단되면 사용자에게 확인:
> "이 질문은 단일 답변으로 충분해 보입니다. 토론 진행할까요, 단일 답변 드릴까요?"

## 진행 절차

### Step 0 — 입력 파싱·검증

- 주제 추출 (인자 또는 자연어 발화에서)
- 역할 목록 파싱 (콤마 구분), 미지정 시 기본 3역할: **엔진팀 / 클라이언트 / TD**
- 사이클 수 파싱, 미지정 시 **3**
- 검증: 역할 ≥ 2 (단일 역할 무의미), 역할 ≤ 5 (그 이상은 토큰 폭발), 사이클 ∈ {2, 3}
- 주제가 비어있거나 trivial 하면 사용자에게 확인

검증 실패 시 토론 진행 X — 명확화 요청.

### Step 1 — 공유 컨텍스트 준비

다음을 한 번 작성하여 모든 사이클의 모든 에이전트에게 공유 (각 에이전트 호출마다 prompt 시작부에 포함):

```
=========================================
[프로젝트 배경]
=========================================
(현재 작업 중인 프로젝트의 핵심 정보 — CLAUDE.md 요약 또는 사용자 제공 context)

=========================================
[토론 주제]
=========================================
(사용자가 제시한 주제 + 배경 정보)

=========================================
[관련 데이터 / 현재 상태]
=========================================
(주제와 관련된 현재 관측 데이터·실측치·코드 상태 등)

=========================================
[사전 합의 / 직전 논의가 있었다면]
=========================================
(있을 때만 포함. 참고용 명시 — "이 합의에 도달할 의무 없음")
```

### Step 2 — Cycle 1: 독립 의견

각 역할마다 1개 에이전트를 Agent 툴(`general-purpose` subagent_type)로 spawn. **반드시 병렬 실행** — 한 메시지 안에 여러 Agent tool 호출 블록을 함께 보내야 함.

각 에이전트 프롬프트 구조:
```
[당신은 토론 시뮬레이션의 한 역할자입니다. 코드 변경·파일 작성 X. 응답 텍스트만.]

[공유 컨텍스트 — Step 1 에서 작성한 그대로]

=========================================
[당신의 역할]
=========================================
**<역할명>** — <역할 정의 1-2 문장>

관점:
- <이 역할이 우선시하는 가치 3-5개>

사고 방식:
- "<이 역할이 자주 던지는 질문>"
- ...

당신이 인지하고 있는 자기 블라인드 스폿:
- <역할의 한계 2-3개>

=========================================
[이번 사이클의 과제 — Cycle 1: 독립 의견]
=========================================

지금은 다른 그룹이 무엇을 말할지 모릅니다. 당신의 독립 의견을 표명하세요.

세 주제에 답변:
1. **한계성 / 문제점**
2. **방향 타당성 / 합리성**
3. **추가 개선 / 대안**

(주제에 따라 항목 명칭은 조정 가능 — 예: 회고면 "잘된 점/아쉬운 점/액션", 리스크 평가면 "위협/완화책/잔여 리스크")

지침:
- 캐릭터 일관성 — 자기 역할 관점에서만 사고
- 구체적 (모호한 일반론 금지)
- 솔직 — 단점·우려를 숨기지 말 것
- 다른 그룹과 합의 시도 금지 — 지금은 독립 단계
- 한국어, 약 400-600자
- 헤더 형식: `### <항목 1>`, `### <항목 2>`, `### <항목 3>`

답변만 출력 (자기 소개 같은 메타 텍스트 없이).
```

각 에이전트의 응답을 변수로 저장: `cycle1_role_1`, `cycle1_role_2`, ...

### Step 3 — Cycle 2: 상호 보강·반문·질의

각 에이전트마다 별도로 spawn. **자기 거울 답변 방지** — 자기 자신의 Cycle 1 발언은 "요지 정리" 만 짧게(3-5줄), 다른 그룹의 발언은 전문 그대로 전달.

병렬 실행. 각 에이전트 프롬프트:
```
[당신은 <역할명> 입니다. Cycle 2 — 다른 그룹의 의견에 보강·지지·반문·질의하는 단계.]

[공유 컨텍스트 — Step 1 그대로]

=========================================
[당신의 Cycle 1 발언 요지 — 자기 거울 답변 금지]
=========================================
> <자기 발언 3-5줄 요지>

=========================================
[다른 그룹들의 Cycle 1 발언 (전문)]
=========================================

## <다른 역할 1>
<해당 에이전트의 Cycle 1 응답 전문>

## <다른 역할 2>
<해당 에이전트의 Cycle 1 응답 전문>

(역할 수에 맞게 반복)

=========================================
[당신의 Cycle 2 과제]
=========================================

위 다른 그룹들의 의견에 반응하세요. 각 그룹별로 다음 4가지 액션 중 적절한 것 선택:

- **보강** — 동의하면서 보충
- **지지** — 강하게 동의하는 부분 + 이유
- **반문** — 의문 또는 반박
- **질의** — 답을 듣고 싶은 구체적 질문

지침:
- 캐릭터 일관성 — 자기 역할 시각에서만 사고
- 형식적 균형(보강 1개씩 등) 강제 X — 진짜 반응이 우선. 어느 그룹에는 반박만, 다른 그룹에는 지지만 해도 OK
- 다른 그룹 의견에 무조건 동의 X — 정직한 차이 드러낼 것
- 자기 그룹 입장 일관 유지
- 한국어, 약 500-700자
- 헤더 형식: `### → <상대 역할명>`

답변만 출력.
```

각 응답을 `cycle2_role_1` 등으로 저장.

### Step 4 — (사이클 3 모드일 때) Cycle 3: 도전에 답변

사이클 수 = 2 면 이 단계 스킵, 바로 Step 5 로.

각 에이전트마다 별도 spawn, 병렬 실행. 핵심: **자기에게 향한 도전·질의를 명시적으로 발췌**해서 전달 (다른 사람이 누구한테 한 말인지 헷갈리지 않게).

각 에이전트 프롬프트:
```
[당신은 <역할명> 입니다. Cycle 3 — 자기에게 향한 도전에 답변하는 단계.]

[공유 컨텍스트 — Step 1 그대로]

=========================================
[당신의 이전 발언 요지]
=========================================

Cycle 1 요지: <자기 Cycle 1 3-5줄>
Cycle 2 요지: <자기 Cycle 2 3-5줄>

=========================================
[당신에게 향한 Cycle 2 도전·질의]
=========================================

### <다른 역할 1> 로부터:
<그 에이전트가 당신에게 한 발언 발췌 — 보강/지지/반문/질의>

### <다른 역할 2> 로부터:
<그 에이전트가 당신에게 한 발언 발췌>

(이 발췌는 다른 에이전트의 Cycle 2 응답에서 `### → <당신 역할>` 섹션을 추출)

=========================================
[당신의 Cycle 3 과제]
=========================================

위 도전·질의에 답하세요. 4가지 액션 중 적절한 것 선택:

- **수용** — 인정하고 양보할 부분
- **방어** — 동의하지 않고 자기 입장 고수 (이유 포함)
- **타협안** — 양쪽 의견 절충
- **commit / 보류** — 무엇을 commit / 무엇은 더 검토 필요

지침:
- 캐릭터 일관성 — 자기 역할 시각
- 질의에는 구체적으로 답할 것 (모호한 일반론 금지). 가능하면 구현 가능 여부·비용 견적 동반
- 자기변명만 금지 — 인정할 건 인정
- 한국어, 약 500-700자

답변만 출력.
```

응답을 `cycle3_role_1` 등으로 저장.

```markdown

work_id: null
session_id: null
decision_type: experiment              # 토론은 대개 experiment 또는 policy
affected_classes: []                   # 토론 중 거론된 클래스명 (있는 경우)
```

## 역할 라이브러리 (참고)

사용자 지정 없이 기본 3역할 사용 시 또는 사용자가 라이브러리 이름으로 지정 시 사용:

| 역할 | 정의 | 우선순위 |
|------|------|---------|
| `엔진팀` | 시스템 구축·유지보수자 | 운영 안정성·데이터 무결성·기술 부채 |
| `클라이언트` | 실사용자 | 일상 워크플로우 마찰·즉시 가치·신뢰 |
| `TD` | 리더 | 전략·ROI·자원 배분·측정·포기 시점 |
| `시니어` | 경험 많은 개발자 | 패턴·선례·장기 영향·유지보수성 |
| `주니어` | 신규 개발자 | 학습 곡선·문서·진입 장벽 |
| `보안` | 보안 엔지니어 | 위협 모델·법무·컴플라이언스 |
| `QA` | 품질 엔지니어 | 회귀·엣지케이스·테스트 가능성 |
| `사용자` | 최종 사용자 | UX·접근성·실수 허용도 |
| `운영` | 인프라·배포 | 가용성·모니터링·장애 대응 |

각 역할은 자기 blind spot 도 함께 정의해서 자기 인식 유지. 사용자가 직접 역할명 + 정의 제공하면 그것을 우선.

## 비용 안내

| 모드 | LLM 콜 | 추정 토큰 |
|------|--------|-----------|
| 3역할 × 2사이클 | 6회 | 20k-50k |
| 3역할 × 3사이클 | 9회 | 30k-80k |
| 5역할 × 3사이클 | 15회 | 50k-130k |

비용 부담스러우면 사용자에게 **사이클 2개 또는 역할 2-3개**로 축소 제안.

## 핵심 주의 사항

1. **역할 일관성** — 각 에이전트가 자기 역할 관점만 유지하도록 프롬프트에 강하게 명시. 균형 잡힌 voice 안 나오면 단일 모델 시뮬과 차이 없어짐
2. **자기 거울 답변 방지** — Cycle 2/3 에서 자기 자신 이전 발언은 짧은 요지만, 다른 그룹은 전문. 자기 발언 전문 다시 받으면 "이미 한 말 반복" 으로 회귀
3. **격리 유지** — 같은 사이클 내 다른 에이전트의 발언은 절대 미리 공유 X. Cycle 1 은 완전 독립, Cycle 2 는 Cycle 1 결과만, Cycle 3 은 Cycle 1+2 결과만
4. **발언 그대로 인용** — 보고서 작성 시 LLM 으로 재요약·재구성 X. voice·뉘앙스가 핵심 가치
5. **병렬 spawn** — 같은 사이클의 에이전트들은 한 메시지에 함께 호출 (Agent tool 다중 use). 순차 실행하면 시간 N배
6. **trivial 질문 방어** — 사용자가 사소한 걸로 호출하면 비용 낭비. Step 0 에서 거를 것

## 종료

보고서 작성 후 사용자에게:
- 보고서 경로
- 핵심 발견 3-5개 (특히 입장 변경·자기 정정·새 통찰)
- 즉시 commit 항목 수
- 보류 항목 수와 결정 시점

추가 사이클이나 다른 역할 추가 요청이면 새 호출로 받음 (이전 토론은 완결).
