# ax-work — 마스터 작업 수행 (워커 측 계약)

> 마스터가 생성해 배달한다. **손으로 고치지 말 것** — 다음 배달에 덮인다.
> 정본: `~/ax-cluster/master/client/skills/ax-work/SKILL.md` (마스터)

## 0. 🔴 이 스킬의 네 가지 전제 (사용자 확정 2026-08-09)

1. **이 머신에 프로젝트 소스 클론이 있다.** 없으면 작업하지 않는다
2. **마스터의 작업 요청은 네가 1차로 받고, 네가 오케스트레이션한다.** 마스터는 컨텍스트·큐·
   라우팅만 댄다 — 실행 판단은 이 머신의 몫이다
3. 🔴 **컨텍스트 문서·도메인 규범은 어디까지나 참조다. 모든 판단의 기준은 소스 파일이다**
4. **너 혼자 다 하지 않는다** — 대량 생성은 `agy`/로컬 LLM 에 위임하고 **너는 검증한다**

## 1. 먼저 `./.ax/config.json` 을 읽는다

작업은 **체크아웃 디렉토리에서 시작한다.** 설정은 항상 같은 상대경로에 있다:

    ./.ax/config.json        이 머신·프로젝트 설정 (마스터가 생성)
    ./.ax/work/<task_id>/    작업 부산물은 전부 여기 (git 이 무시한다)

거기서 읽을 것: `master.services`(포트) · `checkout.path` · `capabilities` · `backends`.

🔴 **없으면 추측하지 말고 멈춘다.** 경로를 역산하거나 다른 머신의 값을 가져다 쓰지 말 것 —
그렇게 복사된 설정이 죽은 채 남아 있던 사고가 실제로 있었다(`.mcp.json` 이 다른 머신의
사용자 경로를 가리키고 있었다). 마스터에 배달을 요청한다.

## 2. 마스터에서 일감을 받는다

| 무엇 | 어디 |
|---|---|
| 태스크 claim | `POST http://<master>:8101/api/v1/tasks/claim` — `capabilities` 를 **config 값 그대로** 신고 |
| 하트비트 | `POST /api/v1/tasks/<id>/heartbeat` — 오래 걸리면 lease 가 만료된다 |
| 매니페스트 | MCP `get_manifest` (8103) — 컨텍스트·**도메인 규범**·골조·동결 계약이 한 문서 |
| 제출 | `POST /api/v1/tasks/<id>/submit` |
| 검색이 더 필요하면 | MCP `search_context_tool` · `resolve_terms_tool` |

세 서비스 모두 **베어러 토큰**이 필요하다. MCP 는 등록에 헤더가 박혀 있다.

🔴 **능력을 부풀리지 말 것.** `capabilities` 에 없는 것을 신고하면 이 머신이 못 하는 일을
집어가고, 큐는 **조용히 굶는다**. 특히 `ue5` 는 UE5 툴체인이 실제로 있는 머신만이다.

## 3. 🔴 매니페스트는 지도다 — 판단은 소스로 한다

매니페스트에는 컨텍스트 문서 발췌와 도메인 규범(invariants)이 들어 있다. 그건
**어디를 볼지 알려주는 것**이지 사실의 원천이 아니다.

    지도(매니페스트)로  →  어느 파일·어느 클래스인지 좁힌다
    그 다음 반드시      →  Read 로 그 소스 파일을 직접 읽는다

**실측된 이유**(2026-08-09): 규범만 주고 로컬 모델에 코드를 시켰더니 실재 멤버 4/4 를 쓰고
invariant 도 지켰지만, `CurrentStep`(실제는 `Step`) · `EMissionTaskExecutorState`(실제는
`EMissionExecutorState`) 처럼 **한 글자 차이로 지어낸 이름**이 남았다. 정확한 철자는
**헤더에만 있다.** 너는 파일을 읽을 수 있으니 그 오류를 낼 이유가 없다.

- 시그니처·멤버명·enum 값은 **선언부를 열어 확인**한다
- 규범(invariant)과 소스가 어긋나면 **소스가 이긴다.** 어긋난 사실을 제출물에 적는다
- 매니페스트가 *"규범 grounding 없이 진행된다"* 라고 적혀 있으면 그대로 믿고, **소스를 더 읽어**
  메운다

## 4. 위임하고 검증한다 (모토: 무료=대량 생산, 상용/너=검증)

`./.ax/config.json` 의 `backends` 가 이 머신에서 쓸 수 있는 것을 말해 준다.

| 백엔드 | 쓰는 자리 |
|---|---|
| **로컬 LLM** (`backends.ollama`) | 반복적 본문 채우기, 대량 변환. 무료다 |
| **`agy`** (`backends.agy` 가 true 일 때) | 큰 파일 조사·정리. 🔴 **`--add-dir` 로 파일을 쥐여줄 것** — 웹에서 찾으라고 시키면 출처를 지어낸다(실측). `-p` 는 **프롬프트 직전**에 둔다 |
| **너(Claude)** | 오케스트레이션 · 소스 대조 · 최종 검증 |

🔴 **위임 결과의 "완료" 를 믿지 말고 산출물을 확인한다.** `agy` 가 `status:"SUCCESS"` 를
반환하면서 파일을 안 쓴 사건이 있다. 파일이 생겼는지, 내용이 맞는지 **네가 본다.**

🔴 **결정적 게이트가 LLM 판단보다 우선한다.** 컴파일·테스트·린트가 있으면 그것이 최종 판정이고,
"모델이 괜찮다고 했다" 는 근거가 아니다.

## 5. 파일을 어디에 쓰나

| 산출물 | 위치 |
|---|---|
| **코드 변경** | 체크아웃 안. 🔴 **`attempt/<task_id>/<workshop>/<timestamp>` 브랜치**에서 작업 |
| 로그·중간물·매니페스트 사본 | `./.ax/work/<task_id>/` — git 이 무시한다 |
| 그 밖 | **아무 데도 쓰지 않는다** |

🔴 **git 금지 목록** — 되돌리기 어려운 것은 하지 않는다:

    push --force · reset --hard · checkout(작업 브랜치 밖) · git clean ·
    브랜치/태그 삭제 · rebase · main 직접 push

특히 **`git clean` 은 절대 부르지 않는다.** 미추적 파일을 통과시키는 더티 체크의 전제가
그것이다. 그리고 사람이 편집 중인 미커밋 파일이 있을 수 있다 — `.uasset` 은 바이너리라
날리면 복구할 수 없다.

**시작 전에 워킹트리를 확인한다.** 추적 파일이 더러우면 **작업하지 말고 보고한다** — 사람이
편집 중일 수 있고, 그걸 밀어내는 것이 이 게이트가 막으려는 사고다.

## 6. 제출

제출물에 **반드시** 담을 것:

- 무엇을 바꿨나 (파일·브랜치)
- **소스로 확인한 것** — 어떤 선언부를 읽고 무엇을 맞췄나
- 규범과 소스가 어긋난 지점이 있었으면 그 사실
- 위임한 것이 있으면 **무엇을 어디에 맡겼고 어떻게 검증했나**
- 결정적 게이트(빌드·테스트)를 돌렸으면 그 **원문 판정**. 🔴 요약하지 말 것 —
  `ssh` 종료 코드는 **양방향으로 못 믿는다**(빌드 실패에 0, 테스트 성공에 1이 나온 실측이 있다).
  로그의 판정 문자열이 근거다

## 7. 막혔을 때

- **설정이 없다** → 마스터에 배달 요청. 추측 금지
- **체크아웃이 낡았다** → 마스터에 최신화 요청. 🔴 `reset --hard` 로 스스로 맞추지 말 것
- **능력이 모자란다**(UE5 없음 등) → 집지 말고 사유와 함께 반환. 못 하는 일을 붙들면 lease 만 태운다
- **소스와 지시가 모순** → 소스가 이긴다. 모순을 보고한다
