# ax-infer — 추론만 한다 (워커 측 계약)

> 마스터가 생성해 배달한다. **손으로 고치지 말 것** — 다음 배달에 덮인다.

## 0. 🔴 이 스킬과 `ax-work` 의 차이 — **너는 쓰는 주체가 아니다**

    ax-work    (구 토폴로지) 워커가 고치고 커밋하고 attempt 를 push 한다
    ax-infer   (현 토폴로지) 🔴 워커는 **읽고 추론하고 텍스트로 답한다.** 적용·빌드·커밋은
               **통합자 한 대**가 한다

사용자 확정 2026-08-11. 근거는 하나다 — **빌드해 본 주체가 커밋해야 깨진 것이 원격에 못
박힌다.** 옛 구조는 태스크를 워커의 자기 신고(`RESULT: DONE`)로 판정하고 *"컴파일되나"* 를
아무도 묻지 않았고, 전임 시스템이 정확히 그 구조에서 사고를 냈다: 깨진 골조가 `origin` 에
박히고 **워커 전원이 그 위에서 작업**했다.

🔴 **그래서 이 스킬에는 git 쓰기가 없다.** `ax-work` 가 시키던 attempt 브랜치·커밋·push 를
**하지 않는다.** 두 스킬이 함께 배달돼 있으니, **마스터의 지시가 어느 쪽인지 보고 고른다** —
지시에 `ax-infer` 가 적혀 있으면 이 문서가 계약이다.

## 1. 먼저 `./.ax/config.json` 을 읽는다

체크아웃 경로·능력·백엔드가 거기 있다. **없으면 추측하지 말고** `RESULT: BLOCKED` +
없는 경로를 적는다. 마스터가 배달을 안 한 것이므로 네가 만들 것이 아니다.

## 2. 🔴 일감은 배달되어 온다 — 큐를 직접 부르지 않는다

읽을 것은 `./.ax/work/<task_id>/manifest.md` 하나다. 큐(8101)는 **401 이 정상**이다 —
토큰은 마스터에만 있고, 우회로를 찾지 않는다. 매니페스트가 없으면 `RESULT: BLOCKED`.

## 3. 🔴 매니페스트는 지도이고, 판단은 소스로 한다

매니페스트에는 기준 커밋·대상 파일·**동결 계약**·골조·RAG 발췌·도메인 규범이 실려 있다.
그러나 **최종 근거는 체크아웃의 실제 소스**다. 실측으로 확인된 이 구조의 값이 그것이다 —
워커의 Claude 가 헤더를 직접 열어 **실재하는 멤버만** 썼다.

- 매니페스트와 소스가 어긋나면 **소스가 이긴다.** 어긋난 사실을 응답 본문에 적는다
- 기억에서 API 를 꺼내지 않는다. 열거값·멤버·시그니처는 **읽은 파일에서** 가져온다
- **동결 계약은 못 바꾼다** — 추가는 되고, 변경·삭제는 위반이다. 마스터가 적용 직전에 검사한다

## 4. 시작 자세 — 🔴 **기준 커밋의 소스를 읽어야 한다**

    git fetch origin
    git checkout <기준 브랜치>              ← 매니페스트 「기준 (커밋·브랜치)」 절의 durable task/<id>
    git merge --ff-only origin/<기준 브랜치>  ← 🔴 ff 가 안 되면 BLOCKED. reset --hard 금지

**왜 이것만은 하나**: 낡은 소스에서 추론하면 통합자가 적용할 트리와 근거가 어긋난다.
브랜치 이동은 추적 파일만 건드리고 되돌릴 수 있어 허용하지만, **그 이상은 없다.**

🔴 **`Source/` 하위가 더러우면 `RESULT: BLOCKED`.** 판정 범위는 정확히 이것이다:

    git status --porcelain -- Source/     ← 여기가 더러우면 BLOCKED
    범위 밖(Content/·루트의 .slnx·.uproject) → **막지 않는다**

범위 밖은 UE5/VS 가 프로젝트를 열기만 해도 다시 쓰는 머신 지역 파일이다(실측: `.uproject` 의
diff 는 `EngineAssociation` GUID). 그걸 감시하면 게이트가 **항상 빨간불**이 되고, 항상 빨간
게이트는 게이트가 아니다. 🔴 마스터도 **같은 범위**로 파견 대상을 고른다 — 네가 더 넓게 보고
거부하면 왕복만 생긴다.

## 5. 🔴 무엇을 쓸 수 있나 — **응답 파일 하나뿐이다**

| | |
|---|---|
| 쓴다 | `./.ax/work/<task_id>/response.txt` **하나.** git 이 무시하는 자리다 |
| 🔴 **안 쓴다** | 소스 파일 · 커밋 · `git add` · push · 브랜치 생성/삭제 · 그 밖 모든 경로 |

**소스 파일을 직접 고치지 않는다.** 고치고 싶은 내용을 **응답 파일에 텍스트로** 낸다.
적용은 통합자가 한다 — 그래야 빌드가 통과한 것만 원격에 남는다.

🔴 **git 금지 목록** (되돌리기 어려운 것): `push --force` · `reset --hard` · `git clean` ·
브랜치/태그 삭제 · `rebase` · `main` 직접 push. 특히 **`git clean` 은 절대 부르지 않는다** —
사람이 편집 중인 미커밋 `.uasset` 은 바이너리라 날리면 복구할 수 없다.

## 6. 응답 형식 — 🔴 **파일 본문을 통째로, 마커로 구분해서**

`./.ax/work/<task_id>/response.txt` 를 **UTF-8** 로 쓴다. 대상 파일마다 한 블록:

    === FILE: Source/ModularStage/Mission/MSMissionTask.h ===
    (그 파일의 **완성된 전체 내용**. 부분 diff 가 아니다)

    === FILE: Source/ModularStage/Mission/MSMissionTask.cpp ===
    (같음)

🔴 **이 파일에는 블록만 있다.** `RESPONSE:`·`RESULT:` 를 **파일에 쓰지 않는다** — 그 두 줄은
§7 대로 **stdout 에만** 낸다. 실측 2026-08-12(첫 실전 구동): 파일 끝에 써 넣었더니 마지막
파일의 본문 끝에 `RESULT: DONE` 이 섞였다. 마스터가 떼어 내지만 **⚠️ 로 보고된다.**

🔴 **규칙 넷.** 하나라도 어기면 마스터가 응답을 버린다(fail-closed):

1. **매니페스트 「대상 파일」 목록의 파일만** 낸다. 목록 밖 경로는 마스터가 버린다 —
   분해 계획에 없던 파일은 다른 조각과 충돌할 수 있다
2. **목록의 파일을 전부** 낸다. 빠지면 그 조각은 미완이다
3. **부분이 아니라 전체 내용**을 낸다. 통합자는 파일을 그대로 쓴다
4. 🔴 **마크다운 펜스(``` )를 넣지 않는다.** 설명·주석은 응답 파일이 아니라 stdout 본문에

⚠️ **`[PSEUDO]` 를 남기지 않는다.** 골조의 `[PSEUDO]` 주석은 *"여기를 채워라"* 는 표시이고,
채운 뒤에는 지운다. `[DOC]`·`[STATE]`·`[BIND]`·`[REPLICATED]` 와 무태그 주석은 **보존한다.**

⚠️ **비어 있는 본문을 내지 않는다.** 못 채웠으면 그 파일을 빼는 게 아니라 `RESULT: BLOCKED` 다.

## 7. 종료 자세와 마커 — 🔴 **stdout** 의 마지막 두 줄이 계약이다

응답 파일을 쓴 **뒤에**:

    git checkout main                     ← 🔴 main 으로 돌아온다 (기준 브랜치가 아니라)

기준 브랜치에 앉아 있으면 마스터의 정리기가 **그 브랜치를 영영 못 지운다**(체크아웃된 브랜치는
삭제 대상에서 빠진다). 응답 파일은 `.ax/` 라 브랜치 이동에 영향받지 않는다.

그 다음 🔴 **stdout 에 출력하는(= 화면에 찍는) 마지막 비어 있지 않은 두 줄**을 정확히
이렇게 낸다. **응답 파일이 아니라 stdout 이다:**

    RESPONSE: <낸 파일 수>
    RESULT: DONE

🔴 **그 두 줄 뒤에 아무것도 찍지 않는다.** 실측 2026-08-12: 마커를 본문 중간에서 *인용*하고
(*"Final two lines of the output file: …"*) 마지막에 요약 문장을 한 줄 더 찍는 바람에 **마지막
줄이 `RESULT:` 가 아니어서 BLOCKED** 이 됐다 — 일은 제대로 해 놓고 판정에서 떨어졌다.
요약은 마커 **위에** 쓰고, 마커를 인용하지 말고 **마커로만** 끝낸다.

못 끝냈으면 `RESULT: BLOCKED` 이고 **그 위에 왜인지 적는다.**

🔴 **마스터는 이 마커만 읽고, 그 다음 응답 파일을 되읽어 대조한다. fail-closed 다** — 마커가
없거나·마지막 줄이 아니거나·철자가 다르면 **BLOCKED** 다. 산문으로 *"성공적으로 완료했습니다"*
라고 써도 성공이 아니다. 거짓 완료가 큐에 쌓이면 다음 태스크의 `depends_on` 이 잘못 풀린다.

**stdout 본문(마커 위)에 담을 것** — 응답 파일이 아니라 여기다:

- **소스로 확인한 것**: 어떤 선언부를 읽고 무엇을 맞췄나
- 매니페스트·규범과 소스가 어긋난 지점
- 🔴 **애매해서 골라야 했던 것** — 통합자가 아니라 사람이 볼 대목이다. 골조 단계의 휴리스틱
  수집과 같은 자리이고, **기계가 정하지 않는다**
- 위임한 것이 있으면 무엇을 어디에 맡겼고 어떻게 검증했나

## 8. 막혔을 때

🔴 **막혔을 때도 `RESULT: BLOCKED` 를 내고 끝낸다.** 조용히 멈추면 마스터는 타임아웃까지
기다리다 같은 판정을 내리는데, 그 사이 시간과 리스를 버린다.

- **설정·매니페스트가 없다** → 배달이 안 된 것이다. `BLOCKED` + 없는 경로. 추측 금지
- **체크아웃이 낡았다** → `fetch` + **ff 로만** 따라잡는다. 안 되면 `BLOCKED`
- **`Source/` 가 더럽다** → `BLOCKED` + `git status --porcelain -- Source/` 원문
- **동결 계약을 지키면 요구를 만족할 수 없다** → 🔴 계약을 바꾸지 말고 `BLOCKED` + 그 모순.
  동결이 틀렸다면 골조를 다시 만들 일이고, 그건 마스터와 사람의 몫이다
- **소스와 지시가 모순** → 소스가 이긴다. 모순을 보고한다
- **401 이 돌아온다** → 정상이다(§2). 우회로를 찾지 말 것
