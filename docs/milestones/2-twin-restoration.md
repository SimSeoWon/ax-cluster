## 왜 이 마일스톤인가

마일스톤 1 이 **파이프를 이었다.** 그런데 그 파이프에 흐르는 **정보를 만드는 능력이 없다.**

```
트윈을 쓰는 쪽 (검색)   ← 부분적으로 있다
트윈을 만드는 쪽 (합성) ← 🔴 0
```

트윈은 **2026-08-08 12:56 에 받은 스냅샷**이고 스스로 자라지 못한다. 워크플로우가 코드를
새로 짜도 그 코드는 트윈에 안 들어간다. 시간이 갈수록 RAG 근거가 실제 코드베이스와
벌어지는데 **에러 없이 조용히** 벌어진다.

### `data-schema.md` 하나로 뒤집힌 것

§10「재생성 명령 요약」이 **각 자산을 어떻게 되살리는지** 이미 적어 두었다:

| 자산 | 재생성 |
|---|---|
| `context_a/b` + `bm25.db` | `--rebuild` |
| `bm25_domains.db` + `ontology_domains` | **`--sync-domain-index`** |
| `class_graph.db` · `dependency_graph.db` | **파일 삭제 → 재기동 시 풀 스캔** |
| 인프라 이전 | `--export-state` → `--import-state` |

그리고 가장 중요한 구분:

> 도메인 YAML·컨텍스트 MD 자체는 파생이 아니라 **합성 산출물**이다. … 인프라 컴퓨터를
> 옮길 때는 **이 두 디렉토리만** 옮기면 된다 — `vector_db/` 전체(임베딩·BM25·
> `class_graph.db`·`dependency_graph.db`)는 **로컬 연산만으로 재생성 가능한 파생 자산**이다.

→ 우리가 받은 zip 이 합성 산출물 2개이고, 나머지는 로컬에서 만들면 되는 것이다.
내가 "클래스 그래프 1,341줄 이식" 이라 분류한 것도 이 문서가 *"파일 삭제 → 풀 스캔"* 이라고
답을 주고 있었다. **줄 수는 작업량이 아니다.**

### A. `/distribute` 를 세우려면
- Step 2 계층 플랜 (`generate_work_plan`)
- Step 4 **골조 생성** (`generate_skeletons`) ← §4.5 의 전제
- Step 1.5b 템플릿 매칭 · Step 1.5 코드베이스 분석 · Step 0·5 골조 분석
- Step 1.4·6 기존 기능을 MCP 로 노출 (중복검사 · 빌드)

### B. `/review-work` 를 세우려면
- `review_work`(시뮬레이션 머지+빌드) · `integration_build` · `finalize_work` ·
  `reject_work` · `tdd_dryrun`

### C. 트윈을 자라게 하려면
- 컨텍스트 MD 합성 — 🔴 **LLM 을 부른다**(`context.py:373`). 순수 이식이 아니고 모델 배정과 엮인다
- 온톨로지 합성 — `class_graph` 를 import 한다. **선행 조건이 있다**
- 클래스 그래프 · 의존 그래프 — **LLM 없음.** `data-schema.md` 기준 "삭제 → 풀 스캔"
- **도메인 색인**(`sync_domain_index`) — 🔴 온톨로지 247 yaml 이 **검색 0건**인 직접 원인.
  "미이식" 이 아니라 **명시 호출 누락**이었다(원본 `import_state` 독스트링이 경고해 뒀다)
- 상태 임포트/익스포트 — 다음 `--export-state` 를 받기 전에

### D. 볼 수 있게 하려면
