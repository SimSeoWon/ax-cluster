## 3. 진짜 원인은 저널에 그대로 있었다

`#391` 배선(`agent_report` → `[agent]` 저널)은 **살아 있었다.** 매 시도마다 codex 자신의
말이 찍혔다:

    [agent] 6831331b @192.168.0.2 말: 구현 계획: … `[PSEUDO]` 표식을 제거하고 …
            AGENTS.md 규약에 따라 소스 수정과 빌드 전에 동의가 필요합니다.
            이 계획대로 진행해도 되는지 승인해 주세요. RESULT: BLOCKED
    [usage] 입력 196,267 · 출력 1,236 · 비용 미상
    [revise] 1/3 — 재시도로 보낸다

🔴 **세 시도의 출력이 글자까지 같다** — 토큰 수(196,267 / 1,236)도 동일하다. 결정적 거절이라
재시도가 원리적으로 못 고친다.

[중요] 심은 것은 나다. `#402` 가 `AGENTS.md` 를 CLAUDE.md 전문 시드로 깔면서
*"이 파일과 게임 소스는 고치기 전에 계획을 말하고 동의를 받는다"* 가 **워커에도** 갔다.
그 규칙은 **대화 세션**을 위한 것인데 파견 세션에는 물어볼 사람이 없다.

## 4. 고친 자리 — 문서가 아니라 지시문

먼저 `bundle.managed_block` + `payload/claude_md/NS.md` 에 워커 한정 예외를 넣었다(`103d64e`).
그것만으로 끝내지 않은 근거 넷, 전부 실측이다:

    ⑴ `AGENTS.md` 는 **배달물**이다 — 사람이 본문을 고치면 날아가고,
       배달이 밀린 기계는 옛 문구를 본다
    ⑵ `role: worker` 는 **마스터 레지스트리에만** 있다 — `.2` 의 `.ax/config.json`
       `this_host` 는 `host`/`user`/`os` 뿐이라 워커 안에서 자기 역할을 못 읽는다
    ⑶ 읽어도 「이 기계가 워커다」이지 「이 프롬프트가 파견이다」가 아니다 —
       같은 체크아웃에서 사람이 직접 codex 를 열 수도 있다
    ⑷ 🔴 **승인 플래그로도 못 막는다** — codex 는 도구 승인 채널이 아니라 **산문으로**
       물었다. `approval_mode="approve"` 29개도 `--dangerously-skip-permissions` 도
       텍스트 질문은 못 막는다

🔴 그래서 원천은 **지시문 하나뿐이다** — 마스터가 만들고, 파견마다 나가고, 모델이 무조건
읽는다. `runner.INSTRUCTION` 에 두 줄을 넣었다(`7245cc0`, ASCII 유지):

    "This message is dispatched work from the AX master, not a human chat:
     the plan was already approved when the task was registered. "
    "Do not ask for approval, do not propose a plan for review,
     do not wait for confirmation - implement the bodies now. "

## 6. 플레이크 하나 — 조용해서 위험했다

`test_nowork.py` 가 **내용은 0실패인데 rc=1** 로 끝났다. 10회 중 5회.

`_notice` 가 Redmine 함수를 스텁으로 갈아끼우고 **첫 게시물**을 받았는데, `register_work` 도
데몬 스레드로 이슈를 만든다(`_try_create_work_issue_async`). 그 스레드는 설정을 **모듈
속성으로 늦게** 읽으므로, 스텁이 걸려 있는 사이 깨어나면 가짜 설정을 집어 등재 노트를 먼저
넣는다. 제목으로 공지를 지목하도록 고쳤다(`3012a5f`).

[주의] **경쟁이라 조용했다** — 다음 판에서 통과하므로 「진짜 공지 본문이 틀어진 것」과
구분되지 않았고, 문서의 테스트 루프는 rc 로 판정한다. 필터가 진짜 결함을 가리지 않는지
확인했다 — 공지 본문을 망가뜨리니 3/3 결정적으로 실패, 되돌리니 12/12 rc=0.

## 7. 남은 결함 — 여섯 번째 갈래가 없다

`revise.py` 에는 재시도가 무의미한 갈래가 둘 있다 — `ENV`(`#391`) · `QUOTA`. 「지휘자가 일을
안 하고 말로 끝냈다」는 **어느 쪽도 아니라** `classify` 로 떨어져 `MAX_ATTEMPTS=3` 을 태운다.

    조각 2건 × 3시도 = 6회 · 입력 196,267 × 6 ≈ 118만 토큰을 같은 거절에 썼다

🔴 [주의] **이 수치와 「출력 동일」 근거에는 미확인 반대 가설이 있다** (2026-09-13, 리포트 66 · `#623`).
`.2` 의 codex 세션 기록은 **첫 시도 시각에만** 있고 재시도 시각엔 0건이었다 — 세션 1 재시도가
codex 를 다시 돌리지 않고 **첫 시도의 `out.txt` 를 다시 읽은 것**일 수 있다(가설 · 미확인). 맞다면
실제로 쓴 것은 첫 시도 2번 ≈ 39만이고, 「결정적 거절이라 출력이 글자까지 같다」 는 근거가 아니다.
다만 후속 실물이 첫 시도에 정상 완료돼 일부러 재현할 실익이 없다는 사용자 결정으로 `#623`은
**미확인인 채 추적 종료**했다. 이 가설을 `#615`나 재시도 구조 변경의 근거로 쓰지 않는다.

신호는 둘 다 손에 있다 — 출력에 `RESULT: BLOCKED` + 파일 변경 0, 그리고 **직전 시도와 출력이
동일**. 지시문 수정으로 이 원인은 막혔지만 **갈래가 없으니 다음 거절도 3번 태운다.**

[주의] 원인이 조각 기록(`.md`)·레드마인에는 안 간다 — 저널에만 있다. 요청자는 층1 얘기만
받는다(`#399` 와 같은 결). `#391` 이 고쳤다던 오독이 **다른 자리에서 재발했다.**

## 11. 배운 것

1. 🔴 **배달물은 코드다.** 문서 한 줄이 워커 6회 시도를 태웠다. `AGENTS.md` 를 「문서」로
   보고 검증 대상에서 뺀 것이 이 사고의 뿌리다.
2. 🔴 **원천은 「매번 나가는 것」에 있다.** 배달물·설정·문서는 상태이고 뒤처질 수 있다.
   지시문은 파견마다 새로 만들어져 나간다 — 못을 박을 자리는 거기다.
3. **로그는 있었는데 안 읽었다.** 원인은 첫 시도부터 저널에 평문으로 있었다. 사람이
   워커에 SSH 로 들어가 `out.txt` 를 읽고서야 나왔다 — **기록의 존재와 도달은 다르다.**
4. **주석으로 적은 계약은 계약이 아니다.** 「같은 글자여야 한다」가 주석이라 갈릴 수 있었다.
