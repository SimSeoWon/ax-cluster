# 72 — 훅 배선을 세션 cwd 에서 떼어냈다: 주석의 전제 하나가 프롬프트 5회를 삼켰다

2026-09-20 · Redmine `#648`(신규) · 커밋 `fc4114f`·`831662a` · 세 클론 동기 · 네 대 배달

## 1. 발단 — `.33` 이 보고서를 써서 올렸다

사용자가 `.33` 세션이 작성한 문제 보고서를 마스터로 가져왔다. 요지 둘:

    문제 1  UserPromptSubmit 훅이 프롬프트를 5회 차단·소실시켰다 (11:23~11:25)
    문제 2  코드 요청에서 「온톨로지·RAG 선행」 절차를 건너뛰었다

`.33` 은 자기 `settings.json` 의 훅 명령 4개를 절대경로로 **임시 수정**해 두고,
*"마스터 배달 시 상대경로로 되돌아갈 수 있습니다"* 라며 마스터 측 요청 3건을 붙였다.

## 2. 대조 — 맞은 것 · 틀린 것 · 더 있는 것

### ⑴ 원천은 주석이 스스로 말하고 있었다

`master/client/bundle.py hook_command_for` 는 상대경로를 **의도적으로** 박고 있었다:

    [주의] 경로는 **상대·슬래시**다 — `.mcp.json` args 와 같은 근거로, 훅의 cwd 는 체크아웃
    루트다. 절대경로를 박으면 체크아웃이 옮겨질 때 조용히 죽는다.

🔴 **그 전제가 틀렸다.** 훅의 cwd 는 **세션의 현재 작업 디렉터리**이고, 세션 도중에도 움직인다.
같은 전제가 `mcp_entry_for`(`bundle.py:981`)에도 그대로 있다.

### ⑵ 정정 — 요청 ③ (fail-open) 은 이미 그렇다

`.33` 은 *"훅이 스스로 실패할 때 프롬프트를 막지 않도록"* 을 요청했다. **이미 그렇다.**
`pending_works.py` 에 `sys.exit` 는 **0건**이고, `_load_client` 실패도 한 줄 찍고 `return` 이다.
exit 2 를 낸 것은 훅이 아니라 **파일을 못 연 파이썬 인터프리터**다.

[중요] 여기서 래퍼(`py … || exit 0`)를 씌웠다면 **원인이 아닌 곳을 덮고** 진짜 원인은
다음에 다른 모양으로 다시 나왔을 것이다. 고장난 자리는 **부르는 명령**이었다.

### ⑶ 확대 — cwd 의존은 훅 3개 전부였다

셋 다 payload 의 `data["cwd"]` 로 `.ax/lib` 를 찾고 있었다.

| 훅 | 하위 폴더 cwd 에서 |
|---|---|
| `pending_works.py` | `[분산 작업] 점검 못 함` — `.33` 의 짐작대로 |
| `domain_hint.py` | 도메인 힌트 침묵 |
| `work_completion.py` | 🔴 **엉뚱한 `Source/NS/.ax/work-notices`** 에 완주 고지를 쓴다 — ⑹ `asyncRewake` 깨우기가 그 자리를 안 본다 |

**보고서에 없던 것은 셋째다.** 훅 하나를 고치러 들어갔다가 정본 ⑹ 경로의 조용한 구멍을 찾았다.

## 3. 🔴 두 번 틀렸고 두 번 다 실측이 잡았다

이 세션의 값은 여기에 있다. **읽어서 세운 가설 둘이 돌려보니 뒤집혔다.**

### 오진 ① 「입구는 둘이다」

첫 커밋(`fc4114f`)에 *"하위 폴더에서 **여는** 것도 같은 자리를 밟는다"* 라고 적었다.
근거는 내가 그 입구로 재현했다는 것이었는데, **그 재현은 `--settings` 로 훅을 명시해 넣은
것**이었다. 배달 뒤 자연 상태로 쟀다:

    루트에서 연 세션        훅이 실린다 — 훅이 찍은 `[에디터 MCP]` 줄이 모델에 그대로 들어갔다
    하위 폴더에서 연 세션    **훅이 하나도 안 실린다** — 부모의 `.claude/settings.json` 을 안 읽는다

**실제 입구는 세션 도중의 `cd` 하나다.** `.33` 에서 그것을 옮긴 것도 사람이 아니라 모델이었다
(Bash `cd …\Source\NS` 11:22:55 → **32초 뒤** 첫 차단 11:23:24 · 그 전엔 실패 0).

### 오진 ② 「그 세션엔 RAG 도구가 없었다」

오진 ①이 이것을 무너뜨린다. **그 세션은 훅이 실려서 실패했다 → 루트에서 시작했다 →
`ax-client` 는 붙어 있었다.** 나는 「하위 폴더 = MCP 승인 밖」(이것 자체는 실측이다)과
「그 세션이 하위 폴더에 있었다」를 한 줄로 엮어 **문제 2 를 배선 탓으로 돌렸다.**

    Source\NS 에서   ax-client - ⏸ Pending approval     ← 「여는」 경우에만 해당
    루트에서         ax-client - √ Connected            ← 그 세션이 있던 자리

그래서 **문제 2 는 `.33` 보고서가 적은 그대로다** — 도구는 있었고(deferred 라 `ToolSearch`
필요) 선행 절차를 건너뛴 것이다. 마스터가 고칠 배선 결함이 아니다.
[주의] NS 온톨로지 0건도 원인이 아니다 — `NS/context/` 73건 + `vector_db`·`bm25.db` 로
`search_context` 는 도메인 없이 돈다(`.33` 이 관련 문서 5건을 받은 것이 그 증거다).

**두 오진의 공통 모양**: 한 번 잰 사실을 **안 잰 상황에까지 확장**했다. 기억
`verify-by-running-not-reading` 이 지목한 부류이고, 이번엔 그 규칙이 실제로 잡아냈다.
