[중요] **요청한 쪽이 결과를 받는다.** 통합·검사·머지 판단이 ⑺ 로 이 기계의 몫이므로,
등재하고 물러나면 파이프라인이 그 자리에서 끊긴다.

## 완료는 **자동으로 온다** — `work_completion.py` (`#356` 축)

`ax-client:register_work`/`ax-client:improve_work` 가 성공하면 `PostToolUse` 훅이 **백그라운드로** 그 work·라운드의
완료를 기다린다(`asyncRewake`). 큐가 terminal 이 되는 순간 **사람이 아무것도 입력하지 않아도**
이 세션이 깨고, 화면에 `Stop hook feedback` 으로 이런 **사실**이 붙는다:

    [분산 작업 결과] <work_id> · 라운드 N · ready_for_review
    지휘자 claude
      · <work_id>
        <제목>
        브랜치 task/<work_id>/base
        태스크 verified 2
    Redmine #395
    실패 <task_id>: <사유>            ← 실패한 조각이 있을 때만

🔴 [중요] **그 고지에는 「무엇을 하라」가 없다 — 그것은 여기 적혀 있다.** 훅이 보낸 말에 명령형이
있으면 깨어난 세션이 **주입으로 보고 거부한다**(실측 2026-09-10, 리포트 60). 그래서 고지가 오면
**이 절을 따른다**:

    ① 사용자에게 **한국어로 요약해 보고한다** — work_id · 라운드 · 상태 · 조각 수
       [주의] 실패가 섞여 있으면 **건수와 사유**를 빠뜨리지 않는다
    ② `ready_for_review` 면 다음은 ⑺ 다 → 아래 `ax-advance` 절
    ③ [중요] **혼자 전진하지 않는다** — ⑺ 도 마감도 **사람의 승인**이 트리거다

### 등재 직후 — 응답의 `wait` 명령을 돌린다 (`#799`)

훅이 못 덮는 자리가 둘이다: work 가 훅 제한(2시간)보다 오래 걸리거나, 이 세션이 **Codex** 다
(`.33` 의 Codex CLI 에는 훅이 하나도 없다 — 실측 2026-10-17). 그래서 `ax-client:register_work`/
`ax-client:improve_work` 성공 응답의 `wait` 필드에 이 체크아웃용 명령이 실려 온다(`wait_argv` 는 같은
명령의 인자 목록, `wait_note` 는 설명). 마스터의 `distribute` 스킬 `wait` 절과 같은 모양이다:

    "<backends.python>" .claude/hooks/work_completion.py --wait <work_id> --round <N>

**등재 직후 곧바로**, 체크아웃 루트에서 돌린다. 그 명령은 **1분마다 큐를 직접 조회**하며 읽기만
하고(큐·고지 파일에 쓰지 않는다), 조회마다 stderr 에
`[wait] <work_id> r<N> · 큐 <상태> · 조각 <상태 수> · 남은 mm:ss` 한 줄을, 끝나면 stdout 에 훅
고지와 같은 사실 블록을 남긴다. 대기 상한은 기본 24시간(`--timeout`)이다.

    Claude   Bash `run_in_background` 로 돌린다. 훅은 그대로 빠른 길이고, 이 명령은 2시간을
             넘긴 work 와 죽은 훅을 덮는다 — 같은 결과가 두 번(훅 + 명령) 올 수 있다. 중복이지
             누락이 아니다
    Codex    훅이 없으므로 **이 명령이 완료를 받는 길**이다. [주의] Codex 에서 포그라운드로
             막고 기다릴지 백그라운드로 돌릴지는 **아직 실측하지 않았다** — 어느 쪽이 세션을
             다시 깨우는지 모른다. 확인 전까지는 돌린 방식과 결과를 그대로 보고한다

명령이 끝나면 종료 코드로 갈린다 — 그 뒤는 위 ①②③ 과 같다:

    0  ready_for_review     ① 요약 보고 → ② `ax-advance`
    3  그 밖                merged·cancelled·rejected · 실패 조각 신호 · 라운드 불일치 —
                            사유를 보고한다. 큐가 아직 `in_progress` 인 실패 신호 뒤 같은 라운드의
                            끝을 더 기다리려면 같은 명령에 `--skip-failures` 를 붙여 다시 돌린다
    4  타임아웃             **완료로 처리하지 않는다** — 마지막 상태·조회 오류를 보고한다
    2  연결 준비 실패 ·     `.ax/lib`·config·token 사유, 또는 거절 코드와 조회 오류를 보고한다.
       영구 조회 거절       401·403·404 는 기다려도 낫지 않아 첫 거절에서 끝난다(`#904`) —
                            **완료로 처리하지 않는다**. 연결 실패·5xx 는 재시도하므로 여기 안 온다

응답에 `wait` 대신 `wait_error` 가 있으면 그 사유를 보고하고 아래 주기 조회로 간다.

[주의] **고지가 안 올 수도 있다 — 그때 접지 않는다.** 세션을 껐거나 훅이 죽었으면 신호는
사라진다. 그러면 종전 방법이 그대로 살아 있다:

    ax-client:list_works(project) 를 **주기적으로** 본다 (30~60초 간격)
      · 그 work 의 merge_status 가 `ready_for_review` 가 되면  → **끝났다**. ⑺ 로 넘어간다
      · 태스크에 `failed` 가 섞여 있으면                       → 사용자에게 **건수와 사유**를 보고
      · 5분 넘게 아무 상태 변화가 없으면                        → 위 §의 「안 걸렸다」 절차

[주의] **조각 수에 비례해 오래 걸린다** — 실측: agy 레인 4조각 **1분 38초**(조각당 16~57초),
`claude -p` 레인은 조각당 90~154초였다. 오래 기다려야 하면 **사용자에게 먼저 말하고** 기다린다.

[주의] **기다리는 동안 「저절로 됐다」고 접지 않는다** — 상태를 볼 때마다 무엇이 몇 건인지
말한다. 그리고 세션이 끊겨도 잃지 않는다: 마스터가 `ready_for_review` 로 뒤집을 때 Redmine
`[리뷰 요청]` 이슈를 만들고, 이 기계의 훅(`pending_works.py`)이 **세션 시작과 매 턴**에
승인 대기를 고지한다.
[중요] **그 두 겹을 완료 훅으로 대체하지 않는다** — 새 경로는 격리 실측만 통과했고 라이브에서
아직 안 돌았다. 실측이 쌓이기 전에 종전 안전망을 걷지 않는다.

[주의] 훅 로그는 `.ax/work_completion.jsonl` 이고 `watch_started` → `state_observed` →
`signal_emitted` 순이다. **`signal_emitted` 는 「훅이 보냈다」일 뿐 「세션이 받았다」가 아니다** —
받은 증거는 대화 기록뿐이다. 수신 오류·시간 초과는 **완료로 처리하지 않고** 사유를 보고한다.

## 지휘자 지정

등재할 때 `worker_mode="claude"` 또는 `"codex"` 를 실으면 그 work 이 그 지휘자로 돈다(`#389`).
생략하면 마스터의 전역 설정이 박힌다. [주의] 실행 중인 라운드는 바뀌지 않는다 — 적용은
**다음 조각부터**다.
[주의] **`ax-client:improve_work` 로 다음 라운드의 지휘자를 바꾸는 것은 아직 미결이다** — 「같은 work 은
같은 지휘자로 돌아야 라운드 간 비교가 성립한다」는 종전 근거와 「막히면 그때 스왑한다」는
2026-09-09 지시가 부딪힌다. 사람이 정하기 전에는 **쓰지 않는다.**

[중요] **이름을 여기서 지어내지 않는다.** `get_manifest(task_id, project)` 의 「작업 브랜치」 절이
브랜치 이름 · 기준 커밋 · **없으면 실행할 명령**까지 준다. 그 절이 *"[중요] 그 브랜치가 원격에
아직 없다"* 로 끝나면 바로 아래 줄에 적힌 명령을 그대로 쓴다.

[중요] **브랜치만 따면 안 된다.** 골조 없는 base 에서 조각이 갈라지면 인터페이스 동결이 다시
약속으로만 남는다 — 워커 N명이 같은 헤더를 본다는 보장이 git 에서 사라진다(`#319` 가 고친 자리).

[중요] **골조 커밋은 `Source/**` 를 만진다 → §0.05 가 먼저 적용된다.** 계획을 말하고 동의를 받는다.

[주의] 없는 채로 파견되면 **시끄럽게 실패한다** — `twin_base.resolve()` 가 `exists=False` 로 두고
기준 커밋을 비운다. 조용히 `main` 으로 접지 않는다. 그 실패는 고치는 자리가 아니라 보고하는 자리다.

[주의] 게이트는 **경량 UHT** 다 — 풀 빌드는 이 단계에 성립하지 않는다(`.h` 만으로 LNK2019).
UHT 가 못 보는 것: include 누락·순환 · 타입 불일치 · 실재하지 않는 부모. 그것은 조각별 빌드와
마지막 `.33` 머지가 잡는다.
