## 5. 소 1.3.3 — 온톨로지 LLM 재합성 (중 1.3 의 마지막 LLM 조각)

`master/ontology/` 에 6모듈 신설. 결정적 부분(쓰기·검증·레이어·stale·수집)은 이미 있었고
**LLM 한 겹만** 비어 있었다.

    domain_md   도메인 MD 파싱        contexts  응집 조각화 + .h/.cpp 발췌
    prompt      actions/invariants    parse     응답 파서 + 결정적 필터
    synth       오케스트레이션         __main__  CLI (status·plan·verify·dry·refresh)

### 5.1 🔴 원본 파서를 그대로 옮기면 6/7 도메인이 조용히 빈다

원본 `_SECTION_PATTERNS` 는 6섹션 스키마만 안다. 실물은 **7개 중 1개만** 그 스키마다.
나머지 6개는 `시스템 개요` + `핵심 구현 패턴` + `확장 포인트` 라는 **제3의 사실상 표준**
(원본 `agent_defs.py:132` 가 에이전트에게 그 셋을 읽으라고 지시한다).

그대로 옮겼으면 6개 도메인이 `responsibilities=[]`·`boundary=[]`·`invariants=[]` 로 나오고
**파싱은 "성공" 으로 보고된다.** 실측 대조:

    GlobalEventSystem 서술량 — 원본 파서 322자  →  우리 1,225자 (3.8배)

**섹션을 전부 읽고 아는 것만 골라 쓰되 모르는 섹션은 남긴다.** 그리고 🔴 **없는 정규 섹션을
결과에 적는다**(`missing`) — 결손을 숨기면 다음 세션이 "원래 없나 보다" 로 읽는다.

### 5.2 🔴 프롬프트 예산을 실측으로 정했다

원본 상수(클래스 10 × `.h`3,000 + `.cpp`2,500 = **55KB**)는 **상용 API 전제**다. 우리 노드로
그대로 보내면 리포트 10 §8 의 사고를 반복한다. 그래서 `plan` 명령을 **LLM 0** 으로 먼저 만들고
`/api/generate` 의 `prompt_eval_count` 로 환산비를 쟀다:

| 프롬프트 17,315자 | 토큰 | 환산 | `num_ctx` 8192 여유 |
|---|---|---|---|
| 35B-A3B | 6,070 | 2.85자/tok | 2,122 tok |
| qwen2.5-coder:14b | 6,200 | 2.79자/tok | 1,992 tok |

**출력 여유가 2,000 토큰뿐이라 잘릴 자리였다.** JSON 5~15건에 2,500tok 을 확보하기로 하고
발췌 예산을 **11,000 → 7,000자**로 낮췄다. 전 조각이 **출력여유 3,459tok 이상**으로 들어간다.

### 5.3 🔴 페이로드를 조각내 두 노드에 나눠 던진다 (사용자 지시)

> *"컨텍스트 용량을 줄이진 않지만 페이로드를 분리해서 보내고 그걸 재합성할 수 있는 물리
> 성능이 있잖아."*

정확한 지적이었고 내 설계의 실제 결함을 짚었다. 단일 요청이면
`ProjectAlpha_UiViewManagement` 는 **67개 중 8개만 보이고 59개가 영영 안 보인다.**
**창을 못 늘리는 것과 데이터를 못 보는 것은 다른 문제**이고, 후자는 요청을 나누면 풀린다.

- **응집 순서로 자른다** — `#include` 그래프로 BFS. 이름순으로 자르면 한 액션의 참여자가
  서로 다른 조각으로 흩어져 **어느 조각에서도 안 보인다.** 실제로 `*_Renewal` 위젯 패밀리와
  `UWNDUIPage_*` 계열이 같은 조각에 모였다
- **`allowed` 는 도메인 전체 멤버**로 둔다 — 조각 단위로 좁히면 조각을 가로지르는 액션이
  통째로 버려진다. cross-domain 차단이라는 원래 목적은 그대로 지켜진다
- **레인당 in-flight 1** — 모델 이름이 곧 노드 선택이라, 모델당 스레드 하나면 노드당 1건이다

🔴 **다른 모델을 섞으면 핀이 깨진다.** 두 노드 다 `MAX_LOADED_MODELS=1` 이라 `.2` 에
`gemma3:12b` 를 요청하면 상주 14b 를 쫓아내고 브로커가 다시 올린다(~60초) — **왕복 스래싱**.
그래서 기본값은 **두 노드의 상주 모델**이다.

### 5.5 결정 3가지

- **objects 는 LLM 이 만들지 않는다** — 멤버·파일·레이어는 전부 결정적으로 나온다.
  물으면 있는 답을 지어내게 하는 것이고 틀릴 여지만 는다
- **actions 와 invariants 를 합쳐 부르지 않는다** — 프리필이 절반이 되지만 금지 규칙이
  서로 달라 지시 준수가 나빠진다. 우리의 실측된 실패 모드가 문장력이 아니라 형식 준수다
- **병합은 이름 기준이고, 그게 의미 종합이 아님을 명시한다** — 두 조각이 같은 흐름의
  앞뒤를 각각 보고 다른 이름을 붙이면 **둘 다 남는다.** 그 한계를 아는 채로 두는 것이
  조용히 하나를 버리는 것보다 낫다. 🔴 **대화형 에이전트가 나은 자리가 정확히 여기다**

### 12.4 소 2.3.1 도메인 규범 — **목표 ②가 처음으로 끝까지 돈다**

`master/work/norms.py`. 매니페스트가 규범 자리에 `"_미구현_"` 을 싣던 것을 닫았다.

| | 프롬프트 | 생성된 코드 |
|---|---|---|
| 규범 없음 | 1,251자 | `CurrentTaskIndex`(**헤더에 없다**) · `TaskList` |

그 `return` 이 **`ExecutorTickOnlyWhenRunning` invariant 그대로다**(*"틱은 CurrentState가
Running일 때만"*). 규범이 생성 결과를 바꿨다는 것이 실측으로 나왔다.

🔴 **그러나 환각이 사라지지는 않았다.** 소스와 대조하니:

    CurrentStep                 → 실제 멤버는 `Step`                     (저장소 전체 0건)
    EMissionTaskExecutorState   → 실제 enum 은 `EMissionExecutorState`   (저장소 전체 0건)

**한 글자 차이의 근사 오류**다. 규범은 *무엇을 지킬지*를 주지만 **정확한 철자는 헤더에만
있다.** `docs/3-open-items.md` 의 *"추론 노드에 소스를 실어야 한다"* 가 이제 추측이 아니라
**실측**이고, 지금 가장 실질적인 다음 공백이다. (그리고 층2/층3 게이트가 존재하는 이유이기도

    <체크아웃>/CLAUDE.md            정본 본문 + 🔴 **머신별 AX 관리 블록**
    <홈>/.claude/skills/<이름>/     역할별 스킬

세 가지가 동시에 풀린다 — ⑴ 찾을 일이 없다(상대경로가 모든 머신에서 같다) ⑵ cwd 안이라
`--add-dir` 가 필요 없다(Claude 도구 범위가 cwd 기준, help 원문 *"the current directory"*)
⑶ **`.git/info/exclude`** 로 무시해 워킹트리를 안 더럽힌다. `.gitignore` 가 아닌 이유는
**마스터가 소스 저장소에 push 할 수 없기 때문**이다.

**CLAUDE.md 는 `/init` 으로 한 번 만들어 정본화**했다(226줄). 각 워커가 따로 `/init` 하면
서로 다른 문서가 생겨 지금 고치는 갈라짐이 재현된다. 🔴 그 본문에서 **머신 특정 서술을
걷어냈다** — `/init` 이 마스터 미러 기준으로 *"you cannot build here"* 를 써 놓아
`.2` 에서는 틀린 문장이었다. 머신 차이는 **관리 블록**에만 둔다.

### 14.4 역할 — `driven` 과 `role` 은 다른 축이다

사용자 정리: *"메인 작업 PC는 서버 마스터만 알면 되는 거고, 작업 요청하고 처리하는 것이나
온톨로지 등록 요청 등의 MCP들을 등록하는 것만 할 거고, 워커는 워커만의 내용이 있지 않을까?"*

    driven   닿을 수 있나   ssh | interactive
    role     시켜도 되나    worker | requester

🔴 **`.33` 은 SSH 가 열려 있어도 `requester` 라 `drivable_hosts` 에서 빠진다.** 사람이
편집 중인 트리에 일감을 파견하지 않는다. 스킬도 갈린다 — worker 는 `ax-work`,
requester 는 `ax-request`·`ax-ontology`.

### 14.5 🔴 능력 표의 축을 사용자가 바로잡았다

처음엔 UE5 유무를 앞세워 적었다. 사용자 지적: *"이 기능은 판단의 원천인 소스코드를 기반으로
클로드가 판단하라는 게 주안점인데 왜 .2 머신만 말한 거야?"* — 맞다. **소스 판단은 클론을
가진 모든 워커의 공통이자 본령**이고, UE5 는 그 다음 축(검증 가능 여부)이다.

이제 두 워커가 **같은 첫 문장**을 갖는다:

> 🔴 **소스를 근거로 판단한다** — 체크아웃 전체를 직접 읽고 선언부로 사실을 확인한다
> (**이것이 워커의 본령이고 모든 워커가 동등하다**)

BC-250 에는 *"컴파일·에디터·테스트만 안 된다. 소스 판단·코드 작성은 다른 워커와 똑같다 —
못 하는 것은 **옳음의 최종 판정**뿐"* 이 붙는다. 그리고 능력의 **결과**를 적는다:
`ue5 ❌` 가 아니라 *"층3 검증을 여기서 할 수 없다 → `ue5` 워커의 검증을 거쳐야 한다"*.

### 14.6 🔴 배달 검증이 네 번 사고를 잡았다

| | 무엇이 틀렸나 |
|---|---|
| `.2` 아카이브 이동 | 명령이 **출력 없이 실패** — 상태를 다시 읽어 잡았다 |

전송이 아니라 **되읽어 대조**가 이 넷을 전부 잡았다. 없었으면 **조용히 다른 파일이
배달됐다.**

### 14.7 1인 + N워커 루프 확정 (`docs/8-git-authority.md` §8.4)

사용자가 대화로 확정한 것들:

1. **요청자가 durable `task/<id>` 를 원격에 만든다** — 마스터는 push 를 못 하므로(§2.1)
   push 권한이 있는 사람의 체크아웃이 그 자리다
2. **성공·실패 무관하게 attempt 를 push 한다** — *"안 그러면 실패 처리가 애매해져"*.
   버리면 무엇을 시도했는지 사라지고 피드백 근거도 없다
3. **피드백은 코드 위치에 `[FEEDBACK]` 블록으로 박는다** — 골조의 `[PSEUDO]` 와 같은 자리.
   큐의 텍스트만으로는 워커가 *어디를* 고칠지 모른다. 🔴 **재구현이 아니라 수정**(누적 모델)
4. **durable 은 오래 사는 작업 공간이고 머지는 끝에 사람이 한 번** — 이것이 AgentTest 를
   복잡하게 만들던 압력을 없앤다. `verify_worker.py`(314줄)의 CAS·머지 권한 이전은
   **재설계가 아니라 불필요**해진다
5. **층3 은 요청자가 가장 빠르다** — `.33` 에 UE5 가 있다. ⚠️ 단 **메인 워킹트리에서
   브랜치를 갈아타지 않는다**(`git worktree`). 사람의 미커밋 작업은 되살릴 수 없다
6. **언제든 멈출 수 있다** — 큐에 `cancel` 과 worker directive(화이트리스트·fire-once)가
   **이미 이식돼 있었다.** 🔴 즉시가 아니라 **다음 하트비트**에 멈춘다

**원본 대조**: 3번은 원본이 이미 검증한 형태다(`verifier.py:85` *"worker 브랜치에 feedback
주석을 target_file 상단에 박아 commit + push"* · `verify_worker.py:9~11` *"reject → durable 을
attempt 로 fast-forward(구현 누적) 후 [FEEDBACK] commit … 재구현 아님"*). 그리고 **게이트는
이미 이식돼 있다** — `layer2_verify.py:46` 이 `[PSEUDO]/[FEEDBACK]` 잔재를 검사한다.

매니페스트 소비자가 둘인데 사정이 정반대다:
