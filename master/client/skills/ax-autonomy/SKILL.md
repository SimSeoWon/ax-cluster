# ax-autonomy — 자율성 값을 바꾸고 남은 태스크를 다시 제안한다 (요청자 측)

## 목차

- 개요
- 1. 도구
- 2. 절차
- 3. 이 스킬이 하지 않는 것

## 개요

> 마스터가 생성해 배달한다. **손으로 고치지 말 것** — 다음 배달에 덮인다.
> 일감 `#963` · 일감 흐름은 `ax-issue` 스킬이다.

자율성은 플랜 전체에 걸린 값이다(플랜 시작 표지 `autonomy=`, 없으면 0.5). 값이 태스크 세밀도와 어떻게
대응하는지는 `#948` 이 정한다 — 지금은 값을 기록하고, **남은 태스크를 어떻게 다시 짤지는 사용자와 대화로** 정한다.

## 1. 도구

    ax-client:plan_autonomy(issue_id, value, why, tasks)    값 변경 이력 노트 + 대기 태스크만 다시 짠 제안
    ax-client:plan_set(issue_id, tasks, why, user_answer)   동의 뒤 등록 — 최신 제안과 같은 목록이어야 한다
    ax-client:plan_start(issue_id)                          지금 플랜·자율성 확인(읽기)

## 2. 절차

1. `ax-client:plan_start` 로 지금 플랜을 읽고, 지금 값과 대기 태스크를 사용자에게 보인다.
2. 새 값과, 그 값으로 대기 태스크를 어떻게 다시 짤지(쪼갤지·묶을지·그대로 둘지)를 사용자와 정한다.
   모호하거나 정보가 없으면 묻는다 — 추측으로 채우지 않는다.
3. `ax-client:plan_autonomy(issue_id, value, why, tasks=다시 짠 대기 태스크)` — `tasks` 를 비우면 지금 대기 태스크를
   그대로 다시 제안한다. 시작된 태스크와 근거, 체크리스트는 자동으로 옮겨진다.
4. 제안 표(응답의 `tasks` 순서)를 보이고 동의를 받는다. 고치면 3 을 다시 한다.
5. 동의를 받으면 그 목록 그대로 `ax-client:plan_set(…, user_answer=사용자 동의 원문)`.

## 3. 이 스킬이 하지 않는 것

- 값↔세밀도 대응을 스스로 정하지 않는다(`#948`).
- 시작된 태스크를 바꾸거나 빼지 않는다 — 서버가 거절한다.
- 동의 없이 등록하지 않는다 — `user_answer` 가 비면 거절된다.
