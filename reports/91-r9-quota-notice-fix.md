# 91. R9 한도 소진 안내 수정

2026-10-04 · Codex 마스터 · 사용자 R9 검증·수정·로컬 서브 에이전트·드라이런·커밋/푸시/배포 및 리뷰 상태 변경 승인.

## 결함과 수정

R9는 `32a1e0bfe1093501cdc0672fd98ab372bced5efe`의 리뷰이며 지적은 한 건이다.
현재 `commit_task`에서 한도 소진 시에도 상한 안내 분기로 들어가 pending 복귀 안내와
종결 안내를 함께 남겼다. 첫 시도에서도 `attempt 1 ≥ 3`이라는 잘못된 문구가 재현됐다.
실제 제출은 quota_exhausted였고 격리 임시 큐의 pending 복귀·워커 5시간 차단은 정상이다.

사용자가 로컬 방식을 선택했다. 구현 에이전트는 `master/work/infer.py`의 상한 안내 조건에
`not quota_hit`을 추가하고 `master/test_infer.py`에 실제 commit_task 경로 회귀를 추가했다.
한도 첫/상한 시도, 일반 상한, 환경 실패, 출력 반복의 안내·로그·제출 사유를 비교한다.
워커 실행·계측·고지·API는 대역으로 격리했다. 독립 검토가 신규 31건을 직접 실행했다.

## 검증과 한계

- 메인 직접 infer 154/154, revise 64/64, 독립 신규 회귀 31/31 및 diff 검사 통과.
- 전체 드라이런 명시 목록 12모듈 **591건** 통과
  (14+77+32+7+36+51+64+103+27+11+154+15).
- 기본 샌드박스의 source_scope 28/32 실패는 기존 권한 제약과 같은 경로다.
  승인된 `/tmp/ax-r9-integration-dryrun.sh`의 동일 전체 검사 재실행은 12모듈 모두 통과했다.
  운영 코드나 권한 설정은 변경하지 않았다.
- 추가 메모리 역검증은 복사 globals에 mock이 적용되지 않아 예상 실패 건수가 달라졌다.
  실패를 보고하고 중단했으며 이 결과는 성공 증거에서 제외했다.
- 배포 준비 읽기에서 존재하지 않는 파일 경로를 지정한 조회가 실패해 중단했다.
  사용자 후속 지시로 상태 변경·소스 업로드와 승인된 배포를 재개한다.
