# 분류: 버그

`#960` 착수 전 인터뷰에서 「버그」로 확정된 일감의 단계별 안내다. 단계 순서와 건너뜀은
머리말 `steps` 와 `master/interview.py` 가 정한다 — 이 본문은 각 단계에서 **무엇을 찾고 무엇을 묻는지**다.
모든 단계는 결과 제시 → 사용자 확인 → 단계 노트로 끝난다.

## 조사 (investigate)

- 언제부터 발생했는가 — 처음 관측된 시각·일감·로그 줄.
- 이번에 생겼다면 최근 작업한 Redmine 일감 중 관련된 것(재료의 최근 완료 일감 목록에서 고른다).
- 원래 의도된 동작은 무엇이었나 — 그 동작을 정한 일감·문서·커밋(why).
- 지금 실제로 어떻게 동작하나 — 관련 코드 경로(how). 합성 문서는 어느 파일을 볼지까지만 쓴다.
- 사용자에게 확인: 「원인 후보가 이 일감·커밋이 맞나」 · 「의도된 동작이 이것이 맞나」.

## 명세 (specify)

- 사용자 언어로 목표를 되말하고(역복창) 고친 뒤의 동작을 확정한다.
- 완료 조건에는 **재현이 사라졌음을 보이는 검사**가 들어가야 한다.

## 재현 (reproduce)

- 고치기 전에 증상을 직접 재현한다 — 명령과 출력 줄 그대로.
- 재현이 안 되면 그 사실과 시도한 조건을 결과로 보이고 사용자에게 묻는다(추측으로 넘어가지 않는다).

## 파급 측정 (impact)

- 고칠 자리를 쓰는 호출자·인접 모듈·상주 서비스(재기동 필요 여부)·배달 대상.
- 「안전하다」는 근거는 하나라도 실제로 돌려 확인한 것을 쓴다.
