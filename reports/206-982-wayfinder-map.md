## 2. 인터뷰에서 정해진 것 (사용자 결정)

- 맵 티켓은 **실작업을 하지 않는다**. 실작업은 발번된 노드 일감을 기존 플로우로 처리하라고 따로 지시한다.
- 기존 분산 작업(work)과는 출발점이 다르다. work 는 **설계서를 미리 다 만든 뒤** 정적으로 배분한다. 맵은 모호하거나 미지인 노드에서 출발해 노드가 끝날 때마다 자란다.
- 노드 타입은 셋이다. 프리필(분석: 할 것·모르는 것) · 작업(기존 플로우) · 검증(실제 적용된 노드들을 묶어 본다).
  처음 나온 다섯 단계 안은 사용자가 철회했다. 「일감 안쪽에서 단일 선형 플로우가 이미 다섯 단계를 처리한다」는 이유다.
- 마감은 노드 타입이 아니다. **Root 를 닫을 때의 사람 게이트**다.
- 새 노드는 제안 → 동의 → 등록 순서다. 등록 전에 **모든 층의 형제**와 중복을 견준다. 재검증은 B다: 붙는 자리에서 Root 까지 올라갔다 내려오며 모든 층 형제의 완료물을 다시 본다.
- 발동은 A다. 분류가 신규 기능이면 분류 직후 「웨이파인더로 진행할까요?」를 묻는다. 판단이 끼지 않는 조건이다.
- 비범위(추후): Root 원격 브랜치·노드 서브 브랜치 · `.33` 언리얼 표면 · 노드 전용 새 파견 경로 · Git 아카이빙 게이트 · 간트.

## 3. 실물이 잡은 것 — 단위 검사 528건이 모두 통과한 뒤였다

단위 검사의 Redmine 대역은 아래 두 제약을 몰랐다. 시험 Root #985 에 실제로 맵을 만들자 처음 드러났다.

1. **조상-후손 사이 `blocks` 를 422 로 거절한다.** 메시지는 「일감은 하위 일감과 연결할 수 없습니다」(#986→#987)였다.
   처음에는 「조상 선행은 지도에만 둔다」로 고쳤다(`b50f99e`, 사용자 선택 A).
2. **열린 하위 일감이 있는 부모는 닫히지 않는다.** #990 에 「완료」를 요청했는데 실제 상태는 「신규」로 남았다(자식 #991).
   파생 트리에서는 부모가 먼저 끝나야 하므로 이것이 근본 충돌이다. Redmine 의 부모-자식은 「범위가 품는다」는 뜻이고 「앞선 일에서 파생됐다」는 뜻이 아니다.
   → **Redmine 에서는 모든 노드를 Root 직속으로 둔다. 파생 트리는 지도 「부모」 칸에만 둔다**(`97660e0`, 사용자 선택 A).
   선행은 전부 형제 사이 `blocks` 로 걸린다. 1의 처리는 필요 없어져 되돌렸고, 대역이 422 를 재현하는 것만 남겼다.

부수 관측: `blocks` 로 막힌 일감은 막는 일감이 닫혀야 닫힌다(#993 이 #992 보다 먼저 닫히지 않았다). 맵의 선행 의미와 같은 방향이다.
