### 1.2 아키텍처 — 루프가 두 개인데 하나만 닫혔다

**① 작업 루프 — 서버측 완결, 실측 증명:**

```
register_work(1.5s) ─ 매니페스트 1회 수집(RAG 5건+골조+동결계약)
     ↓
get_code(20.1s) ─ 브로커→14b 생성(무료) → 펜스 제거 → 층2 agy(상용) → APPROVE
     ↓
작업장 ─ 적용·빌드·테스트·커밋 (여기부터는 작업장 몫 — 미구현)
```

실측 산출물: 동결 시그니처(`virtual void Init() override`)를 지킨 UE5 C++ 가
`APPROVE(backend=agy)` 로 나왔다. **모토(무료=대량 생산, 상용=검증만)가 코드 구조로 굳었다.**

**② 트윈 갱신 루프 — 열려 있다:**

```
작업장 push → [Gitea 훅  미설치] → 스풀(있음, 항상 비어 있음) → [소비자 ] → 재색인(수동)
```

지금은 커밋해도 마스터가 모른다. 안 닫으면 **매니페스트가 점점 낡은 코드를 근거로 삼는다** —
검색이 좋아질수록 오히려 위험해지는 종류의 구멍이다.

## 3. 유용한 점 — 재사용 가치가 있는 패턴

**① fail-closed 가 전 층에 동일하게 걸려 있다.**
인증(토큰 없으면 기동 거부) · 층2(verdict 없으면 차단) · 층3(로그 계약 미충족=실패) ·
더티 체크(확인 실패=차단) · 세대 포인터(재색인 실패 시 옛 세대 보존) · dispatch(`ok` 아니면
미인계) · provision(pull "성공" 을 `/api/tags` 로 재검증). **새 코드가 기존 규약을 그대로
따라가므로 예측 가능하다** — 이게 이 저장소의 실질적 아키텍처다.

**② 결정마다 실측 근거가 붙어 있다.**
`.33` 상주 금지(여유 VRAM 7.6GiB < 14b 9.0GB), 층3 로그 판정(ssh 종료 코드 양방향 오류 측정),
골조의 매니페스트 이동(`task_data` API 미노출 측정). 근거가 코드 주석과 문서에 남아 있어
**다음 세션이 재검토 대신 인용**할 수 있다.

**③ 매니페스트 = 마스터→작업장 단일 텍스트 채널.**
골조·동결 계약·RAG 히트가 한 문서. 로컬 LLM(도구 호출 불가)이 검색 0회로 grounding 을 받고,
"1회 수집 → 다회 소비" 라 토큰이 라운드마다 늘지 않는다. **결손을 본문에 명시**하는 것까지가
패턴이다 — 빈 섹션을 감추면 다음 세션이 버그로 오해한다.

**④ 보유(want)와 상주(resident)의 분리.**
`/api/tags` 와 `/api/ps` 는 다른 질문이다. `want=[CODER] + resident=False` 가
"디스크에는 두되 VRAM 에는 안 올린다" 를 선언으로 표현하고, check 가 위반을 잡는다.
**공유 GPU 머신이 있는 환경 어디서나 쓸 수 있는 패턴**이다.

**⑤ 개수 단언이 있는 테스트.**
MCP 도구를 2종 추가하자 `test_mcp_servers` 의 "도구 8종" 단언이 깨졌다 — 의도된 실패다.
단언이 없었으면 도구가 조용히 사라져도 몰랐을 것이다.

**⑥ 이식은 복사가 아니라 대조.**
원본 워크플로우 9,690줄 중 이미 다르게 가진 것(층2/층3 · 큐 상태기계)을 식별해 안 옮겼고,
`verify_worker.py` 는 "권위가 상용 verdict → 층3 으로 이전되므로 재설계 대상" 으로 분류했다.
§4.7 복구 지도가 그 대조표다 — **다음 세션이 같은 조사를 반복하지 않는다.**

## 6. [중요] AgentTest 백포트 후보 — 협업 관점 (기록만, 적용 안 함)

> AgentTest 는 참조 전용이다. 아래는 **그쪽 코드를 실제로 열어 확인한 것**과 우리가 실측으로
> 배운 것 중, **팀(협업) 환경이라 오히려 더 아픈** 항목만 골랐다. 우선순위순.

### 6.1 [중요] `_slugify` 한글 버그 — **원본에 동일 코드로 존재함을 확인했다**

`mcp/task_queue/persistence.py:91~102` 가 우리가 고치기 전 코드와 **글자까지 같다.**
비-ASCII 를 버리고 빈 결과를 `"work"` 로 폴백하는데, slug 가 중복 검출 키다.

**협업 영향이 우리보다 크다**: 한국어 팀이 쓰는 순간 **팀원 B 의 일감이 팀원 A 의 일감과
"중복" 으로 거부**된다. 영문 제목 관습 덕에 지금까지 안 터졌을 뿐이다.
수정안은 우리 커밋 `45235a6` — 버려진 내용이 있으면 정규화 원문의 md5 8자를 붙인다.
같은 제목은 여전히 충돌(중복 검출 유지), 순수 ASCII 는 그대로(기존 work id 호환).

### 6.2 [중요] 서비스 무인증 — 원본 큐에 Authorization 검사가 없음을 확인했다

`mcp/task_queue/server.py` 에 인증 코드가 0줄이다. 1인 LAN 에서는 위험 수용이 가능했지만
**팀 환경은 정반대다** — 팀원 누구의 PC 가 악성코드에 물려도 큐를 통째로 조작할 수 있고,
큐가 조작되면 **워커들이 그 지시로 코드를 쓴다.** 우리 `master/auth.py`(120줄, ASGI 미들웨어,
fail-closed, `/livez` 만 개방)는 프레임워크 무관이라 거의 그대로 이식 가능하다.

### 6.3 더티 체크 — 자동화가 팀원의 미커밋 작업을 날리지 않게

우리 `workshop_check.py`: 파견 전에 `git status --porcelain` 을 보고 **추적 파일 변경이
있으면 차단**(untracked 는 통과), 확인 실패도 차단. 오늘 실전에서 사용자가 편집 중이던
`BP_MissionPrefab_C_0.uasset` 을 잡아 파견을 막았다.

AgentTest 워커는 팀원 PC 의 체크아웃에서 브랜치를 전환한다 — **점심 먹으러 간 팀원의
미커밋 블루프린트**가 정확히 이 시나리오다. uasset 은 바이너리라 되살릴 수도 없다.
협업 환경일수록 이 게이트의 값어치가 크다.

### 6.4 "됐다" 검증 패턴 — 위임 결과는 산출물로 재확인

agy 가 `status:"SUCCESS"` 를 주고 파일을 안 쓴 사건(리포트 04)에서 나온 규칙을
우리는 코드에 박았다: provision.pull 은 성공 응답 후 `/api/tags` 를 다시 읽고, 가이드 배달은
바이트 수를 대조한다. AgentTest 는 워커·검증자·합성기가 **서로의 보고를 믿는 지점이 훨씬
많다** — 각 인계 지점에 "산출물 재확인 한 줄" 을 넣는 것이 팀 규모에서 회귀를 크게 줄인다.

### 6.5 매니페스트 결손의 투명화

원본 `cluster_context.py` 는 베스트에포트로 **조용히** 빈/부분 매니페스트를 만든다.
우리는 결손 사유를 본문에 적는다("검색 실패: …", "이 태스크는 규범 grounding 없이 진행된다").
협업에서는 이게 더 중요하다 — **매니페스트를 만든 사람과 소비하는 워커가 다른 사람**이라,
결손이 안 보이면 워커는 "원래 컨텍스트가 이만큼인가 보다" 하고 그냥 짠다.

### 6.6 보유/상주 분리 선언 (`want` + `resident`)

팀원 GPU PC 를 "모델은 받아두되 상주는 금지" 로 선언하고 위반을 자동 검출하는 패턴(§3-④).
팀 환경에서는 **개인 PC 의 VRAM 을 인프라가 잠식하는 문제**가 사람 간 갈등이 되므로,
선언+검출이 구두 약속보다 낫다.

### 6.7 소소하지만: 개수 단언 테스트 · 중간 펜스 보존

- MCP 도구/스킬 목록에 **개수 단언**을 두면 등록 누락·유실이 조용히 지나가지 않는다 (§3-⑤).
- 펜스 제거를 프롬프트 지시(원본 방식)에만 맡기지 말고 파이프라인에서 벗기되, **본문 중간
  펜스는 남겨서** 검증 층이 "여러 파일/설명 섞임" 신호로 쓰게 할 것 (`generate.py:_FENCE`).

### 백포트하지 않아도 되는 것 (우리 환경 특수)

- 세대 포인터 영속화 — 원본은 상주 데몬이라 해당 없음. **프로세스를 쪼갤 때만** 필요해진다.
- 골조의 매니페스트 이동 — 원본은 서버가 git push 를 하므로 git-carried 가 그대로 맞다.
- 스텁 문서 색인 — 원본은 애초에 안 버렸다. 우리 이식 오류였다.
