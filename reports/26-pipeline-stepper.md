# 26 — #223 파이프라인 단계 스텝퍼 + 재기동 경로 실측

리포트 24 §7 의 결손 셋 중 마지막(③ 단계 뷰)을 닫는다. 착수 조건(소 A #222 + #220 ③-B)은
리포트 25 에서 충족됐다.

## §1 [중요] 그릴 단계를 데이터가 정했다 — 12가 아니라 6

서술상 우리 파이프라인은 12단계다(등록 → 골조 → 분해 → claim → 추론 → collect → 층1 →
적용 → 조각별 빌드 → 커밋 → verify → 머지). 그런데 **태스크 레코드가 증거를 갖는 것은 여섯**뿐이다
(실측 2026-08-19, 라이브 태스크 `420a5c1e` 의 전 필드 확인):

    등록  created                     배정  claimed_at
    실행  note·note_at (심박 위상)      제출  submitted_at
    판정  verified_at + verdict        종결  work.merge_status

마스터 측 단계(분해·collect·층1·적용·커밋)는 **통합자 로그에만 있고 큐에는 없다.**
[중요] **모르는 것을 그리면 그림이 거짓말을 한다** — 그리지 않고, **안 그린다는 사실을 화면 하단에
적었다**("단계는 큐가 기록하는 여섯이다 — 마스터 측 단계는 통합자 로그에만 있어 그리지 않는다").
[주의] 그래서 이 스텝퍼는 「12단계 중 어디」가 아니라 **「큐가 아는 여섯 중 어디」** 다.

## §2 상태 판정 — 추정하지 않는다

네 상태(`done`·`current`·`failed`·`pending`)의 근거는 각각 특정 필드이고, 없으면 `pending` 이다.
「아마 지났을 것」을 done 으로 만들지 않는다.

[중요] **실패의 위치를 구분한다** — 착수 실패(`build-setup`·`infer-setup`)는 **제출에 이르지 못한**
실패이므로 실행에서 끊고, 판정 반려는 실행·제출을 `done` 으로 남긴 뒤 판정에서 끊는다. 둘을 뭉치면
*"빌드는 돌았나?"* 라는 질문에 화면이 답을 못 한다.

## §3 렌더 — 자립형 인라인 SVG, 색 외 신호

#216 의 토폴로지 뷰와 같은 규약: 외부 라이브러리 0, 인라인 SVG, 다크 고정 팔레트.
[중요] **색만으로 의미를 전달하지 않는다** — 라벨(글자) + `<title>`(상태 이름과 시각) + 현재
위치는 고리 하나 더 + **실패는 X 표식**. 원 아래 시·분을 찍어 「언제 그 단계였나」도 읽힌다.
work 당 스텝퍼는 4개까지, 종료된 work 는 1개만 — 끝난 일에 줄줄이 그리면 지금 도는 것이 묻힌다.

## §4 실측

테스트 13건 신규(단계 판정 7 · 렌더 3 · 배선 3), 전체 **3577/3577**.
라이브: 종료된 buildjob work 의 스텝퍼가 여섯 단계 전부 `done` 으로 뜨고 **실제 시각이 붙었다** —
등록 01:10:52 → 배정 01:10:55 → 제출 01:13:05 → 판정 01:18:12.

[주의] **유닛 하나가 새 렌더 때문에 깨졌고 그게 옳았다**: `test_work_section_shows_progress_as_
fraction_never_percent` 가 `%` 부재를 단정했는데 SVG 의 `width="100%"`(속성)에 걸렸다. 막을 것은
**본문에 보이는 숫자 퍼센트**이므로 단정을 `>[^<]*\d+%` 로 정확히 했다 — 규칙을 느슨하게 하지 않고
**표현을 정확하게** 했다.

## §5 [중요] 재기동이 세 번 연속 D-Bus 타임아웃 — 실제 경로는 `sudo -n`

`systemctl restart ax-projects` 가 *"연결 시간 초과 / Method call timed out"* 으로 **3회 연속
실패**했다(같은 세션 앞부분 00:38·01:16 에는 성공했다 — 간헐적이다). 진단: 서비스는 정상 running,
`list-jobs` 비어 있음, dbus active, `busctl status` 응답 정상 → **서비스 문제가 아니라 요청이
polkit/D-Bus 대기에서 멎는 것**. `--no-block` 도 같은 타임아웃.

해결: **이 용도로 이미 등록된 NOPASSWD 항목이 있었다** —
`sudo -n /usr/bin/systemctl restart ax-task-queue|ax-broker|ax-projects|ax-indexer.service|ax-status.timer`.
그 경로로 즉시 재기동됐다(01:16:45 → 02:03:09).

[중요] **재기동 성공 판정은 종료코드가 아니라 `ExecMainStartTimestamp` 다** — #216 에서 이미
「조용히 안 먹은」 실측이 있었고, 이번에는 **명령이 실패를 말하는데도 서비스는 계속 살아 있어**
상태만 보면 정상으로 보였다. 시각 대조가 그 둘을 갈랐다.

  트윈에 남겨야** 한다 — 지금은 통합자 로그에만 있다. 그것을 만들면 스텝퍼가 12단계가 된다
