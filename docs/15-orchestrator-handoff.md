## 15.1 목적과 범위

마스터 `.57`에서 진행하던 AX 인프라 작업을 다른 도구의 새 세션이 이어받는다.
사용자가 Claude 또는 Codex로 전환하면, 새 지휘자가 사용자 결정·변경 파일·검증 결과·
남은 작업을 확인하고 서브 에이전트를 다시 배정할 수 있어야 한다.

이번 계획의 첫 구현은 **수동 교대와 양방향 실증**이다. 자동 한도 감지·CLI 선택 실행기는
#368의 후속 검토 범위다. `.33` 게임 작업 진입점, AX 큐/브로커/파견 구조, 작성 레인 순서는
이번 계획 때문에 변경하지 않는다. 서브 에이전트와 원격 AX 워커는 별개의 실행 주체다.

## 15.2 현재 확인된 출발점

- 공용 계획의 색인은 `PLAN.md`, 상세 설계는 `docs/`, 작업 보고서는 `reports/`에 있다.
- `/home/sim/CLAUDE.md`는 `machines/sim-desktop.md`를 가리키는 심볼릭 링크다.
- Claude의 개인 기억은 `/home/sim/.claude/projects/-home-sim/memory/`에 있다.
  필요한 사용자 결정만 선별해 공용 문서로 옮긴다. 대화·설정 전체를 복제하지 않는다.
- 이번 확인에서 `/home/sim/.claude/plans`는 없었다. 공용 플랜을 도구 전용 디렉토리에 두지 않는다.
- `master/work/lanes.py`의 기본 작성 체인은 `codex → agy → qwen2.5-coder:14b`다.
  이것은 본문 작성 경로이고, 대화형 지휘자의 인수인계가 구현됐다는 증거는 아니다.
- 서브 에이전트 대화/실행 ID의 도구 간 이전은 전제하지 않는다. 결과 파일과 요약으로 인계한다.
- 원격 접근·서비스 조작·MCP·훅의 Codex 동등성은 아직 실증하지 않았다.

## 15.3 공용 문서와 도구별 진입점

구현 시 다음 구성을 적용한다. 아래 추가 파일과 연결은 아직 구현 전이다.

| 위치 | 용도 |
|---|---|
| `docs/15-orchestrator-handoff.md` | 교대 설계와 검증 방법 — 이 문서 |
| `docs/orchestrator-handoff.md` | 현재 작업의 짧은 인수인계 기록, 한 벌만 유지 |
| `docs/orchestrator-rules.md` | 두 지휘자가 함께 지키는 운영 규칙과 원문 근거 |
| 기존 `machines/sim-desktop.md` | Claude 진입점에 공용 문서 링크 연결, 기존 심볼릭 링크 보존 |
| Codex의 적용 범위에 맞는 `AGENTS.md` | 실제 로드 위치를 확인한 뒤 공용 문서 링크 연결 |

인수인계는 전체 기억을 반복해서 싣지 않고 관련 이슈·설계·로그를 가리킨다.
인증 키·토큰·비밀번호는 기록하지 않는다. 접근 방법과 자격 정보의 위치만 적는다.

## 15.4 교대 절차

1. **작업 중 체크포인트**: 의미 있는 변경·검증이 끝날 때 기록을 갱신한다.
   한도 소진 직전에만 쓰면 갑작스러운 종료를 복구할 수 없다.
2. **넘기는 지휘자**: 새 위임을 멈추고 서브 에이전트별 결과를 회수한다.
   실행 중이면 담당 파일·작업·프로세스·로그 위치와 계속 실행 여부를 적는다.
   작업 트리의 미커밋 변경과 진행 중인 테스트도 보존한다. 교대를 위해 강제 종료하거나
   커밋·푸시·브랜치 삭제를 자동 수행하지 않는다.
3. **사용자가 전환**: 같은 작업의 변경을 지휘하는 세션은 한 번에 하나다.
   양쪽 세션이 열려 있어도 이전 세션은 변경/위임을 재개하지 않는다.
   초기에는 기록과 사용자 전환으로 소유권을 관리한다. 파일 기록을 실제 잠금으로 부르지 않는다.
4. **받는 지휘자**: 현재 HEAD·dirty diff·관련 이슈·프로세스/로그를 기록과 대조한다.
   기록의 완료 주장을 그대로 믿고 작업을 중복 실행하지 않는다.
   이전 세션이나 서브 에이전트가 여전히 쓰는지 불명확하면 읽기 조사만 하고 충돌부터 해소한다.
5. **재개**: 기존 목표와 승인 범위에서 이어서 처리한다. 독립된 작업은 새 서브 에이전트에
   담당 파일과 완료 조건을 지정해 맡기고, 지휘자가 검토·통합한다.

예고 없는 한도 소진/종료에서는 마지막 체크포인트와 실제 상태를 함께 복원한다.
돌고 있는 AX 서비스나 원격 작업이 대화 세션과 함께 멈췄다고 가정하지 않는다.

기존 사용자 승인은 대상·범위·근거와 함께 전달한다. 도구 교대만으로 승인을 넓히거나
다시 요구하지 않는다. 미승인인 ⑺ 전진·finalize, `awaiting_resume`의 사람 재개 조건은
그대로 유지한다. 샌드박스/도구 권한은 각 환경에서 실제로 허용되는지 별도로 확인한다.

## 15.5 인수인계 기록 양식

```markdown
# 현재 AX 작업 인수인계
- 갱신 시각(시간대 포함):
- 지휘 도구 / 세션 식별자(확인 가능할 때):
- 상태: 작업 중 / 교대 준비 / 인계 완료 / 복구 확인 필요
- 관련 Redmine 일감 / 목표:
- 사용자 결정·승인 범위·근거 / 미결 질문:
- 저장소·브랜치·HEAD / 미커밋 파일과 변경 의도:
- 완료한 작업 / 검증 명령·결과·로그:
- 미검증 사항 / 실패·보류 사유:
- 실행 중인 서비스 작업·프로세스·원격 작업 / 로그 위치:
- 서브 에이전트별 담당 파일·진행·산출물·종료 여부:
- 바로 다음 작업:
- 관련 문서 링크:
```

모르는 상태는 `미확인`으로 적는다. 문서에 기록한 지휘자는 실행을 차단하는 잠금이 아니다.

## 15.6 구현 순서와 완료 조건

1. **지침·연결 조사**: Claude 지침/관련 기억/스킬/훅/MCP를 목록화하고 Codex의 실제
   접근 수단과 대조한다. 공통 규칙, 도구별 연결, 미지원 기능을 구분해 근거를 남긴다.
2. **공용 진입점 연결**: 공용 규칙과 인수인계 파일을 만들고 양쪽의 시작 지침에서 찾게 한다.
   새 세션 두 종류에서 같은 사용자 결정과 다음 작업을 읽는지 확인한다.
3. **Claude → Codex 실증**: 작고 되돌릴 수 있는 AX 작업을 넘겨 미커밋 변경·검증 결과·
   다음 작업을 재설명 없이 이어받는지 측정한다. 서브 에이전트 결과 회수도 포함한다.
4. **Codex → Claude 실증**: 같은 방식의 반대 방향 인계와 검토를 수행한다.
5. **중단 복구 실증**: 실제 한도를 소진시키지 않고 예고 없는 종료를 모사한다.
   임시 작업 공간에서 오래된 기록·미커밋 변경·실행 중 작업을 판별하고 중복 변경을 막는지 확인한다.
6. **종결**: 두 방향의 인계 시간, 추가 설명량, 중복 작업 유무, 잃은 변경 유무,
   검증 결과를 보고서와 Redmine에 남긴다. 사용량은 도구가 제공하는 값만 기록하고
   측정 불가 항목은 미측정으로 표시한다. 양방향·중단 복구 실증 전에는 완료로 닫지 않는다.

이번 문서 작성은 계획 수립이다. 공용 진입점 배선, 실제 교대와 자동 전환의 완료를 뜻하지 않는다.
