## 무엇을 하려던 마일스톤이었나

마일스톤 1 이 **파이프를 깔았고 그 안에 흐르는 것을 아무도 만들지 않았다.** 이번은 그
데이터를 만드는 것이었다. 목표는 둘(사용자 확정 2026-08-08):

1. **온톨로지 문서를 자동으로 작성한다** — 커밋마다 컨텍스트 문서 → 관계 그래프 → BM25 →
   최종적으로 **사용자의 수동 명령과 대화형으로 휴리스틱이 포함된** 온톨로지
2. **그 트윈 데이터를 코드 작성 에이전트에게** 관련된 것만 추출해 전달한다

[중요] **목표 ①의 마지막 절이 핵심이었다.** 온톨로지는 전자동이 **아니다** — 자동 승급은
2026-06-01 영구 비활성이고, 미배정 클래스도 *"노출만, 자동 편입 0"* 이다. 휴리스틱은 그
자리를 메우는 **LLM 0 추천기**다. **둘 다 끝까지 관통했다** (소 43/43).

## 산출물 — 4종 (5종이 아니다)

| | 산출물 | 생산자 | LLM |
|---|---|---|---|
| ① | 컨텍스트 문서 (**태그·related_classes·category 포함**) | `context_synth/` | [중요] 예 |
| ② | 관계 그래프 — 상속(tree-sitter) + `#include` | `graph/` | 아니오 |
| ③ | 온톨로지 문서 (도메인 yaml) | `ontology/` + **사람** | [중요] 예 |
| ④ | 시소러스 (`aliases`) | [중요] **사람이 등록** + 인덱스 빌더 | 아니오 |

**태그는 별도 산출물이 아니다** — 합성 프롬프트가 ①의 프론트매터로 쓰게 한다.

```
[트윈이 자라는 길]  커밋 → 컨텍스트 MD + source_commit 스탬프 + 색인 upsert   [중요] LLM
                        → 의존/상속 그래프 증분 · path_sync                   LLM 0
                        → stale 판정 → 온톨로지 재합성                         [중요] LLM
```

[중요] **컨텍스트 MD 가 온톨로지 재합성의 신호원이다.** MD 의 `source_commit` 갱신 → *"저장값 ≠
문서값"* 으로 stale 판정한다. **문서가 없으면 온톨로지는 자기가 낡은 줄 모른다.**

## [중요] 여기서 배운 것 — 다음 마일스톤이 다시 밟지 말 것

**세는 법**

- [중요] **손으로 적은 분자는 어긋난다 — 두 번 실측됐다.** 중 1.3 이 `7/10` 인데 남은 목록은
  6개(합 13)였고, 중 1.3 이 5→8 로 올랐는데 대 1 의 분자가 15 에 멈춰 있었다(실제 18).
  **작업이 는 게 아니라 세는 법이 틀렸다** → 분자는 레드마인이 계산한다.
- [중요] **줄 수는 작업량이 아니다.** `class_graph` 1,341줄 = *"파일 삭제 → 재시작 시 전체 재스캔"*.

**데이터**

- [중요] **1,055 스냅샷 문서를 벌크 재생성하지 않는다.** 우리 로컬 모델이 받은 스냅샷보다
  **나빴다**(주석 처리된 코드를 살아 있다고 서술). 합성기는 *새/변경분*용이다.
- [중요] **사실 게이트는 모호하면 봐준다** — 엔진 클래스, 괄호 없는 `Class::Member`(실측 오탐).
  *정상 문서를 막는 게이트가 통과시키는 게이트보다 나쁘다.*
- [중요] **가중치를 만지지 말 것** — 눈으로 보며 세 번 손댔고 한 번은 나빠졌다. **데이터를 늘리는
  쪽만 안전하고, 순위 튜닝은 정답 집합 전에 하지 않는다.**
- [중요] **매니페스트를 믿지 말고 파일을 훑는다.** 받은 스냅샷에 목록에 없는 yaml 이 하나 있었고,
  그 클래스는 **검색에도 동기화에도 빠져 있었다.** 뷰어가 그것을 드러냈다.
- [중요] **소스 44%가 CP949**(실측 723/1,654). 그래프는 무사하지만 **합성은 치명적**이다 —
  한글 주석이 최고 신호원이라서.
- [주의] **후보 폭발**: 다른 소속을 뺀 뒤에도 `GlobalEventSystem` 은 **178**. 온 프로젝트가
  include 하는 허브라 **하위 문서로 갈라야** 풀린다.

**사람의 자리**

- [중요] **`protected` ≠ `verified_by_user`.** 전자는 출처 기반이라 일괄로 걸 수 있고("재생성으로
  덮지 마라"), 후자는 사람이 검수했다는 뜻이다. 240건에 일괄 보호를 걸었고, 보호+재합성이
  **손실 0 · 순증 47** 을 냈다(보호 없이는 5개 중 3개를 잃었다).
- [중요] **잠금 보존은 절반만 있었다** — 패키지가 `verified_by_user` 를 *보존*했지만 **거는 경로가
  없어 死코드**였다. 보존만 있고 설정이 없으면 기능이 아니다.
- [중요] **레인이 결과를 가른다.** 재합성의 얕음은 모델의 한계가 아니라 **레인 선택** 탓이었다
  (사용자 지적으로 뒤집힌 결론). 로컬 2노드와 `claude`/`agy` 는 다른 물건이다.

**분산**

- [중요] **워커에 큐 토큰을 주지 않는다 — 마스터가 중개한다.** 실측: 두 워커 모두 8101 이 **401**,
  AX MCP **0건**. 스킬의 전제가 틀려 있었다. 리스 하트비트도 마스터가 대신 친다.
- [중요] **판정은 fail-closed 마커** — 마지막 세 줄 `ATTEMPT`/`HEAD`/`RESULT`. 관대함은 **BLOCKED
  쪽으로만** 연다.
- [중요] **묶으면 싸다** — 4파일 묶음 **$0.042/file** vs 단일 **$0.133/file**(3.2배).
  [중요] **그런데 워커를 늘리면 비싸다** — 2대는 12% 빠르고 **90% 비쌌다**(캐시 생성이 워커별 고정비).
- [중요] **워커는 `main` 으로 복귀한다.** 아니면 자기가 앉은 브랜치를 영영 못 지운다. 그리고
  **브랜치 삭제는 마스터만** 하고, tip 이 `origin/<base>` 에서 닿을 때만 지운다.
- [중요] **파일 불가분으로 쪼갠다** — `.h`/`.cpp` 는 한 덩어리다. 개수가 아니라 **충돌 방지**가 기준.
- [주의] **`/init` 은 opt-in 이다** — 배달 페이로드 13,325자가 **이미 이전 `/init` 산출물**이라
  미지 식별자 목록이 동일했다. 매번 돌리면 $1.68 을 헛쓴다.

**조용히 틀리는 것들** (이 저장소의 반복 실패 유형)

- [중요] **scp 가 rc=0 으로 실패한다** — 윈도우 역슬래시 경로에 `protocol error` 를 내면서도
  종료 코드는 0이다. 그 결과 **모든 윈도우 배달이 기본 문서를 CLAUDE.md 위에 덮었다.**
  → 상태가 아니라 **결과로 판정한다**(§8.3 의 *"완료 신호를 믿지 말고 산출물을 검증할 것"*).
- [주의] **`%(...)`·공백은 원격 셸 문법이다** — `--format` 인자를 안 감싸면 리눅스 워커만 조용히
  깨지고, `cmd` 의 `if exist A (…) & …` 는 뒤를 통째로 삼킨다(양쪽 rc=0).
- [주의] **awk 로 문서를 세지 말 것** — *"7개 중 6개에 tags 가 없다"* 는 오독이었다. 파서로 다시
  세니 전부 있었다. **측정 도구가 틀리면 측정이 아니라 소설이다.**
