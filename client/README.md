# client

**윈도우 UE5 PC**(팀원 각자의 작업 머신)에서 도는 코드가 들어갈 자리.

> ⚠️ **이름 주의 — 이 저장소의 3계층**
>
> | 디렉터리 | 머신 | 역할 |
> |---|---|---|
> | [`master/`](../master/README.md) | 192.168.0.57 (리눅스) | 오케스트레이션 ② · **워커 풀** · RAG · 브로커 |
> | [`worker/`](../worker/README.md) | BC-250 #1·#2 (리눅스) | **추론 노드** — 텍스트 in/out만 |
> | **`client/`** | 윈도우 UE5 PC | **오케스트레이션 ① + 엔진 바운드(층3)** |
>
> AgentTest 코드의 `worker/`(윈도우에서 돌던 작업자 하네스)가 원래 여기 해당했으나,
> **2026-08-07 부로 마스터로 이전**한다(`../PLAN.md` §5.2-A). 이 디렉터리 이름은 그 코드가
> *있던 곳*을 가리키는 이름으로 남는다. 이 저장소의 `worker/` 와는 다른 것이다 — `../PLAN.md` §4.1.

## 역할 — 두 가지뿐이다 (2026-08-07 개정)

1. **오케스트레이터 ①** — 사용자가 앉아서 지시하는 곳. 여기 Claude Code 가 작업을 분해해
   task_queue 에 넣고, 리눅스 인프라를 병렬 처리 용량으로 활용한다(`../PLAN.md` §2.1).
2. **엔진 바운드 작업** — UE5 빌드 + `RunTests` = 3층 게이트의 **층3**(`../PLAN.md` §4.3).
   **다른 곳에서 할 수 없기 때문에** 남는다.

> 🔴 **`worker/`(작업자 하네스)는 더 이상 여기 없다.** 팀 환경에선 팀원 PC 들이 워커 풀이었지만,
> 1인 클러스터에선 **마스터가 그 역할을 인계**했다(`../PLAN.md` §2.1·§5.2-A).
> 따라서 "파일을 소유하는 유일한 계층"도 더 이상 사실이 아니다 — 마스터의 워커 프로세스도
> 저장소를 클론하고 코드를 쓴다. **BC-250 만 여전히 파일을 만지지 않는다.**

## 여기 남는 것 (AgentTest 에서 이식하지 않고 잔류)

`../PLAN.md` §5.2-B. 전부 **엔진 바운드**다.

| 컴포넌트 | Windows 의존 | 사유 |
|---|---|---|
| `mcp/master_orchestrator/ue_builder.py` | 19줄 | `UE Build.bat` 실행 |
| `mcp/master_orchestrator/ue_test_runner.py` | 2줄 | `UnrealEditor-Cmd RunTests` |
| `mcp/master_orchestrator/executor_integration_build.py` | 3줄 | 통합 빌드 게이트 |
| `mcp/master_orchestrator/tdd_dryrun.py` | 1줄 | TDD 드라이런 |
| `mcp/commandlet_runner/` | 5줄 | UE 커맨드릿 |

**통합 빌드 게이트는 인프라에 고정하지 않는다** — task_queue 잡으로 큐잉해
**UE5 를 가진 아무 작업자가 claim** 하는 CI 러너 패턴(`../PLAN.md` §5.2-C).
이래야 마스터가 UE5/Windows 에 묶이지 않는다.

## 마스터와의 경계

| client/ | master/ |
|---|---|
| 오케스트레이션 ①(사용자 접점) | 오케스트레이션 ②(자체 모델 자원) |
| **층3** UE5 빌드 · `RunTests` | **층1·층2** 자기검증 · 상용 모델 문법검사 |
| — | 워커 풀 · 잡 분배 · RAG · 추론 브로커 |

- **BC-250 추론 노드를 직접 호출하지 않는다** — 마스터 브로커 경유(`../PLAN.md` §4.2).
  노드 방화벽도 `192.168.0.57` 에서만 11434 를 허용하도록 잠겨 있다.
  오케스트레이터가 둘이어도 **브로커는 하나**다.
- **폴링은 여기 남는다.** 마스터는 Gitea 를 직접 호스팅해 이벤트 구동으로 가지만(`../PLAN.md` §5.4.2),
  이 PC 는 git 서버 입장에서 외부인이라 task_queue 에 폴링(또는 롱폴링)으로 붙는다.
- ⚠️ **능력 기반 라우팅(`requires: ue5`)이 아직 없다.** 없으면 마스터 워커가 UE5 잡을 집어간다
  — `../PLAN.md` §3 미결 항목.

## 배포 형태 — 재검토 대상

AgentTest 는 PyInstaller `--onefile` exe 를 `AgentWatch.zip` 으로 배포하고 팀원이
UE5 프로젝트 루트에 압축 해제하는 방식이다(`../PLAN.md` §5.4.1).

**그 배포 의식은 "설치해줄 팀원"이 있어서 존재했다.** 1인 클러스터에선 이 PC 도 내 기계이므로
zip 패키징·`install.bat`·`bump_version.ps1` 은 **축소·폐기 후보**다(`../PLAN.md` §5.2-D).
다만 마스터(§5.4.3, systemd)와 달리 윈도우에서 무엇으로 띄울지는 **아직 정하지 않았다.**
