## 0. 무엇을 하는가

명령 하나가 순서를 강제한다. **이 스킬은 언제·무엇을 확인하는지를 정한다.**

    1 등록부      이 호스트가 등재된 모든 프로젝트의 경로를 <root>\<프로젝트> 로 바꾼다
    2 낡은 등록    옛 경로를 **실제로 가리키는** AxWorker_*·AxConductor_* 만 해제한다 (윈도우)
                  AxWorker_* 해제는 철회된 상주의 잔재 정리다(`#861` — 상주는 다시 등록되지 않는다).
                  AxConductor_* 는 3 의 배달이 새 경로로 다시 등록한다(파견 때만 쓰는 로그인 런처)
    3 클론·배달    마운트된 프로젝트 하나 — 체크아웃이 없으면 클론, 그 뒤 배달(런처 등록 포함)
    4 대조        같은 프로젝트를 그 호스트만 `check`

비마운트 프로젝트는 경로만 바뀐다. 클론·배달은 마운트 전환(`set_active`, `align=True`) 때 된다.

## 1. 실행 전 — 사용자에게 받을 것

- **호스트 IP · 체크아웃 루트**(예: `C:\trunk`) — 추측하지 않는다.
- **신규 기계면 계정**(`--user`) — `.2` 는 `janus`, `.33` 은 `user`, `.43` 은 `sim` 처럼 기계마다 다르다.
- 마스터 `git status --short` 가 비어 있어야 한다. dirty 면 `check` 가 실패한다(`dirty_master`).
  커밋은 사용자 승인 사항이다 — 이 스킬이 하지 않는다.
- 윈도우 워커는 **사람이 로그인해 있어야** 지휘자(`/IT`) 경로가 산다. 재부팅 뒤면 먼저 말한다.

## 2. 명령

작업 위치 `/home/sim/ax-cluster`. 먼저 계획을 보이고, 사용자가 승인하면 `--confirm`.

    AX_PROJECTS_ROOT=/home/sim/ax-cluster .venv/bin/python -m master.client setup-host \
        --host=<ip> --root=<경로> [--user=<계정>]               # 계획만 (쓰지 않는다)
    ... 같은 명령 + --confirm                                    # 실행

백슬래시 경로는 셸에서 작은따옴표로 감싼다: `--root='C:\trunk'`.

## 3. 결과 보고

- 단계별 `[완료]`/`[실패]` 줄과 마지막 `check rc` 를 그대로 전한다.
- **실패는 고치는 자리가 아니라 보고하는 자리다.** 멈춘 단계·사유·갈래를 내고 멈춘다.
- `check` 통과는 **파일이 정본과 같다**는 뜻이다. 로그인·인증·실제 파견 성공은 별개다 —
  윈도우 Codex 는 셸 읽기·apply_patch 쓰기·결과 회수를 따로 확인한다(`docs/windows-codex-remote.md`).
- UE5·Ollama 같은 기계 능력은 이 명령이 설치하지 않는다. `probe` 결과로 빠진 것을 말한다.

## 4. 하지 않는 것

- 옛 디스크의 파일을 지우거나 옮기지 않는다 — 레지스트리와 상주 과제만 바꾼다.
- 비마운트 프로젝트를 클론하려고 마운트를 바꾸지 않는다 — 전환은 사용자 결정이다.
- 커밋·push·서비스 재기동을 하지 않는다.
