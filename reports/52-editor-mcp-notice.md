# 52 — 「에디터에 붙었나」를 세션이 스스로 안다 (`#374`)

**2026-09-06** · 신규 훅 1 · 테스트 28건 · `.33` 라이브 3케이스

---

## 1. 결론부터

어제 `.33` 세션은 **한참 작업한 뒤에야** *"세션 시작할 때부터 unreal-mcp 연결이 실패한
상태였다"* 를 알았다. 이제 세션 시작에 한 줄이 뜬다:

    [에디터 MCP] 꺼짐 — 에디터가 안 떠 있다 (127.0.0.1:8000). 소스·빌드·로그 작업은 영향 없다.
                 애셋·BP·입력 매핑을 건드려야 하면 사람에게 에디터 기동 + 세션 재시작을 요청할 것

## 2. 🔴 함정 — 「포트 열림」이 「이 세션이 붙었다」가 아니다

MCP 는 **세션 시작에 한 번만** 붙고 자동 재시도가 없다. 그래서 **세션보다 늦게 켠 에디터에는
못 붙는다** — 어제가 정확히 그 경우였고, `netstat` 으로는 `LISTENING` 이라 멀쩡해 보였다.

이슈 원안은 「에디터 프로세스 기동 시각 vs 세션 시작 시각」 비교였다. 실제로 만들다 보니
**그 시각을 추정할 필요가 없었다** — 이 훅은 세션 시작에 **직접 돌기 때문에** 그때 재서
적어 두면 된다. 프로세스 시각 비교는 스냅샷이 없을 때만 쓰는 폴백으로 남겼다.

    off        포트 닫힘                          에디터가 안 떠 있다
    ok         지금 살아 있고 세션 시작에도 살아 있었다    붙었을 것이다
    stale      🔴 지금 살아 있는데 세션 시작엔 아니었다    이 세션은 못 붙었다 — 세션 재시작
    gone       세션 시작엔 살아 있었는데 지금 닫혔다      도구는 목록에 남고 호출만 실패한다
    not_mcp    포트는 열렸는데 MCP 응답이 아니다         남이 그 포트를 잡고 있다
    unknown    열렸지만 세션 시작 기록이 없다           단정하지 않는다

## 3. 만들기 전에 셋을 봤다

    ① 원전에 있나        있다 — `docs/runbook.md` §12 (사람이 읽는 점검 절차).
                        마지막 줄이 우리 결론과 같다: *"도구가 안 보이면 세션 재시작"*.
                        절차를 **관측값으로 바꾼 것**이지 새 계층이 아니다
    ② 이미 잡는 게 있나   없다. `pending_works.py` 는 분산 작업만 본다
    ③ 오탐이면 뭐가 죽나   [중요] **비대칭이다** — 틀린 「붙음」은 도구 호출이 실패하며 그 자리에서
                        드러나고, 틀린 「못 붙었다」는 **사람에게 헛되이 세션 재시작을 시킨다.**
                        그래서 모호하면(타임아웃·비HTTP) **살아 있음 쪽으로 접는다**

## 4. 막지 않는다 · 켜 주지 않는다

에디터가 필요 없는 작업이 대부분이다(2026-09-05 실증 3라운드 전부). 고지만 하고, **기동은
사람의 결정**이다 — 원격 기동은 세션 0 경계로 기술적으로도 막혀 있고 `win-main-33.md` 가
*"원격 절차를 설계하지 마라"* 라고 적어 둔 자리다. 요청이 애셋·BP·입력 매핑을 건드릴 때
**요청자 세션이** 판정해 사람에게 재시작을 요청한다(`ax-request` SKILL §0.06) — 훅은 문장에서
애셋 여부를 가르지 않는다.

## 5. 라이브 (`.33`, 실물)

| 상태 | 결과 |
|---|---|
| 에디터 꺼짐 → 세션 시작 | `꺼짐` 한 줄 |
| 세션 시작 **뒤에** 8000 이 열림 → 다음 턴 | 🔴 `이 세션은 못 붙었다` + 세션 재시작 요청 |
| 같은 판정으로 한 턴 더 | **침묵** (매 턴 반복 없음) |

[주의] **「붙음」을 진짜 UnrealEditor 로 잰 적은 없다** — 로컬 테스트의 실소켓과 `.33` 의 가짜
서버로만 확인했다. 다음에 사용자가 에디터를 켜고 세션을 열면 그때 확정된다.

## 6. 측정이 잡은 것 둘 (둘 다 내가 만든 것)

**⑴ handshake 가 본문을 기다리다 오탐을 만들었다.** streamable-http 응답이 `text/event-stream`
이면 `read()` 가 서버가 끊을 때까지 블록한다 → 타임아웃 → `not_mcp`. **본문을 안 읽고**
상태줄과 Content-Type 으로 판정하도록 고쳤다.

**⑵ 테스트가 배달 표면에 `__pycache__` 를 만들었다.** `bundle.workshop_files` 가 `hooks/` 를
rglob 로 쓸어 담으므로 그대로 두면 `.pyc` 가 **요청자 기계로 배달된다**(`test_client_bundle` 이
그 바이트를 읽다 `UnicodeDecodeError` 로 죽어서 드러났다). 테스트와 훅 양쪽에
`sys.dont_write_bytecode = True` — 사람의 `.claude/hooks/` 도 더럽히지 않는다(배달 뒤 실측: 없음).

[주의] 소켓 테스트가 **5회 중 2회** 흔들렸다 — `accept()` 에 블록된 스레드가 있으면 `close()`
가 실제로 닫지 않는다. 6회 반복으로 확인하기 전에는 「통과」로 보였다.

## 7. 남은 것

- `bundle.workshop_files` 가 `__pycache__`/`.pyc` 를 **거르지 않는다** — 지금은 만드는 쪽에서
  막았지만, 배달 쪽 가드는 없다. 고칠지는 결정 필요(`bundle.py` 는 이 작업의 대상 밖)
- 「붙음」 실측 — 사용자가 에디터를 켠 세션에서 확인
- 레드마인 `#374` 상태 전이는 **요청자(`.33`)의 자리**다. 마스터는 사실만 노트로 남겼다
