## 5. #840 ② — 형식·사실 검사에 진 클라우드는 재시도에서 뺀다 (`02bb205`)

사용자: 「#840은 버그를 고쳤는데 왜 완료가 아니야?」 → 「드라이런으로 테스트 불가능해?」 → 「(가)로 구현하고 드라이런으로 확인해」.

- **착수 전 드라이런(LLM 0)**: 재시도는 `infer.py` 가 `run_chain` 을 기본 레인으로 다시 불러 **세 번 모두 agy** 였다 —
  10-22 노트의 「미구현」을 돌려서 확인했다. #788 결정 2(「형식·사실 실패는 다른 cloud 로만」)와 다르다.
- **구현**: `llm_policy.eligible/next_lane(excluded=)` — 진 클라우드는 부르지 않고 그 자리는 건너뛴다(한도 소진이 아니므로
  claude·로컬은 열리지 않는다) · `lanes.run_chain(excluded=)` · `infer` 가 층1(format)·층2(facts)에서 진 레인을 누적 표지
  `[lane-fail:agy:facts,…]` 로 submit-fail detail 앞에 싣고(큐가 앞 600자를 `last_feedback` 으로 다음 시도에 전달),
  다음 시도는 그것을 읽어 뺀다. 층2 **검증 불가**는 작성자 탓이 아니라 더하지 않는다.
- **동반 발견 결함**: 「클라우드 생성 전부 실패 → 즉시 실패」 가드(`3123389`)가 `stage == "llm"` 을 비교했는데 `wcommit` 은
  「본문 작성」을 쓴다 — **운영에서 한 번도 발동하지 않았다.** 검사들은 `"llm"` 을 주입해 통과했다(#878 과 같은 부류 —
  운영과 다른 값을 검사). `wcommit.STAGE_LLM` 하나로 비교한다. [주의] 그래서 lane 모드에서 클라우드가 전부 실패한 조각은
  이제 같은 체인 재시도 없이 바로 실패로 기록된다 — 10-22 의 의도대로다.
- **드라이런(LLM 0, 실제 `commit_task` 3회, 큐 절단 흉내)**: 1회 agy 층2 실패 → 재시도·`[lane-fail:agy:facts]` →
