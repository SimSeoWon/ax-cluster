## 4. [중요] LFS — 답은 리포트 31 에 3일 전부터 있었다

내 진단: *"오브젝트가 서버에 없다"* → **틀렸다.** 실측:

    익명 LFS batch   401 Unauthorized
    토큰 LFS batch   200 · href 발급 → 실제 다운로드 200 · 308,880바이트

오브젝트는 있었다. git-lfs 가 인증 실패를 *"remote missing object"* 로 뭉뚱그린 것이다.
그리고 **막힌 것은 마스터 하나뿐**이었다:

    마스터   origin 이 파일시스템 bare 경로 → LFS API 부재. worktree add 가 smudge 에서 죽음
    .2       실물 보유(308,880바이트 확인) → 문제 없었다
    .43      git-lfs **미설치** → 필터가 안 돌아 포인터로 정상

🔴 **이 역할별 표가 리포트 31 §3-ⓐ 에 이미 있었다** (*"마스터 포인터 · .2 실물 134MB ·
.43 포인터(git-lfs 미설치) · .33 실물"*). 온보딩 클론도 `GIT_LFS_SKIP_SMUDGE=1` 로 **이미
고쳐져 있었다**(`onboard.py:411`). 세션 시작에 리포트를 읽으라는 규칙을 지켰으면 이 절 전체가
없었다.

해결은 **다 받는 것**이었다(사용자 지시): `git lfs fetch --all gitea-write` + `git lfs checkout`
→ 753개 141MB · 트윈 282M. 그 뒤 **코드 변경 없이** `worktree add` rc=0, `carry.publish` ok.

[주의] 남은 것: 클론은 `GIT_LFS_SKIP_SMUDGE` 로 고쳤는데 **`worktree add` 계열(`carry.py`·
`attempt.py`)이 그 env 를 안 물려받는다.** 마스터는 실물을 받아 해소됐지만 구조는 그대로다.

## 7. 곁에서 나온 구조 문제 (제안 아님 · 사용자 판단 자리)

- **게임 저장소를 마스터 데이터의 운반 통로로 쓴다.** 매니페스트는 트윈에 이미 있고
  (`NS/manifests/<id>.md`) 조회 도구(`get_manifest`)도 있는데, 같은 것을 `add -f` 로
  `task/<id>` 에 커밋해 보낸다. 그래서 머지마다 *"이 인프라 파일을 `main` 에 넣을 거냐"* 가 생긴다
- **`.ax/` 는 일부러 추적 밖이다**(`.git/info/exclude`, 사용자 확정 2026-08-09 · 근거는
  `bundle.py:18`). 대가: 버전을 git 으로 못 재서 `check` 해시 대조와 `#277`(도는 상주가 옛 코드)이
  별도 장치로 필요하고, `exclude` 는 클론에 따라오지 않는다. 그러면서 매니페스트만 `add -f` 로
  추적시켜 **원칙이 한 저장소 안에서 갈린다.** 원전은 exe zip 배포라 이 충돌이 없었다
- **`carried_error` 가 사람 화면에 안 찍힌다** — `stage_register` 가 `manifest_degraded` 만
  출력해서 carry 실패가 *"OK"* 로 보였다. 코드 주석은 *"결과에 크게 남긴다"* 인데 출력에 없다
