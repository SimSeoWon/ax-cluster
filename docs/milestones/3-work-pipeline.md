## [중요] 성격 — 마일스톤 2 와 무엇이 다른가

마일스톤 2 는 **데이터를 만들었다**. 트윈이 자라고, 색인되고, 코드 작성 에이전트에게
전달된다. 이번은 그 트윈으로 **실제 코드를 대량 생산하고, 그 결과를 믿을 수 있게** 만든다.

    마일스톤 2   요청 하나 → 워커 하나 → 결과 하나          (1분 29초 실측, 한 줄로 이어짐)
    마일스톤 3   요청 하나 → **N 조각** → 워커 2대 → 순차 적용 → **3층 판정**

[중요] **얻는 것은 처리량이 아니라 증분이다** (사용자 재정의 2026-08-11). 실측이 처리량 쪽을
부정한다 — 워커 2대는 **12% 빠르고 90% 비쌌고**, 3.2배 절감은 **묶음**의 이득이지 병렬의
이득이 아니며, 층3 은 어차피 `.2` 한 대다. 이 마일스톤의 장치들(동결 · 골조 빌드 게이트 ·
의존 순서 · 통합자가 통과분만 커밋)은 전부 **"작업이 항상 컴파일되는 상태로 쌓이게"** 하는
것이다. 그래서 **검증은 선택이 아니라 전제다** — 검증 없이 쌓으면 증분이 아니라 부채다.
상세 = [`../4-work-loop.md`](../4-work-loop.md) §4.5 · [`../settled-decisions.md`](../settled-decisions.md).

[완료] **"판정이 워커의 자기 신고뿐" 이던 것은 고쳐졌다** (2026-08-12) — 게이트가 **네 겹**이다:
골조 빌드 · 층1(응답 수락 + 적용 직전) · 층2(상용 모델, 선언부 grounding) · 층3(조각별 UE5 빌드 +
work 단위 RunTests). 마커는 *"응답을 받았는가"* 만 판정하고, *"컴파일되는가"* 는 **통합자가 UE5
로** 판정한다. *"결정적 게이트가 LLM 판단보다 위"* 가 규칙에서 **구조**가 됐다.

[중요] **그런데 구멍이 하나 남았고 그것은 코드로 메울 수 없다** — **이 프로젝트에 자동화 테스트가
0개다**(실측). §4.3 이 실측한 *"컴파일을 통과하는 환각"*(`Cast<IInteractable>` · `IsValid()` 로직
오류)은 **테스트만** 잡을 수 있는데, 잡을 테스트가 없다. 층2 가 일부를 가져가지만 전부는 아니다.
[주의] 그래서 층3 의 `RunTests` 는 지금 **fail-open** 이고, 그 사실이 판정마다 출력에 실린다.

## [중요] 토폴로지가 바뀌었다 — **쓰는 주체는 하나다** (사용자 확정 2026-08-11)

    옛것   워커 N대가 각자 자기 클론에서 수정 → 각자 커밋 → attempt push → 마커로 판정
    새것   워커는 **추론만** → 통합자(`.2`)가 **적용 → UE5 빌드 판정 → durable 커밋**

**빌드해 본 주체가 커밋한다** — 그래서 깨진 것이 원격에 **못** 박힌다. 옛 구조에서 규율이던 것이
새 구조에서는 **구조**다. 근거·비용·왜 `.33` 이 아니라 `.2` 인지 =
[`../8-git-authority.md`](../8-git-authority.md) §8.4 · [`../settled-decisions.md`](../settled-decisions.md).
이 결정이 분류도 바꿨다(중 1.3 = 추론 파견만, 적용·빌드·커밋은 중 1.4). [중요] **닫힌 중 2.5 의 일부가
유휴가 되지만 지우지 않고 보류**한다 — 되돌릴 수 있어야 한다.
